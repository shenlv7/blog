> 同一张跨 4.2e7 倍的张量，同样是 8 bit：INT8 的 SQNR 是 **17.55 dB**，**99.47%** 的元素被压成 0；
> FP8 e4m3 是 **34.69 dB**，归零 3.84%；按 128 分块缩放是 **47.88 dB**，归零 0.01%。
>
> 但把张量换成范围规整的高斯权重，INT8 立刻反超：**39.45 dB vs 31.55 dB**，差 7.9 dB。
> 同一个位宽，谁更准取决于张量长什么样 —— 因为 INT8 的误差是**绝对**的，FP8 的误差是**相对**的。
>
> 最后一节是反直觉的那一半：真训 600 步，fp32 / INT8 / FP8 per-tensor / FP8 分块 四种精度的 loss 落点差 0.3%–1.5%，
> 参数轨迹却已经偏了 1.47%–3.10%，**而且偏离排序跟 SQNR 排序对不上**。
>
> 边界先钉死：e4m3 是我用 numpy 手写的模拟器，跑的是单隐层小网络和合成张量，不是 GPU 上的 FP8 kernel，也不给吞吐数字。这里验的是**格式的误差结构**，不是某个框架的实现质量。

**读这篇要会**：均匀量化的 step / round-to-nearest / SQNR 的 dB 定义／二进制浮点的「指数 + 尾数」表示（知道 1.5 = 1.1₂ × 2⁰）／矩阵乘和反传的链式法则。会 numpy，不需要 GPU。

## 🎯 8 个 bit 的两种切法

第 21 篇量化权重、第 58 篇量化激活，用的都是 INT8：一个符号位 + 7 位幅度，值域被切成 255 个**等宽**格子，格宽由整张张量的最大值定死。

$$\Delta_{\text{int8}}=\frac{\max|x|}{127},\qquad \text{SQNR}_{\text{int8}}\approx 52.9\ \text{dB}-20\log_{10}\!\left(\frac{\max|x|}{\mathrm{RMS}(x)}\right)$$

公式右边那个分式就是 crest factor（峰值／有效值）。它的含意很硬：**张量的动态范围每多 20 dB，你就白丢 1 个 bit 的精度**，跟你用了几位没关系。

FP8 走的是另一条路：4 位指数 + 3 位尾数（e4m3），值域不是等宽格子，而是每个二次幂区间里切 8 段：

$$\frac{\Delta_{\text{fp8}}(v)}{|v|}=2^{-3}\cdot\frac{2^{\lfloor\log_2|v|\rfloor}}{|v|}\in\left[2^{-4},\,2^{-3}\right]$$

也就是说，不管 $v$ 是 $10^{-3}$ 还是 $10^{3}$，它的相对误差都在 **6.25%–12.5%** 这个带子里（round-to-nearest 后 RMS 约 2.5%–3.6%，对应 **29–32 dB**）。代价是尾数只有 3 位：满量程对齐时（张量最大值≈2），$[1,2)$ 区间里 INT8 有 128 个格子，e4m3 只有 8 个。

spec 上的几个硬数字，后面测出来能不能对上全靠它们：E4M3 **最大 448**（没有 inf，只有 NaN），最小正规数 $2^{-6}=0.015625$，次正规步长 $2^{-9}=0.001953125$。所以 e4m3 的动态范围是 $448/2^{-9}\approx 2.3\times10^{5}$ —— 比 INT8 的 254 宽了三个数量级，这就是 4 位指数买来的东西。

**为什么不是 fp16？** 5 位指数、10 位尾数，动态范围和精度都够，但它是 16 bit：H100 上 bf16/fp16 的峰值算力是 FP8 的一半，权重和激活的搬运也翻倍。做训练的人不是嫌 fp16 不准，是嫌它贵。

## 🔬 实测：4.2e7 倍的张量与两个对照

张量按「梯度/激活的典型形态」造：幅度取 lognormal（$\sigma=1.6$），再让 1% 的元素乘 60 当离群值。跑出来 max/min = **4.23e7**，10 分位 0.0477、90 分位 3.08 —— 也就是 80% 的质量挤在两个数量级里，剩下一点撑到 1e4。

| 方案 | SQNR | 归零（<1e-12） | 顶格（≥447） |
|---|---|---|---|
| INT8 per-tensor | 17.55 dB | **99.47%** | 0.03% |
| FP8 e4m3 per-tensor | 34.69 dB | 3.84% | 0.03% |
| FP8 e4m3 128 分块 | **47.88 dB** | 0.01% | 0.03% |

INT8 那 99.47% 不是 bug：$\max|x|=10^4$，step $=78.7$，而这张张量一半的元素比 0.157 还小 —— 它们全落在第一个格子里，round 之后就是 0。**255 个格子，普通元素连一个都用不上。**

同样的位宽换成浮点，3.84% 的归零全发生在 $|v|<2^{-10}$ 的尾巴上（次正规/零），主体部分照样有 3 位尾数。这就是「误差按比例算」和「误差按绝对值算」的差别，跟位数无关。

再看对照，同一套量化器压一个 $\sigma=0.02$ 的高斯权重张量：

| 方案 | SQNR（高斯权重） |
|---|---|
| INT8 per-tensor | **39.45 dB** |
| FP8 e4m3 per-tensor | 31.55 dB |
| FP8 e4m3 128 分块 | 31.82 dB |

两件事值得记：

1. **INT8 反超 7.9 dB**。高斯张量的 crest factor 只有约 4.4，按上面的公式预测 $52.9-20\log_{10}4.4\approx40.4$ dB，实测 39.45 dB —— 误差公式是对的。范围规整的张量，7 位尾数就是比 3 位准。
2. **128 分块在这张表上一点用都没有**（31.82 vs 31.55，差 0.27 dB）。原因很直接：高斯没有离群值，每个 128 元素块的 amax 都差不多，分块缩放只是多存了一堆 scale。分块的收益来自**离群结构**，不来自「分块」这个动作本身 —— 这条判断能省掉很多无效优化。

## 🏗️ 生产里怎么落地：DeepSeek-V3 的配方

把上面的机制放大到 671B 参数（每 token 激活 37B）的真实训练里，DeepSeek-V3 技术报告（arXiv:2412.19437）给了一套具体的取舍，正好是这几条公式的工程版：

- **激活按 1×128 tile 缩放**（每个 token 每 128 个通道一把尺），**权重按 128×128 block 缩放**。这就是我上面测的「分块」，只是分得更狠。
- **所有张量统一用 E4M3**。早期 FP8 框架（TransformerEngine 那条线）的做法是前向 E4M3、反传的 dgrad/wgrad 用 E5M2（5 位指数、2 位尾数），因为反传张量更容易溢出。V3 反过来：靠细粒度缩放压住离群，就能全程吃 E4M3 的精度。
- **在线算 amax**，不用「延迟缩放」那套历史最大值外推。代价是每个块都要现场求 max，收益是 scale 永远对得上当前 batch。
- **scale 取 2 的整数次幂**。这样量化就是纯粹的指数搬移，反量化不用做浮点乘；反传里 1×128 的 tile 要变成 128×1（转置 GEMM），提前把 scale 对齐到 2 的幂能避免这次重排引入额外误差。
- **FP32 累加**。8 bit 只用在乘法的输入上，累加器每 128 个元素提升一次精度；FP8 张量核的吞吐按 8 bit 算，精度按 fp32 算。

代价也要写清楚：每 128 个值多存一个 2 字节的 scale，等于 **0.125 bit/值**（相对 8 bit 是 1.6% 的存储/搬运开销）；反传时激活要从 HBM 读出来、反量化、转置、重新量化成 128×1 的 tile 再写回去，这一次重排是纯带宽成本，也是「转置 GEMM 不好融合」这个老问题的直接后果。

## 💻 跑一遍：600 步之后，loss 差不出来

前两节量的是「一张张量压一次」的误差。真正的问题是：这点误差训练下去会怎样？

我用同一个两层 tanh 网络、同一份数据、同一个 Adam（$3\times10^{-3}$，600 步，bs=128），只把 matmul 的输入换成低精度，梯度更新本身保持 fp32：

| 方案 | loss@600 | 相对 fp32 | 参数偏离 fp32 |
|---|---|---|---|
| fp32 | 0.1656 | — | — |
| INT8 per-tensor | 0.1661 | +0.3% | 1.47% |
| FP8 per-tensor | 0.1681 | +1.5% | 2.54% |
| FP8 128 分块 | 0.1673 | +1.0% | **3.10%** |

三个观察，按重要性排：

1. **loss 分不出精度**。四种方案在 0.1656–0.1681 之间，最大差 1.5%。你要拿 loss 当验收指标，会得出「8 bit 训练零代价」的结论。
2. **参数已经偏了 1.5%–3.1%**。600 步、每步 128 样本，量化噪声被 Adam 的二阶矩归一化吸收了一部分，剩下的推着轨迹走了另一个方向。轨迹偏离在短跑里不显形，在几千亿 token 的长跑里会变成什么，这套玩具测不出来。
3. **偏离排序跟 SQNR 排序对不上**：SQNR 最高的分块方案（47.88 dB）参数偏离最大（3.10%），SQNR 最低的 INT8（在这里范围窄，实际 SQNR 并不低）偏离最小。原因是 600 步的 Adam 轨迹对初值和噪声高度敏感，单次轨迹差 1% 量级里全是噪声。**单点的 SQNR 不能预测 600 步后的状态**。

量化器本体只有十几行，完整脚本（含张量构造、三种量化、训练循环）在仓库 [demos/78-fp8-block-scaling.py](https://github.com/shenlv7/blog/blob/main/demos/78-fp8-block-scaling.py)：

```python
def fp8_e4m3(x):
    """对称 e4m3 的 round-to-nearest：正常区内按 2^(e-3) 取整，次正规区步长 2^-9。"""
    a = np.abs(x)
    e = np.floor(np.log2(np.maximum(a, 2.0 ** -6)))
    q = np.round(a / 2.0 ** (e - 3)) * 2.0 ** (e - 3)
    q = np.where(a < 2.0 ** -6, np.round(a / 2.0 ** -9) * 2.0 ** -9, q)
    return np.sign(x) * np.clip(q, 0.0, 448.0)      # 448 是 e4m3 的上界

def int8_sym(x):
    s = np.abs(x).max() / 127.0                      # 一把尺，由全张量最大值定死
    return np.clip(np.round(x / s), -127, 127) * s

def q_fp8_block(x, block=128):
    """每 128 个元素一把尺：等价 V3 的 1x128 activation tile。"""
    b = np.pad(x, ((0, 0), (0, (-x.shape[1]) % block))).reshape(x.shape[0], -1, block)
    s = np.abs(b).max(axis=2, keepdims=True) / 448.0
    return (fp8_e4m3(b / s) * s).reshape(x.shape[0], -1)[:, :x.shape[1]]
```

本机 17 秒跑完，无 GPU。

## 💡 三个可用的判断

1. **选格式先看张量的动态范围，不要问「多少 bit」**。权重是窄范围、近似对称的分布，7 位尾数的 INT8 更准；梯度和激活跨 4–5 个数量级，必须用浮点，让误差跟着数值一起缩。同一个 8 bit 在这两类张量上的最优解是相反的。
2. **分块缩放的收益来自离群结构，先测量再上**。crest factor（$\max/\mathrm{RMS}$）和归零率是两个最便宜的先验指标：crest 在 3–5 之间、归零率接近 0，分块只会多付 1.6% 的 scale 开销（我的高斯对照里就只赚了 0.27 dB）。crest 上百，分块才值得上。
3. **精度方案的验收要看参数轨迹和更新方向，不要看 toy loss**。这张表里 30 dB 的 SQNR 差在 loss 上只剩 1.5%，而参数已经偏了 3%。判断一套低精度训练能不能用，至少要看：同样步数后参数与高精度参考的相对偏离、梯度方向余弦、以及长跑之后的 eval 指标，而不是前几百步的 loss 曲线。

格式是死的，张量是活的。同一个 8 bit，落在权重上是 39 dB，落在梯度上是 17 dB —— 差的不是硬件，是你有没有按分布去切它。
