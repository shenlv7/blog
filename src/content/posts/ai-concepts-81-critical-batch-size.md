> 同一个 1,153 参数的模型、同一条 lr 线性缩放规则，batch 从 32 加到 2048：
> **步数从 680 掉到 50（13.6 倍），到达同一 eval loss 的样本量却从 21,760 涨到 102,400（4.71 倍）**。
> 免费区间只走到 128——从 256 开始，每多买一分并行都要用样本量付账。
> 切断它的不是显存、不是通信带宽，是一个能直接量出来的数：**$B_{noise}=\mathrm{tr}\Sigma/\|G\|^2=257$**。
>
> 而这个数在一次训练里从 22.9 漂到 630，跨 **27.5 倍**。所以「我的任务临界 batch 是多大」这句话，不给测量点就是没有答案。

读这篇要会：mini-batch 梯度是样本梯度的均值 / 方差按 $1/B$ 收敛 / 损失在极小点附近可做二次近似。

## 🎯 加 batch 买的是梯度精度，不是进度

反向上，大 batch 的账是显性的：显存、通信、每步时间都随 $B$ 涨。正向上，账被讲得很含糊——「梯度更准，所以可以放大学习率，所以收敛更快」。前半句对，后半句有上限。

把随机性写成式子。单样本梯度 $g_i$、全量梯度 $G=\mathbb{E}[g_i]$，协方差 $\Sigma$。$B$ 条独立样本的平均梯度满足：

$$
\mathbb{E}\left\|g_B-G\right\|^2=\frac{\mathrm{tr}\Sigma}{B},\qquad
\mathrm{SNR}(B)=\frac{\|G\|^2}{\mathrm{tr}\Sigma/B}=\frac{B}{B_{noise}},\quad B_{noise}\equiv\frac{\mathrm{tr}\Sigma}{\|G\|^2}
$$

$\mathrm{tr}\Sigma$ 是所有参数上单样本梯度方差的总和，$\|G\|^2$ 是信号的能量。**$B=B_{noise}$ 时噪声和信号的平方长度相等**，信噪比 1。这个量在 McCandlish 等人的 *An Empirical Model of Large-Batch Training*（arXiv:1812.06162, 2018）里叫 gradient noise scale，论文的结论正是它随 loss 下降而上升——本文第一个实验会把这个上升测出来。

为什么是 $1/B$：$B$ 个独立样本的均值，方差是单样本的 $1/\sqrt{B}$ 的平方，即 $1/B$。这条只依赖独立同分布，不依赖模型结构。真正的近似在分母——$\mathrm{tr}\Sigma$ 和 $\|G\|^2$ 都是**当前位置的函数**，位置一动，$B_{noise}$ 就动。

## 🔬 一个能在一秒内跑完的测量

测量不需要 GPU，甚至不需要反向传播框架。1,153 个参数的 2 层 MLP（16→64→1，tanh），8192 条合成回归样本，损失是 MSE；因为参数少到可以显式算**每条样本的梯度**，$\mathrm{tr}\Sigma$ 就是对 4096 条样本的梯度矩阵求逐参数方差再求和，$\|G\|^2$ 是它们均值的平方和。一次量测是几十毫秒级。

先看它在一次真实训练里怎么动（bs=32、lr=0.01、momentum 0.9）：

| step | eval loss | $\|G\|^2$ | $\mathrm{tr}\Sigma$ | $B_{noise}$ |
|---:|---:|---:|---:|---:|
| 0 | 0.53585 | 1.55813 | 35.1088 | **22.9** |
| 100 | 0.04408 | 0.00445 | 2.9191 | **630.1** |
| 300 | 0.03264 | 0.00714 | 2.0099 | **280.1** |
| 700 | 0.00282 | 0.00080 | 0.1758 | **219.5** |
| 2000 | 0.00125 | 0.00018 | 0.0800 | **443.6** |

信号能量 $\|G\|^2$ 从 1.56 掉到 1.8e-4，掉了 8,600 倍；$\mathrm{tr}\Sigma$ 只掉 439 倍。分母缩得比分子快得多（8,600 倍对 439 倍），商就往上走——**训练越接近收敛，单个样本之间的分歧越比共同方向重要**，这正是「后期需要小 batch」的定量版本。

初始那一次的 22.9 是个陷阱：随机初始化的梯度又大又一致（所有样本都想把 tanh 拉开），信噪比天然高。用它去定 batch，会把免费区间估算成 20 出头，比实测的 128 小五倍多。

## 🔬 $1/B$ 这条律，用两种独立方式对上了

在 step 300 的 checkpoint 上，从全量数据取出真梯度 $G$，再抽 200 次 batch 梯度 $g_B$，直接量 $\mathbb{E}\|g_B-G\|^2/\|G\|^2$：

| batch | 相对噪声 | 相对噪声 × B |
|---:|---:|---:|
| 1 | 253.64 | 253.6 |
| 4 | 68.20 | 272.8 |
| 16 | 16.90 | 270.3 |
| 64 | 4.290 | 274.6 |
| 256 | 1.082 | 277.0 |
| 1024 | 0.2734 | 280.0 |

乘回去基本是个常数（254–280），说明 $1/B$ 律在这个尺度上成立。同时这张表自带一个读数：**相对噪声等于 1 的位置就是 $B_{noise}$**，插值出来约 257；而从协方差直接算出的值是 256.9。两条路径（一条来自 4096 条样本的协方差矩阵，一条来自 1,200 次实际抽样）差 1% 以内，说明这个量测是真能测的，不是纸面定义。

$B\ge4$ 之后乘回去的漂移（272.8→280.0）来自抽样误差：200 次抽样估方差，标准误约 10%，和这段涨落同量级。

## 🏗️ 九个 batch 的真实账单

现在换成真正要回答的问题：把 lr 按线性规则 $0.01\times B/32$ 同步放大，跑到同一个目标（eval loss ≤ 0.003），代价怎么变。

| batch | lr | steps | 样本量 | 相对 bs=32 |
|---:|---:|---:|---:|---:|
| 8 | 0.003 | 2710 | 21,680 | — |
| 16 | 0.005 | 1360 | 21,760 | — |
| 32 | 0.010 | 680 | 21,760 | 1.00× |
| 64 | 0.020 | 350 | 22,400 | 1.03× |
| 128 | 0.040 | 180 | 23,040 | 1.06× |
| 256 | 0.080 | 100 | 25,600 | 1.18× |
| 512 | 0.160 | 60 | 30,720 | 1.41× |
| 1024 | 0.320 | 50 | 51,200 | 2.35× |
| 2048 | 0.640 | 50 | 102,400 | 4.71× |

三行读数：

**一、免费区间到 128。** 从 8 到 128（batch 放大 16 倍），样本量 21,680→23,040，只差 6.3%。这就是线性缩放规则成立的区间：batch 大了，步数按 $1/B$ 掉，样本量不变，等于白拿并行度。

**二、256 开始收费，1024 之后是硬墙。** 256 收 18%，512 收 41%，1024 收 135%，2048 收 371%。1024 和 2048 都停在 50 步——**batch 再翻一倍，一步没少**，多出来的样本全是纯开销。50 步这个下限不是评估分辨率（每 10 步一次，40 步内也能记录到），而是稳定边界：bs=2048 时 lr=0.64 是 50 步，把 lr 翻到 1.28，训练在第 225 步溢出成 NaN；bs=1024 从 0.32 翻到 1.28 同样 NaN。**大 batch 的并行度买到 50 步就到头，剩下的只能靠更长的训练。**

**三、拐点和 $B_{noise}$ 对得上。** 采样曲线第一次明显抬起在 256，而 step 300 处量到的 $B_{noise}$ 是 256.9。这不是巧合而是同一个事实的两种表述：噪声等于信号之后，多出来的样本只在重复确认同一个方向。

## 💻 核心就三段

```python
def per_sample_grads(P, Xb, Yb):          # (n, 1153) 每条样本的梯度
    h = np.tanh(Xb @ P[0] + P[1])
    r = h @ P[2] + P[3] - Yb
    dz = (r[:, None] * P[2][None, :]) * (1 - h ** 2)
    gW1 = np.einsum('ni,nj->nij', Xb, dz).reshape(len(Yb), -1)
    return np.concatenate([gW1, dz, r[:, None] * h, r[:, None]], axis=1)

def b_noise(P):
    S = per_sample_grads(P, X[idx], Y[idx])      # idx: 4096 条样本
    G = S.mean(0)
    return ((S - G) ** 2).sum(1).mean() / (G @ G)   # tr(Sigma) / |G|^2

def train(bs, lr, target=0.003):             # momentum-SGD，测到目标为止
    P, mom = init(), [np.zeros_like(w) for w in init()]
    for step in range(1, 20001):
        ii = rng.integers(0, n, bs)
        g = grad(P, X[ii], Y[ii])
        for k in range(4):
            mom[k] = 0.9 * mom[k] + g[k]
            P[k] -= lr * mom[k]
        if step % 10 == 0 and ev(P) <= target:
            return step, step * bs
```

生产模型上算不出完整的 $\Sigma$（参数量 $10^{10}$），用两步近似：抽一两个小 batch 估 $\|g_B-G\|^2$，和 $\|G\|^2$ 相除就得到 $B_{noise}$ 的估计，成本是几次前反向。

完整脚本（$\mathrm{tr}\Sigma$ 估计、噪声曲线、九组训练）在 [demos/ai-concepts-81-critical-batch-size.py](https://github.com/shenlv7/blog/blob/main/demos/ai-concepts-81-critical-batch-size.py)。全程 numpy，本机 9 秒跑完。

## 💡 落地清单

- **先测再定**：加卡或调 batch 之前花几十步量一次 $B_{noise}$，成本可以忽略，能直接回答「再加 4 卡还有没有用」。
- **测的位置要是训练中段**，不是初始化。本文里两个位置差 27.5 倍，生产模型上这段漂移只会更大，因为 $B_{noise}$ 随 loss 下降单调上升。
- **超过 $B_{noise}$ 后换缩放规则**：线性缩放失效，改用 $\sqrt{B}$ 缩放，或干脆不再放大 lr——继续线性放大在 1024 档就会像本实验那样停在 50 步不再动。
- **梯度累积与真 batch 在梯度数学上等价**，但 BatchNorm 的批统计量和 dropout 的掩码不同：做累积时要么同步 BN 统计量，要么换 LayerNorm/RMSNorm，否则「大 batch」的语义是残的。
- **超过 $B_{noise}$ 的并行应该换维度**：数据并行买不到速度之后，收益要转向模型并行、流水线、序列并行——它们改变的是每步成本，不是梯度噪声。
- **泛化是另一本账**：Keskar 等人 2016 年（arXiv:1609.04836）观测到大 batch 的泛化差距，Shallue 等人 2018 年（arXiv:1811.03600）系统扫了 batch 与 lr 的组合，发现饱和点随任务、优化器、模型宽度变化，不存在统一的最优 batch。本文只测了「到目标所需样本量」，没有测测试集泛化。

代价口径说明：本机是 3 核 ARM，每步挂钟时间从 bs=8 的 0.64 ms 涨到 bs=2048 的 9.61 ms（64 倍 batch 只慢 15 倍，numpy 的向量化摊掉了调用开销），所以上表统一用「处理过的样本数」作代价代理，而不是秒。这张表是 CPU 上的小型离散实验，不是 GPU 实测；真卡上每步时间对 batch 更接近线性，但样本量那一列与硬件无关。
