> 一条规则的强度是 0.6，意味着「这条经验大多数时候对」。把两百条这样的经验串起来，系统就能在盲测里压过主治医师——而压过主治医师，跟有人愿意用它，是两件不相干的事。

**读这篇要会**：命题逻辑里 `AND` 的短路求值；递归与记忆化（memoization）的基本用法；能读 150 行 Python。不需要懂医学，也不需要懂 Lisp。

## 一、1970 年代的卡点：不缺算法，缺知识

1969 年之后，符号派手里握着一批相当漂亮的东西：归结原理（1965）、STRIPS 规划器（1971）、SHRDLU 那种能在积木世界里听懂「把那个比方块高的锥体放进盒子里」的系统（1970）。它们在玩具问题上表现完美，换到真实世界就崩。原因不是搜索算法不够快，而是**搜索空间随问题规模指数爆炸，而人对这类问题从来不是靠搜索解决的**——人靠的是大量从经验里攒出来的、带例外的、彼此矛盾的判断。

1973 年，英国 Science Research Council 委托 James Lighthill 评估 AI 的进展。报告的结论相当冷：在「组合爆炸」面前，当时的通用方法没有出路，只有被严格限制在窄领域里的方法才可能有用。英国随后的 AI 经费被大幅削减。这份报告后来常被当作「第一次 AI 寒冬」的标志之一，但它同时指出了唯一的生路：**窄领域**。

把一个窄领域做到专家的水平，需要的东西不是更好的搜索，而是那位专家脑子里的几千条经验。问题于是换了形状：怎么把这些经验写成机器能用的形式，怎么在经验互相冲突、证据不完整的时候给出一个还能用的答案。

这正是 1970 年代斯坦福 Heuristic Programming Project 在做的事。它有两个起点，一个在化学，一个在医学。

化学那个叫 DENDRAL，1964 年立项（部分文献记作 1965），主持者是 Edward Feigenbaum、遗传学家 Joshua Lederberg、化学家 Carl Djerassi 和 Bruce Buchanan。任务很具体：给一张质谱图，推断有机分子的结构。它没有用电荷、也没有用神经网络，用的是两条最朴素的化学约束——原子价和分子量——把候选结构的空间砍到可以枚举。团队把它拆成两个程序：Heuristic Dendral 用质谱数据排除候选结构，Meta-Dendral 从「哪些结构被排除了」反推化学规则本身。为了让枚举不漏，Lederberg 和 Harold Brown 等人写了图生成器 CONGEN，并证明了它**完备**（能生成所有满足节点与键型的图）且**不冗余**（不重复输出同构的图）。DENDRAL 通常被称作第一个专家系统。

医学那个叫 MYCIN，1972 年春天在斯坦福起步，做的人是医学生 Edward Shortliffe、计算机科学家 Bruce Buchanan 和临床药理学家 Stanley Cohen，感染科医生 Stanton Axline 提供领域判断。目标：给菌血症和脑膜炎病人选抗生素。1976 年它成了 Shortliffe 的博士论文，同年作为专著出版，书名《Computer-Based Medical Consultations: MYCIN》。

选择抗生素这件事，为什么值得用一整个博士论文去做？因为它是一个**知识密集、证据不全、后果严重**的决策：培养要 24–48 小时才出结果，医生必须先在涂片和临床信息不足的情况下开药；开错药会死人，开多了会养出耐药菌。这类问题恰好落在「搜索没用、经验有用」的位置上。

## 二、机制：把诊断写成规则，把不确定写成算术

MYCIN 的知识不是一棵决策树，是一批各自独立的规则。一条真实规则的样子大致是：

```text
规则 037
  如果  1) 该菌的革兰氏染色为阴性
        2) 该菌形态为杆状
        3) 该菌为兼性厌氧
  那么  该菌的identity 为 enterobacteriaceae，可信度 0.6
```

规则之间通过结论互指：一条规则的结论可以当另一条规则的前提，于是形成链。推理方向是**从目标往回走**——先假设「我要确定菌种」，去找哪些规则的结论是「菌种」，再逐条检查它们的前提是否已知；前提不已知，就再往回走一层，直到撞上可以直接问医生的属性（涂片结果、培养结果、病人是否粒细胞缺乏）。这就是反向链（backward chaining）。它省的地方在于：一次问诊可能只用到 450 条里的 20 条，剩下的不必求值。

不确定性的处理是 MYCIN 最被反复引用的部分。规则强度是一个落在 $[-1,1]$ 的数，叫确定因子（certainty factor, CF）：$+1$ 表示「这条规则必成立」，$-1$ 表示「必不成立」，0 表示「这条经验什么都不说明」。一条规则被触发时，结论的 CF 不是规则强度本身，而是前提的 CF 乘规则强度：

$$CF(\text{结论}) = \min_i CF(\text{前提}_i) \times CF(\text{规则})$$

前提是合取，取最小值。多条规则支持同一个结论时，用 MYCIN 的组合函数叠加：

$$CF(x,y) = \begin{cases} x + y(1-x) & x,y \ge 0 \\[2pt] \dfrac{x+y}{1-\min(|x|,|y|)} & \text{符号相反} \\[2pt] x + y(1+x) & x,y < 0 \end{cases}$$

这个式子的性质值得盯一下，因为它决定了整套机制的天花板。同号两正时 $CF$ 是 $1-(1-x)(1-y)$，也就是「两条都没中的概率」相乘，和噪声或（noisy-OR）同构；代入 $0.9$ 和 $0.9$ 得 $0.99$——**永远到不了 1.0**，也永远不为 0，除非输入本身是。异号时按 $|x|,|y|$ 里较小的那个做分母，效果是「弱的一方几乎被强的一方吞掉」：$0.6$ 遇 $-0.3$ 只剩 $0.4286$。

### 2.1 一个能跑的最小推理机

下面的实现只依赖标准库，约 180 行，复刻了反向链、CF 算术和「结论多值」这三个结构特征（原系统约 450 条规则，跑在 Interlisp 上，代码未公开，所以这里是重写而非移植）。完整脚本在仓库 `demos/ai-evolution-07-1970s-mycin-expert-systems.py`。

```python
def combine(x, y):
    if x >= 0 and y >= 0:
        return x + y * (1 - x)
    if x < 0 and y < 0:
        return x + y * (1 + x)
    return (x + y) / (1 - min(abs(x), abs(y)))

class Engine:
    def __init__(self, rules, chart):
        self.rules, self.chart = rules, chart
        self.memo, self.asked, self.trace = {}, [], []

    def cf_of(self, attr):
        if attr in self.memo:
            return self.memo[attr]
        if attr in self.chart:                     # 可观测属性：直接问
            self.asked.append(attr)
            self.memo[attr] = self.chart[attr]
            return self.memo[attr]

        self.memo[attr] = (None, 0.0)              # 占位，防规则互指成环
        support = {}
        for name, premise, concl, rcf, src in self.rules:
            if concl[0] != attr:
                continue
            pcf, ok = 1.0, True
            for p_attr, p_val in premise:
                val, cf = self.cf_of(p_attr)
                if val != p_val:
                    ok = False
                    break
                pcf = min(pcf, cf)                 # 合取取最小值
            if not ok:
                continue
            c = pcf * rcf
            support.setdefault(concl[1], []).append((name, c, pcf))
            self.trace.append((name, concl[1], pcf, rcf, c))

        best_val, best_cf = None, 0.0
        for val, items in support.items():
            total = 0.0
            for _, c, _ in items:                  # 多条证据依次合并
                total = combine(total, c)
            if abs(total) > abs(best_cf):
                best_val, best_cf = val, total
        self.memo[attr] = (best_val, best_cf)
        return self.memo[attr]
```

四个病例跑下来（本机 `/usr/bin/python3`，真实输出）：

```text
A · 血培养：革兰阴性杆菌，需氧
  问了 5 条：gram, morph, air, site, host
  菌种 e.coli  CF=+0.600
  建议 gentamicin   CF=+0.360
    R001 前提 1.000 × 规则 0.60 = +0.600 -> e.coli
    R010 前提 0.600 × 规则 0.60 = +0.360 -> yes

B · 儿童脑膜炎，脑脊液涂片
  问了 6 条：gram, morph, air, site, patient, host
  菌种 e.coli  CF=+0.600
  建议 gentamicin   CF=+0.360
  建议 cefotaxime   CF=+0.300
  建议 ticarcillin  CF=+0.180
    R001 前提 1.000 × 规则 0.60 = +0.600 -> e.coli
    R007 前提 1.000 × 规则 0.50 = +0.500 -> hemophilus

C · 尿培养：革兰阴性杆菌
  问了 5 条：gram, morph, air, site, host
  菌种 e.coli  CF=+0.800
  建议 gentamicin   CF=+0.480
    R001 前提 1.000 × 规则 0.60 = +0.600 -> e.coli
    R003 前提 1.000 × 规则 0.50 = +0.500 -> e.coli
    R010 前提 0.800 × 规则 0.60 = +0.480 -> yes
```

三件事在输出里都看得见。第一，问诊是**按需**发生的：病例 D 只问了 4 条属性，因为链上没有别的分支需要展开。第二，产物是**多值**的：B 里系统同时给了三种药各自的 CF，不是一句「该用 X」，因为临床上「加一种覆盖厌氧菌的药」和「换药」是两回事，单值分类撑不住这种语义。第三，弱证据会**累加**：C 里两条规则指向同一个菌种，$0.6$ 和 $0.5$ 合成 $0.8$ 而不是取大值 $0.6$。

### 2.2 这个算术的两个后果

第一个后果是：**十几条弱证据足以伪造出高置信度**。取 20 条各自 $CF=0.2$ 的独立规则依次合并，迭代式恰好有闭式解 $1-0.8^n$：

```text
    n= 1   CF=0.2000
    n= 2   CF=0.3600
    n= 3   CF=0.4880
    n= 4   CF=0.5904
    n= 8   CF=0.8322
    n=12   CF=0.9313
    n=16   CF=0.9719
    n=20   CF=0.9885
  第 11 条越过 0.90；n=20 时 0.9885
  闭式解 1-0.8^n 与迭代值一致：n=11 -> 0.9141
```

也就是说，只要知识库里对某个结论有十来条「有点道理」的弱规则，系统输出的 CF 就会稳定地站在 0.9 以上，无论这些规则是否互相独立、是否只是同一个来源的重复表述。原书第 36 章对这个问题有明确记录：如果不加约束，许多小证据会把每个假设都推到 0.99，假设之间的区分度就消失了。真实系统靠两件事压住它：一是同一条结论的规则数量本来就不多，二是规则强度普遍不高。

第二个后果，是常被引用的那句批评——「CF 合并依赖证据顺序，结论不稳定」。把 $\{0.6,-0.3,0.5\}$ 的六种排列全跑一遍：

```text
   +0.6 -> -0.3 -> +0.5   CF=+0.714286
   +0.6 -> +0.5 -> -0.3   CF=+0.714286
   -0.3 -> +0.6 -> +0.5   CF=+0.714286
   -0.3 -> +0.5 -> +0.6   CF=+0.714286
   +0.5 -> +0.6 -> -0.3   CF=+0.714286
   +0.5 -> -0.3 -> +0.6   CF=+0.714286
  极差 1.11e-16
  10 万组随机三元组：最大极差 3.397e-14
```

在这个公式上，顺序不改变结果——10 万组随机三元组（含大量异号组合）的最大极差是 $3.4\times10^{-14}$，纯粹是浮点误差。这条批评对别的 CF 变体或许成立，但对 MYCIN 用的这个式子，实测不成立。它真正的毛病不是顺序，而是语义：CF 不是概率，$CF=0.8$ 没有「80% 的概率」这个含义，两条证据合并也不是贝叶斯更新。后来有工作证明它在特定假设下可以解释成概率，但那些假设（证据条件独立）在临床里恰恰不成立。

第三个结构特征容易被忽略：**知识库与推理机是分开的**。规则是数据，引擎是代码；把 MYCIN 的 450 条医学规则掏空，剩下的引擎换个领域填规则就能用。这套空壳被抽出来单独发布，叫 EMYCIN（Essential MYCIN），是后来所有「专家系统外壳」的祖先。围绕它的工作流程也有了自己的名字：一个知识工程师坐下来访谈专家，把对方的经验逼成规则，再拿病例回来试，错了就改规则。1977 年之后，这套流程被叫作 knowledge engineering（知识工程）。

## 三、产物：一份盲测、一台配置器、一个被封存的知识库

MYCIN 的验证做得比多数人记得的严格。1979 年 9 月的《JAMA》（242(12):1279–1282）刊出一项盲评：10 个脑膜炎病例，9 位开方者（斯坦福的 5 位感染科主治、1 位 fellow、1 位住院医、1 位医学生，加上 MYCIN），8 位外院感染科专家在不知道哪份方案来自机器的前提下逐份判定「可接受 / 不可接受」。结果：MYCIN 的方案获得 65% 的可接受评级，五位主治的方案在 42.5%–62.5% 之间；并且 MYCIN 在 10 个病例里没有一次漏掉可治疗的病原体，同时处方的抗菌药数量更少。同年另一项发表于《Computer Programs in Biomedicine》（9(1):95–102）的评估里，斯坦福专家判定 MYCIN 在菌血症上的治疗方案 90.9% 符合可接受实践。

这里要说清楚一件事：65% 的可接受率不等于「比医生强」。它说明的是，在一个被切得很窄、评价标准被事先定义好的任务上，规则系统的输出落在专家群体的区间内，且没有出现灾难性的漏诊。这套评估方法本身（盲评、外院专家、可接受性分级）是这项工作的另一半产物，后来被反复借用。

它还有一个在 1970 年代相当罕见的特性：能解释自己。医生问「你为什么问这个」，系统会给出正在求值的那条规则；问「你怎么得出这个结论」，系统会把推理链倒着打印出来。这不是事后加的界面，而是规则式表示的直接副产品：知识本来就是一条条独立的、可读的句子，解释就是把用过的句子念出来。黑箱模型在四十多年后重新成为主流，这个能力反而成了要专门研究的东西。

MYCIN 从未在病人身上用过。1978 年底它变成一个静态系统，留在 SUMEX 上供演示和学生项目使用；作者在 1984 年的复盘里写得很直白：知识库「被搁置了」。

关于为什么没进病房，流传最广的版本是「法律责任没人敢担」。这个归因需要打折扣。作者本人在同一份复盘里列的清单要具体得多，也更难解决：医生并不觉得自己需要这个东西（他们对选抗生素这件事相当自信）；把它嵌进日常工作流做不到——为了问一次诊，医生得找到一台终端、登录、回答一连串问题，其中不少只是把别的系统里已有的化验值再手敲一遍；SUMEX 是研究机器，负载高的时候两次提问之间会有恼人的停顿，一次完整问诊可能要 30 分钟到一个小时；整个系统绑在 Interlisp 和 PDP-10 上，搬到别的机器不现实；扩充知识库的经费在系统「已经够大够好」之后反而拿不到。法律责任在他们后期的总结里确实被列为可接受性问题之一，但不是清单的第一项，也不是唯一一项。把「没进病房」全部归给法律，是后来二手叙述里最省事、也最不准确的那个版本——这件事至今没有一致结论，任何单一归因都站不住。

真正把规则系统推上生产线的，是另一类任务：不需要处理人命，但错误极其昂贵。1978 年，卡内基梅隆的 John McDermott 用 OPS5 写了 R1，给 DEC 配置 VAX 订单——一台机器该配哪些板卡、背板槽位怎么排、电源够不够、线缆多长。1980 年 1 月它在 DEC 新罕布什尔州 Salem 的工厂投产，改名 XCON。初期约 750 条规则；到 1986 年处理了 8 万张订单，准确率 95%–98%；DEC 估算它每年省下约 2500 万美元（少赔因配置错误白送客户的部件、装配更快）。规则数随后失控：1987 年 6200 条，1989 年 10129 条，且每年有约一半在改。DEC 自己的说法是，规则从 700 条涨到 6200 条时，维护难度不是线性增长的。

这条曲线就是专家系统留给后来的真正教训：**知识获取是瓶颈，知识维护是更硬的瓶颈**。写规则的人会走，领域会变，规则之间的交互会以没人预料到的方式互相干扰。MYCIN 的知识库在停更五年后就明显过期了——三代头孢上市，抗生素选择的标准整个变了，而规则还停在 1978 年。

## 四、下一篇：1986 年，误差往回传

1970 年代的这场胜利是有限度的：它把「知识」放进了系统，但没有让系统自己获得知识。规则是人写的，写一条就得有人负责一条，多一个领域就多一批访谈。与此同期，另一条线在 1969 年之后几乎断掉——多层网络没有可行的训练方法，Minsky 与 Papert 的那个「不育」猜想看上去得到了印证。

1986 年，Rumelhart、Hinton、Williams 把链式法则系统地接到多层网络上，误差从输出层往回传，隐层的权重终于有了梯度。这一篇讲它为什么在 1986 年才成立（而不是 1974 年 Werbos 的博士论文里），以及它如何用「特征自己学」替换掉「特征由人写」，把 1970 年代那个知识获取瓶颈换个位置重新摆出来。
