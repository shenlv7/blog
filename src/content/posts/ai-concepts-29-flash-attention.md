# AI核心概念(29)：FlashAttention 分块注意力——显存从 128MB 掉到 96KB，逐元素误差还剩 2.6e-16

> 注意力的显存黑洞不是矩阵乘，是 softmax。softmax 要拿整行做分母，所以整行必须先被算出来、写进显存、再读回来。把这一行拆成块之后，数学上可以精确地等价——1e-16 级别的等价——前提是每换一次更大的块，之前累加的结果都要被重新标定一次。那一次乘法漏掉，输出就错 95.6%。

## 🎯 前提：softmax 天生要看到整行

注意力那一步可以写成三行：

```
S = Q Kᵀ / √d          # 分数矩阵，N × N
P = softmax(S, dim=-1)  # 逐行归一化
O = P V                 # 输出，N × d
```

问题出在第二行。`softmax` 的分母是**整行**的 `exp` 之和，所以「算这行的一半」在数学上没有意义——你不知道分母是多少。于是最自然的实现是：

1. 把整张 `S`（N×N）算出来落到显存里；
2. 遍历一遍求每行最大值 `m`（防止 exp 溢出）；
3. 做 `exp`，得到同样 N×N 的 `P`；
4. 求和、相除、再乘 `V`。

术语现场解释：这里的「显存」指 GPU 的 HBM，容量大（几十 GB）、带宽慢；片上还有一块 SRAM，快得多但只有一百多 KB 量级。所谓 **IO-aware**，就是把「算得快」换成「少搬几次数据」。

于是显存峰值被 `S` 和 `P` 死死钉在 ∝ N² 上。实测账（fp32，d=128）：

| 序列长度 N | S 矩阵 | S + P 两个矩阵 |
|---|---|---|
| 1024 | 4.0 MB | 8.0 MB |
| 2048 | 16.0 MB | 32.0 MB |
| 4096 | 64.0 MB | 128.0 MB |
| 8192 | 256.0 MB | 512.0 MB |
| 32768 | 4096.0 MB | 8192.0 MB |

N=32768 时，光是存这份中间结果就要 8 GB。而它对最终输出 `O` 没有任何独立贡献——它只是一个为了归一化而存在的中间量，用完就扔。

## 🔬 在线 softmax：整行可以被压成两行状态

关键观察是：softmax 分母可以**增量**地维护。设已经扫描过的部分得到运行最大值 `m` 和运行分母 `l`，来了一块新分数（记这块里的最大值为 `m_new`）：

```
m_new = max(m, max(块内 S))
l     = l · exp(m − m_new)      + Σ exp(S − m_new)
O     = O · exp(m − m_new)      + Σ exp(S − m_new) · V
```

扫完所有块后，`O / l` 就是标准 softmax 注意力的**精确**结果。两个要点：

- `m − m_new ≤ 0`，所以那个指数因子总是 ≤ 1，不会溢出；它是为了让**之前**的累加结果跟新分母对齐——新块带来了更大的最大值，老结果的尺度就相对变小了，必须回缩。
- 状态只有 `m`、`l` 两行（各 N 个数）加一个 N×d 的累加器 `O`。N×N 的中间矩阵从头到尾没有出现过。

这个技巧叫 **online softmax**，不是 FlashAttention 发明的（Milakov 与 Gimelshein 在 2018 年就给了 softmax 的在线归一化算法）；FlashAttention（Dao 等，NeurIPS 2022）做的是把它变成 IO-aware 的 CUDA kernel，把块锁在 SRAM 里、把 exp 和高精度累加融进矩阵乘，并且在反向传播里不保存 `P` 而是重新算一遍。收益的来源是**减少 HBM 访问**，不是减少计算量——这一点后面有实测。

## 🏗️ 拆开看：等价到什么程度

下面这张表是本文 Demo 的第一组结果，N=512、d=64、fp64，参考值是朴素实现：

| 实现 | 块大小 | max\|ΔO\| | 相对误差 | rescale 触发行次 |
|---|---|---|---|---|
| 仅列分块 | 8 | 3.331e-16 | 6.929e-16 | 2537 |
| 仅列分块 | 64 | 2.637e-16 | 5.485e-16 | 1396 |
| 仅列分块 | 512（不分块） | 3.123e-16 | 6.496e-16 | 512 |
| 2D tiling | 64（行块 128） | 2.637e-16 | 5.485e-16 | 1396 |
| 2D tiling | 32（行块 32） | 2.776e-16 | 5.774e-16 | 1786 |

三个结论：

1. **块大小不影响结果。** 误差在所有配置下都停在 2.6e-16 到 3.3e-16，而 fp64 的机器精度是 2.2e-16——也就是说，剩下的差异全是浮点加法的结合律差异，与分块策略无关。
2. **行也能切。** 二维 tiling（`Br=32, Bc=32`）误差同样是 2.776e-16。这才是能铺满 GPU 的做法：行块和列块各给一个并行维度。
3. **精度越高，分块越安全。** 概率行和的偏差是 4.441e-16，即 1 附近差 4 个 1e-16。

这不是「差不多」的近似注意力——FlashAttention 的卖点恰恰是 **exact attention**。真正近似的是别的路线（稀疏注意力、线性注意力）。

## 💻 可运行代码

核心就两个函数，纯 numpy，本机实测跑通。完整脚本（含下面所有实验的表）放在文末。

```python
import numpy as np

def attn_naive(Q, K, V, scale):
    """朴素实现：物化 N x N 的分数矩阵与概率矩阵。"""
    S = (Q @ K.T) * scale
    m = S.max(axis=1, keepdims=True)
    P = np.exp(S - m)
    P /= P.sum(axis=1, keepdims=True)
    return P @ V, S, P

def attn_flash(Q, K, V, scale, Bc, rescale=True):
    """online softmax + 按 key 维分块，块大小 Bc。"""
    N, d = Q.shape
    O = np.zeros((N, d)); m = np.full(N, -np.inf); l = np.zeros(N)
    for c0 in range(0, N, Bc):
        Kb, Vb = K[c0:c0 + Bc], V[c0:c0 + Bc]
        S = (Q @ Kb.T) * scale                    # 只在 SRAM 里存在的块
        m_new = np.maximum(m, S.max(axis=1))
        alpha = np.exp(m - m_new) if rescale else np.ones_like(m)   # ← 就是这一行
        P = np.exp(S - m_new[:, None])
        l = l * alpha + P.sum(axis=1)
        O = O * alpha[:, None] + P @ Vb
        m = m_new
    return O / l[:, None]
```

跑一行对照：

```python
N, d = 512, 64; scale = 1.0 / np.sqrt(d)
Q, K, V = (np.random.default_rng(20260922).standard_normal((N, d)) for _ in range(3))
ref = attn_naive(Q, K, V, scale)[0]
print(np.abs(attn_flash(Q, K, V, scale, Bc=64) - ref).max())   # 2.637e-16
```

## 📊 显存会计：从 128MB 到 96KB

分块实现要占的显存只有三样：块本身（`Br×Bc` 的分数块）、两行状态 `m`/`l`、输出累加器 `O`。按 128×128 的块算：

| 序列长度 N | 显式 S + P | 分块用的块 | 在线状态 m, l | 降幅 |
|---|---|---|---|---|
| 2048 | 32.0 MB | 64.0 KB | 16.0 KB | 410× |
| 4096 | 128.0 MB | 64.0 KB | 32.0 KB | 1365× |
| 8192 | 512.0 MB | 64.0 KB | 64.0 KB | 4096× |
| 32768 | 8192.0 MB | 64.0 KB | 256.0 KB | 26214× |

诚实补一句：输出累加器 `O` 是 N×d，和输入 `V` 同量级，朴素实现也要，所以不计入降幅。真正变的是**峰值显存不再随 N² 增长**——这一条决定了长上下文能不能训、能不能跑（另一条显存线是 KV cache，第 22 篇讲过，它靠 PagedAttention 这类分页方案解决，两者管的是不同的东西：一个管分数矩阵，一个管 KV）。

## ⚠️ 数字会溢出：减法不是可选项

`exp` 的浮点上限很硬，实测：

| 类型 | 表示上限 | exp 参数上限 ln(max) |
|---|---|---|
| float16 | 6.550e+04 | 11.0899 |
| float32 | 3.403e+38 | 88.7228 |
| float64 | 1.798e+308 | 709.7827 |

也就是说 fp16 里只要某个 logit 比同行其他值大 11.1 以上，不减最大值就爆。实测一组跨度较大的 logit（16 列、标准差 12）在 fp16 上：

- **朴素实现**（先 `exp` 再归一化）：出现 **9 个 inf**，softmax 结果出现 **9 个 nan**——整行直接废掉。
- **在线实现**（先减运行最大值）：结果全部有限，但 `max|Δ| = 4.558e-04`。

第二点值得展开：误差不是来自算法，而是来自 fp16 只有 11 位有效位（尾数 10 位），概率靠近 1 时的最小可分辨步长约为 2⁻¹¹ ≈ 4.9e-4——量级正好对得上。这也是为什么工程实现里 `m`、`l` 这类 softmax 统计量通常用 fp32 累加，即使输入是 fp16/bf16。

还有下溢：那组 logit 的概率跨度是 **2^−68.5**（max=1.0，min=2.4e-21），小于 fp16 次正规数下限的部分全部变成 0（实测 `min = 0.000e+00`）。总质量偏差 1.1e-5（行和 1.000011）——长尾被削平了，但因为它们本来就极小，对输出几乎无影响。

fp32 也不能无脑算：把 logit 拉到 1000（极端离群值），朴素 fp32 同样给出 4 个 inf 和 4 个 nan，而在线版本行和仍然是 1.000000。

## 🔪 少写那一行 rescale：错 95.6%

构造一组「越往后 logit 量级越大」的 key（第 128 行以后 ×4，第 192 行以后 ×8），让运行最大值持续抬升——这正是老结果必须回缩的时候：

| 实现 | max\|ΔO\| | 相对误差 |
|---|---|---|
| 带 rescale（正确） | 0.000000 | 0.0000 |
| 不带 rescale | 3.347364 | 0.9562 |

参考量级 `max|O| = 3.5`，所以「不带 rescale」的输出差不多是彻底错的。注意 `不带 rescale` 那行的触发计数是 0——因为代码里根本没做这个判断，永远不会发现自己在错。

这段代码里最容易被当成「数学推导里的装饰」的就是 `alpha = exp(m - m_new)`。它不是装饰：当新块的运行最大值更大时，早先块的 `l` 和 `O` 是用更小的分母尺度累加出来的，必须整体乘上这个回缩因子才能和新分母对齐。几乎所有自己手写在线 softmax 的第一次失败，都失败在这里。

## 💡 诚实边界：为什么用 numpy 复现不会更快

论文里 FlashAttention 的加速来自「块留在片上 SRAM、中间结果不回 HBM、softmax 与矩阵乘融合成一个 kernel」。用 numpy 复现，这三条一条都做不到。实测：

| N | 朴素实现 | 分块（Bc=128） | 倍数 |
|---|---|---|---|
| 1024 | 69.34 ms | 69.54 ms | 1.0× |
| 2048 | 260.77 ms | 263.75 ms | 1.0× |
| 4096 | 1049.87 ms | 1037.66 ms | 1.0× |

既不更快，也不更慢——**1.0×**。这个「没有变化」本身就是结论：分块不省 FLOPs（每个分数元素仍然只算一次），它省的是把 N×N 写回 HBM 再读回来的那几次搬运；而在 numpy 里，每个块算完照样落回内存，IO 成本一点没省，收益自然是 0。真正拿到收益要靠 CUDA kernel 把块按 SRAM 大小切（这也是块大小在真实实现里通常取 64~128 的原因：更小则并行度足够但算术强度下降，更大则 SRAM 放不下）。

## 小结

- softmax 的「整行依赖」是注意力显存 O(N²) 的唯一来源，而不是矩阵乘。
- 在线 softmax 用一个运行最大值 `m`、一个运行分母 `l` 把整行压成两行状态，数学上精确：块取 8、64、512 或改成二维 tiling，误差都停在 fp64 舍入水平 2.6e-16。
- 唯一真正容易写错的是 rescale 因子 `exp(m_old − m_new)`；漏掉它，输出相对误差 95.6%。
- 溢出靠减最大值解决（fp16 的 exp 参数上限只有 11.09），尾数精度的损失（4.6e-4）靠把 `m`、`l` 用 fp32 累加来缓解。
- 它省的是 IO 不是 FLOPs——所以在 numpy 里做同样的分块，加速是 1.0×。
