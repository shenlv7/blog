# AI核心概念(34)：混合精度——范围、精度，和你以为不存在的第三件事

> 上一批文章在讲怎么把模型压小：量化(21)、GQA(30)、KV-Cache 量化。但真正在 GPU 上跑训练的人都绕不开另一套数字：FP32、FP16、BF16、FP8。它们不是"精度高低的四档"，而是**三种互相冲突的需求**在硬件上打出来的折中。只看"有多少位"会永远踩坑——FP16 的尾数比 BF16 多 3 位，实际训练里却常常是 BF16 更省事，原因藏在指数位里。

## 🎯 三种需求：范围、精度、吞吐

一个浮点数拆成三段：符号位、指数位、尾数位。

- **指数位决定范围**：能表示到多大、能分辨到多小。每多一个指数位，动态范围翻倍。
- **尾数位决定精度**：同一个数量级内的刻度有多密。
- **总位宽决定吞吐**：位宽减半，显存减半、TensorCore 的理论算力翻数倍。

FP16 把 32 位砍到 16 位，砍的不是平均分配：指数位从 8 降到 5，尾数从 23 降到 10。结果就是——**精度损失可接受，范围损失无法接受**。下一个实验把这件事量化。

## 📊 三种格式的真实能力（本机实测）

```
格式           符号   指数   尾数        最大有限值        最小正规       最小次正规     1.0处间隔       动态范围
FP32          1    8   23    3.403e+38    1.18e-38     1.4e-45  1.192e-07       277b
FP16          1    5   10     6.55e+04     6.1e-05    5.96e-08  0.0009766        40b
BF16          1    8    7     3.39e+38    1.18e-38     9.18e-41   0.007812       261b
FP8-E4M3      1    4    3          448      0.0156     0.00195      0.125        18b
```

读这张表只看两列：

- **动态范围**：FP16 只有 **40 个 2 的幂**，FP32/BF16 有 261~277 个。这一列后面会要命。
- **1.0 处间隔**：FP16 是 9.77e-4，BF16 是 7.8e-3。这就是那个反直觉结论的来源——**BF16 精度是差 8 倍的，但它是 2026 年训练默认值**，因为它的范围和 FP32 同构，什么数都不会溢出、不会消失。

BF16 的 "B" 是 Brain Floating Point，Google Brain 2018 年推的。它的逻辑非常工程化：**训练里最贵的不是精度不够，是数值逃跑**。你用 FP16 训练，就得额外养一套缩放机制去追着数字跑；用 BF16，什么都不用做，只是最后学到的参数比 FP32 粗糙一点点。

## 🔬 实验一：先证明这把尺子本身是准的

这一篇所有结论都建立在一个自己写的量化模拟器上（本机没有 numpy/torch，全部用标准库 `math.frexp` + 半数偶数舍入手搓）。既然是手搓的，**第一件事是证明它和真实硬件行为一致**：

```
实验2  FP16 模拟器 vs struct 原生，逐位交叉验证
样本 200000 个，指数 -30..30（覆盖 2^60 动态范围）
  逐位一致   : 153947  (76.97%)
  双方判溢出 : 46053
  不一致     : 0
```

Python 的 `struct` 支持 `'<e'` 格式，直接调用 C 层的 half 转换。20 万个样本、指数从 2⁻³⁰ 到 2³⁰，我的模拟器和它**逐位一致、0 处分歧**，连"什么时候该溢出成 inf"都完全同步（4.6 万例）。之前做量化那篇时我就发现，不先做这一步校准，后面所有"误差是多少"的结论都可能是模拟器自己的 bug。

顺手看一眼它在边界上的行为，这是后面所有坑的源头：

```
          输入                FP16                BF16            FP8-E4M3
     6.2e-05          6.1989e-05          6.1989e-05                   0
       1e-08                   0          1.0012e-08                   0
       0.002           0.0020008           0.0019989           0.0019531
       65520                  溢出               65536                  溢出
```

注意 1e-8：FP16 直接变成 0，BF16 保住了。这不是舍入误差，这是**信息消失**。

## 🏗️ 实验二：梯度随深度衰减，FP16 的地板在哪

构造一个 `1 → 16×depth → 1` 的 tanh 网络（输出层线性），只改深度，用纯 fp32 反向传播测量每层梯度：

```
实验4  同一个网络，只改深度：首层梯度量级与三种格式的存活率
  深度      首层|grad|中位      全网|grad|下界    FP16归零%    FP16x2^15归零%    BF16归零%   需2^k
   2       5.533e-03       4.600e-05      0.00%           0.00%      0.00%      1
   3       5.236e-04       5.475e-08      0.00%           0.00%      0.00%     10
   4       1.043e-04       3.628e-09      2.12%           0.00%      0.00%     13
   6       7.437e-07       4.987e-11     29.50%           0.00%      0.00%     17
   8       5.637e-09       7.205e-13     99.95%           0.05%      0.00%     23
```

三件事同时发生了：

1. 深度每加一层，首层梯度中位数掉一个数量级左右（tanh 导数 + 小初始化，经典消失梯度）。
2. 到 8 层，**99.95% 的梯度在 FP16 里直接归零**——网络第一层实际上收不到任何梯度信号。
3. 同一批梯度，BF16 归零率 **0.00%**。

最后加一列"需 2^k"：**要让 99% 的梯度升进 FP16 的正规区间，静态放大倍数得给到 2²³**。而 FP16 自己的动态范围只有 2⁴⁰——深度一层就吃掉 5 个比特，8 层网就吃掉一大半。这就是 FP16 训练必须配 loss scaling 的全部原因：不是精度不够，是**信号掉进了地板缝里**。

## 💻 核心代码：量化模拟器

整篇文章只需要这一个函数就能复现全部行为：

```python
import math

def rte(x):
    """round to nearest, ties to even —— 浮点硬件默认舍入模式"""
    f = math.floor(x)
    d = x - f
    if d > 0.5:
        return f + 1
    if d < 0.5:
        return f
    return f if f % 2 == 0 else f + 1

class Fmt:
    def __init__(self, name, eb, mb):
        self.eb, self.mb = eb, mb
        self.bias = 2 ** (eb - 1) - 1
        self.emax, self.emin = self.bias, 1 - self.bias
        self.max = (2 - 2.0 ** -mb) * 2.0 ** self.emax
        self.min_normal = 2.0 ** self.emin
        self.min_sub = 2.0 ** (self.emin - mb)      # 次正规数的最小步长

    def quant(self, x):
        if x == 0.0 or x != x:
            return x, False
        s = math.copysign(1.0, x)
        a = abs(x)
        m, e = math.frexp(a)                        # a = m * 2^e, m ∈ [0.5, 1)
        p = e - 1
        if p >= self.emin:                          # 正规数
            k = rte((2 * m - 1) * 2 ** self.mb)
            if k == 2 ** self.mb:                   # 尾数进位
                k, p = 0, p + 1
            v = (1 + k / 2 ** self.mb) * 2.0 ** p
        else:                                       # 次正规数：固定步长
            step = 2.0 ** (self.emin - self.mb)
            v = rte(a / step) * step
        if v > self.max:
            return None, True                       # 溢出（FP16 里就是 inf）
        return s * v, False

FP16 = Fmt("FP16", 5, 10)
BF16 = Fmt("BF16", 8, 7)
```

FP8-E4M3 需要一处特例：它的指数全 1 留给 NaN，所以没有 inf，上限是 448 而不是 `(2-2⁻³)×2⁷=240`。**这种细节不实测就是错的**——我第一版就写错了，跑出来 F4M3 上限是 240。

## 🔬 实验三：被舍入吞掉的参数更新（训练里最阴的坑）

用 `y = 3x + 2`、单隐层 8 个 tanh 单元的极小网络，跑 2000 步全批梯度下降，比较三条数值路径：

```
  FP32 全精度
    训练 MSE: 0:4.28e+00  200:1.01e-02  400:5.34e-03 ... 1000:2.55e-03 ... 2000:1.44e-03
  FP16 裸跑(参数也存 fp16)
    训练 MSE: 0:4.28e+00  200:1.01e-02  400:5.82e-03 ... 1000:4.32e-03 ... 2000:3.65e-03
    被舍入吞掉的更新: 全程 71.9% / 最后 200 步 89.9%
  FP16 计算 + FP32 主副本(标准 AMP)
    训练 MSE: 0:4.28e+00  200:1.01e-02  400:5.34e-03 ... 2000:1.43e-03

  FP16 裸跑相对 FP32 的末期 MSE 劣化: 2.5x
  AMP 相对 FP32 的末期 MSE 比值: 0.998x
```

关键指标不是 MSE（2.5 倍还不算致命），而是那个 **89.9%**：训练后期，十次参数更新里有九次**执行了、但结果和没执行完全一样**。因为参数 w≈1.0 时 FP16 的刻度间隔是 9.8e-4，而后期每步的更新量是 lr×梯度 ≈ 5e-6，比刻度还小——`w - 5e-6` 舍入回 fp16，还是原来那个 w。

这就是"小步长被大数吞掉"（swamping），也是为什么 FP16 训练的标准配方是**保留一份 FP32 主副本**：前向反向用 FP16 跑得快，参数更新在 FP32 里做。表里 AMP 那一行的 MSE 比值 0.998 说明在这个尺度上它和全精度没有区别。

## 🔬 实验四：累加精度比乘法精度更重要

2048 维点积，200 次随机试算，以 fp64 精确和为基准：

```
累加方式                                      中位相对误差        最大相对误差
FP16 输入 + FP16 逐项累加                    5.426e-03     2.593e-01
BF16 输入 + BF16 逐项累加                    4.279e-02     2.358e+00
FP16 输入 + FP32 累加(TensorCore)            2.806e-04     2.964e-02
```

第三行是真实硬件在做的事：**输入用低精度，累加器用 FP32**。相对全程 FP16 累加，误差低 19 倍。原因很直白——逐项累加时，和会越来越大，小项在被加进去时先被舍入，误差随项数累积（√n 量级）。

BF16 那行的最大相对误差是 **2.358**，也就是错了 235%，这已经完全是另一个数了——两个近乎抵消的大项相减，低精度累加器直接崩掉。所以 FP8/BF16 的 GEMM 里"乘完那个加法在哪儿"比"乘法用什么精度"重要得多。

## 🔬 实验五：loss scale 的窗口只有六个比特

把所有深度的梯度合成一个池子，模拟真实网络里跨层跨参数的梯度跨度，扫描静态缩放倍数：

```
  梯度池跨度: 7.205e-13 .. 1.919e-02 = 2.663e+10 倍 (FP16 可表示窗口 1.099e+12 倍 = 40 个 2 的幂)

   scale         最大梯度xS       溢出率       仍归零率   判定
     2^0      1.919e-02      0.0%      46.7%   仍有梯度被抹零
     2^8      4.913e+00      0.0%       3.5%   仍有梯度被抹零
    2^16      1.258e+03      0.0%       0.0%   可用
    2^20      2.012e+04      0.0%       0.0%   可用
    2^24      3.220e+05      0.5%       0.5%   两头都不行
    2^40      2.110e+10     48.4%      48.4%   两头都不行

  可用 scale 区间: 2^16 .. 2^21（宽度 6 个 2 的幂）
```

**可用窗口只有 2¹⁶ 到 2²¹，六个比特宽**。往下，小梯度继续被抹零；往上，最大的那一批梯度先溢出成 inf。2²⁴ 开始"两头都不行"——一边有 0.5% 溢出，另一边 0.5% 归零，**单靠一个静态 scale 已经无解**。

这就是 PyTorch AMP 里 `GradScaler` 必须"动态"的全部理由：它每次检查有没有 inf，有就跳过这一步并把 scale 减半，几十步没出事就翻倍，本质是在这六个比特里做自适应搜索。也是为什么 FP8 的方案更极端（per-tensor / per-block scale），BF16 干脆不要 scale。

## 💡 最后：FP16 里 exp 的爆炸半径

```
     d     点积std      |点积|最大        未缩放溢出率        缩放后溢出率     缩放后max
   128      11.3       42.63         16.4%          0.0%       3.77
  1024      32.0      109.22         37.0%          0.0%       3.41
  4096      64.0      217.30         43.5%          0.0%       3.22

  FP16 上限 65504 → exp(x) 溢出临界 x = ln(65504) = 11.09
```

4096 维的点积，标准差就是 √4096 = 64，偶尔飙到 200 以上。`exp(200)` 在 FP16 里是 inf，`exp(x)` 只要 x > 11.09 就爆——**43.5% 的分数会在没做缩放的 softmax 里直接变成 inf**，然后 inf/inf = NaN，整个 batch 的 loss 报废。除以 √d 之后溢出率归零（最大值只有 3.22）。

所以注意力必须除以 √d、softmax 必须先减最大值，这些不是"教科书上的优雅写法"，是 FP16 逼出来的工程约束。

## 🧭 工程口径

- **训练默认 BF16**：范围等同 FP32，不需要 loss scaling，代价是尾数 7 位（间隔 7.8e-3）。除非你要跑 FP16 特有的 kernel 或硬件不让，否则没有理由选 FP16。
- **FP16 要配三件套**：FP32 主副本 + 动态 loss scale + 梯度里检查 inf/NaN。缺同样就得跟 89.9% 的"空转更新"打交道。
- **累加器永远是 FP32**：低精度乘法不致命，低精度累加才是（BF16 累加实测最大误差 235%）。
- **FP8 是 2026 年的方向，但必须 per-tensor 缩放**：E4M3 只有 3 位尾数（1.0 处间隔 0.125，相对精度 12.5%），范围也只有 18 个 2 的幂。它靠的是把每一块张量各自归一化到自己的刻度上——换句话说，用大量细粒度的 scale 换掉那个"六个比特宽"的全局窗口。
- **判断标准始终是动态范围，不是位宽**：看到任何新的数值格式，先问三件事——指数位几个、尾数位几个、累加在哪做。
