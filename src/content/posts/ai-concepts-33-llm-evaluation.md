# AI核心概念(33)：模型评测——刻度准了，尺子才准

> 前面 30 多篇讲的全是"怎么让模型更快、更小、更聪明"。但如果你用来衡量这些改进的那把尺子本身有 1.38 分的随机漂移，那么所有"提升了 2%"的实验结论都只是在测量噪声。评测的第一性原理只有一句：**先证明尺子稳定，再谈模型好坏。**

## 🎯 评测分成两半

大模型的评测在工程上就两类，别混着谈：

| | 程序判定 | 模型判定 |
|---|---|---|
| 判定者 | 单元测试 / 精确匹配 / 正则 | 另一个大模型（LLM-as-Judge） |
| 典型基准 | HumanEval、GSM8K、MMLU | AlpacaEval、Chatbot Arena、LMSYS 风格偏好 |
| 优点 | 零噪声、可复现、免费 | 能评开放任务（写作、解释、多轮） |
| 缺点 | 只能评有标准答案的任务 | **有随机性、有位置偏差，需要标定** |
| 关键统计量 | pass@k | 一致率、漂移量、位置加成 |

这一篇两半都做实验：前半验证 pass@k 的公式，后半实地测量 LLM 裁判到底有多不稳。

## 🔬 实验一：pass@k 的无偏估计，和三种常见错法

程序判定的世界里有一个看起来简单、实际坑很深的指标。场景是这样的：让模型对同一道编程题采样 n 次（temperature 高、多样性足），其中 c 次通过了单元测试。你想知道的不是"这 n 次里过了几次"，而是"**如果我只给用户 k 次机会，他能拿到至少一个正确解的概率**"。

直觉答案会写 `c/n` 或 `1-(1-c/n)^k`，这两个都不对。真正的公式来自 HumanEval 论文（Chen et al., 2021）：

```python
from math import comb

def pass_at_k(n, c, k):
    """无偏估计：从 n 个样本中不放回抽 k 个，至少命中 1 个正确的概率"""
    if n - c < k:
        return 1.0          # 错误样本不够 k 个，抽 k 个必中
    return 1.0 - comb(n - c, k) / comb(n, k)
```

它就是一个超几何分布的组合数：C(n-c, k) / C(n, k) 是"抽 k 个全都抽到错误样本"的概率。**不放回**是关键词——k 次尝试共享同一批 n 个样本，样本不会被重复抽到。

我用 20 万次暴力抽样验证了它（n=20、c=3，即单样本通过率 15%）：

| k | 公式 1−C(n−c,k)/C(n,k) | 暴力抽样 20 万次 | 误差 |
|---|---|---|---|
| 1 | 0.1500 | 0.1498 | 0.0002 |
| 2 | 0.2842 | 0.2837 | 0.0005 |
| 5 | 0.6009 | 0.6006 | 0.0002 |
| 10 | 0.8947 | 0.8951 | 0.0004 |
| 20 | 1.0000 | 1.0000 | 0.0000 |

误差全部在 0.0005 以内，说明公式和抽样是完全同构的。也就是说：**只要你有 n 个采样，pass@k 对任意 k≤n 都是同一个式子算出来的，不需要为每个 k 重新跑一遍评测**——这是它最大的工程价值。

现在看错法的代价。`1-(1-c/n)^k` 假设的是"有放回抽样"（每次尝试都独立重新采样）：

| k | 错法 1−(1−c/n)^k | 无偏公式 | 偏差 |
|---|---|---|---|
| 1 | 0.1500 | 0.1500 | +0.00 |
| 5 | 0.5563 | **0.6009** | +4.46 pt |
| 10 | 0.8031 | **0.8947** | +9.16 pt |
| 20 | 0.9612 | **1.0000** | +3.88 pt |

k=10 时高估 9.16 个百分点。方向也值得记住：错法在 k 中等时**低估**（因为它以为每次尝试要重新抽、可能重复抽到同样的错误样本），到 k 接近 n 时又**反过来高估**（有放回的情况下永远抽不满、概率到不了 1，而无放回时 k>n−c 必然命中）。一个公式两头都错，这在对比两篇论文的 pass@k 数字时足以制造一次假复现。

⚠️ 还有一个容易被忽略的坑：**n 太小时 pass@k 会被量化成锯齿**。n=5、c=1 时 k=1..5 只能取 0.20/0.40/0.60/0.80/1.00 五个值，任何"k 越大提升越多"的曲线在小 n 下都是阶梯，不是趋势。

## 🏗️ LLM 裁判的三个已知缺陷

程序判定只能覆盖有标准答案的任务。一旦要评"解释得清不清楚""这个摘要保没保住原意"，就只能请另一个模型来当裁判（LLM-as-Judge）。这套做法在 AlpacaEval、MT-Bench 之后基本成了行业默认，但它的三个缺陷是公开记录在论文里的：

1. **位置偏差（position bias）**：同一对答案换个顺序，裁判可能改判。MT-Bench 论文里就报告过换序后一致率明显掉下来。
2. **自我偏好（self-enhancement bias)**：裁判倾向于给自己（或同族模型）生成的答案打高分。
3. **长度偏差（verbosity bias）**：更长的答案更容易赢，哪怕信息量一样。

这三个都不是"模型太笨"，而是**裁判任务本身没有唯一正确答案**：一个 1-10 分的刻度，在质量接近时人类专家之间也吵。所以关键问题不是"能不能消除噪声"，而是"噪声底有多大、我的实验效应量有没有超过它"。

## 🔬 实验二：同一份答案，评 6 次

用 DeepSeek 当裁判，一道有明确机制答案的问题（"为什么前缀缓存不改变模型输出"），三份答案分别是：A 完全正确、B 核心概念说错、C 方向对但含夸大表述。配方写死，只改采样温度=1.0，重复 6 次：

| 答案 | 6 次得分 | 均值 | 标准差 | 极差 | 不同取值 |
|---|---|---|---|---|---|
| A 完全正确 | 10,10,10,10,10,10 | 10.00 | 0.00 | 0 | 1 |
| B 核心错误 | 1,1,1,1,2,1 | 1.17 | 0.37 | 1 | 2 |
| C 半对 | 3,2,2,2,3,2 | 2.33 | 0.47 | 1 | 2 |

结论分三层：

- **两端稳定、中间抖动**：满分和几乎零分的答案裁判从不犹豫（A 的标准差是 0.00），但"方向对、细节错"这种最需要判断力的答案，与多数票的一致率只有 **67%**（6 次里 2 次给了 3 分、4 次给了 2 分）。
- **排名是稳的**：6 次里 best 全选 A（100%），错误答案从没被抬到过半对答案——所以**用 LLM 裁判做排序比做打分可靠得多**。
- **温度 0 在这个案例里确实是确定的**：同一提示词跑 3 次，得分向量都是 (10, 2, 1)。注意这只是"相对确定"——MoE 路由和批处理都会引入非确定性，温度 0 不等于比特级复现。

## 🔬 实验三：把质量差距压缩到"接近"，噪声就露出来了

实验二里答案差距太大，裁判几乎不会错，噪声被效应量盖住了。换成三份**质量接近**的答案（都抓住了自回归+prefill 机制，差别只在细节完整度和一句夸大表述），原顺序评 8 次、反转顺序评 4 次：

| 答案 | 原顺序（A,B,C） 8 次 | 均值 | 反转顺序（C,B,A） 4 次 | 均值 | 漂移 |
|---|---|---|---|---|---|
| A 最完整 | 9,8,8,8,9,8,8,8 | 8.25 | 9,9,8,8 | 8.50 | +0.25 |
| B 含糊 | 7,6,6,6,7,6,6,6 | 6.25 | 7,7,7,6 | 6.75 | **+0.50** |
| C 含夸大 | 5,3,4,4,4,3,3,3 | 3.62 | 6,4,5,5 | 5.00 | **+1.38** |

这张表里藏着一个天然的对照组，也是整篇文章最值得记住的一处设计：

- **B 在所有 12 次评分里位置都没变**（一直是中间那个），它的均值却从 6.25 漂到 6.75，**+0.50 分**。这就是纯采样噪声的下限——**位置没变、答案没变，光靠重采样就能差出半分。**
- **C 从第三位挪到了第一位**，均值涨 **+1.38 分**。减去 0.50 的噪声底，**净首位加成约 +0.88 分**。
- 更狠的是极差：C 在 8 次里拿过 3 分，在反转后有 1 次拿过 6 分——**同一个答案，同一个裁判，3 分到 6 分**。而它在 12 次评分中从没被选为 best。

换句话说：在一个质量接近的三选一里，裁判的**排序结论**（A>B>C，12/12 次）是可信的，但**任何单次的绝对分数都不可引用**。如果你拿"新提示词把 C 从 3 分提到 5 分"当成果汇报，你汇报的很可能是位置。

## 💻 可运行的核心代码

上面两个实验共用同一套骨架，跑通版完整脚本在文末。核心就 20 行：

```python
import json, os, urllib.request
from math import comb

BASE = os.environ.get("DEEPSEEK_BASE_URL", "https://api.deepseek.com/v1").rstrip("/")
KEY = os.environ["DEEPSEEK_API_KEY"]

def chat(prompt, temperature=1.0):
    body = {"model": "deepseek-chat",
            "messages": [{"role": "user", "content": prompt}],
            "temperature": temperature, "max_tokens": 200,
            "response_format": {"type": "json_object"}}   # 强制结构化输出，便于统计
    req = urllib.request.Request(f"{BASE}/chat/completions", data=json.dumps(body).encode(),
                                 method="POST",
                                 headers={"Authorization": "Bearer " + KEY,
                                          "Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=60) as resp:
        return json.loads(json.loads(resp.read().decode())["choices"][0]["message"]["content"])

def pass_at_k(n, c, k):
    return 1.0 if n - c < k else 1.0 - comb(n - c, k) / comb(n, k)
```

两个工程细节值得抄走：

- `response_format={"type":"json_object"}` 是让裁判输出可统计的关键（这是第 17 篇结构化输出的直接应用）。没有它，你得从自然语言里正则抠分数，"裁判抖动"里会混进一半解析错误。
- 统计时**先收集原始分数向量，再算均值和标准差**，不要只打印单次结果。上面 B 的 0.50 分噪声底，就是靠"同一个位置跨 12 次评分"才看出来的。

## 💡 落地清单

1. **pass@k 只用 1−C(n−c,k)/C(n,k)**，并且记住 k>n−c 时直接返回 1.0；n 至少 20 起步，否则曲线是阶梯。
2. **排序用裁判，打分不用裁判。** 要用绝对分数就先做标定：同一批样本重复 N 次，报告均值±标准差，而不是单次分数。
3. **位置随机化是必须的，不是优化。** 把候选答案的位置在多次评分中轮转，取平均，可以抵掉约 0.88 分的首位加成；不做轮转的方案，效应量必须超过 1.38 分才值得相信。
4. **留一个位置不变的对照组。** 这次实验里 B 全程待在中间位，才把"噪声底 0.50 分"和"位置加成 0.88 分"分离开。没有对照组的评测报告，无法回答"这 1 分是提升还是抖动"。
5. **温度 0 不等于可复现**，只是把采样噪声压到最小；跨服务批处理的推理引擎仍可能给出不同结果，重要评测要重复跑。

评测这件事最反直觉的地方在于：**它不是模型能力的度量，而是你自己实验方法的度量。** 一个没有噪声底的评测数字，和一个没有误差棒的物理实验一样，不是"精确"，而是"没测"。
