# AI核心概念(24)：LoRA 低秩适配——冻结大模型，只训一个薄薄的增量

> "全量微调的做法是：为了教模型一个新本事，把整个模型复制一份、连同它的优化器状态一起搬进显存。LoRA 问的是另一个问题——如果这次适配只是权重空间里的一小步偏移，为什么要为一个偏移付一整个模型的价钱？"

## 🎯 前提：微调的账单不在算力，在"每个参数都要背三份状态"

前三期聊的都是**推理**侧的开销（KV 缓存、量化、投机解码）。这一期换个方向：训练侧。

训练一个模型时，显存里躺着的东西比推理多得多。以 Adam 为例，每个参数要背：

| 项目 | 精度 | 字节/参数 |
|---|---|---|
| 权重 | FP16 | 2 |
| 梯度 | FP16 | 2 |
| 一阶动量 m | FP32 | 4 |
| 二阶动量 v | FP32 | 4 |
| master 权重 | FP32 | 4 |
| **合计** | | **16** |

一个 7B 模型：权重本身 14 GB，进入训练态直接变成 7B × 16 B ≈ **112 GB**。单张 A100（80 GB）装不下，得上多卡或者 ZeRO 分片。而你只是想让它在某个垂直任务上表现好一点。

**LoRA**（Low-Rank Adaptation，低秩适配）的出发点极其朴素：预训练权重已经学会了这个世界，微调只是让它"偏一下"。如果这个偏移本身没有那么复杂，那我们根本没必要去更新那 70 亿个参数。

## 🔬 假设：适配不是"重写模型"，而是"扭一下"

先把这个假设变成可测量的问题：**全量微调产生的增量 ΔW = W_微调 − W_预训练，到底需要多少个独立方向？**

矩阵的"方向数"就是它的**秩**（rank）。一个 1000×1000 的矩阵最多有 1000 个秩，但如果它的能量集中在前几个方向，它的**有效秩**就很小——这正是 SVD（奇异值分解）告诉我们的：奇异值平方的累计占比 = 这些方向携带了多少"能量"。

我写了个纯 numpy 的玩具网络来量它（不依赖任何框架，CPU 上两分钟）：16 维输入 → 32 维隐藏层（tanh）→ 4 分类，2400 条训练/600 条测试，标签由一个教师网络生成。从随机初始化的"预训练"权重出发，全量微调 3000 步 Adam：

```text
[起点]      test loss=3.0894  acc=0.2417
[全量微调]  test loss=0.8218  acc=0.8717   train acc=1.0000   676 个可训练参数
```

任务学会了。现在对它的两个增量矩阵做 SVD：

| 增量矩阵 | 秩1 | 秩2 | 秩3 | 秩4 | 秩8 | 吃掉50%能量 | 吃掉90%能量 |
|---|---|---|---|---|---|---|---|
| ΔW1 (16×32) | 22.7% | 39.0% | **51.9%** | 63.7% | 85.9% | 需秩 3 | 需秩 10 |
| ΔW2 (32×4) | 44.9% | **78.3%** | 96.3% | 100% | — | 需秩 2 | 需秩 3 |

ΔW1 满秩是 16，但**前 3 个方向就吃掉了超过一半的能量**；ΔW2 满秩 4，前 2 个方向占了 78.3%。也就是说：这次适配真正用到的自由度，远少于矩阵的尺寸。这就是 LoRA 论文里说的 **intrinsic rank（内在秩）**——大模型是过参数化的，它解决问题时并不会把所有维度都用上。

## 🏗️ 形式：ΔW = (α/r)·B·A

既然 ΔW 是低秩的，那就别直接去学 ΔW —— 把它参数化成两个瘦长矩阵的乘积：

```python
W = W0 + (alpha / r) * (B @ A)     # W0 冻结，只训练 A 和 B
# A: (r, d_out)   B: (d_in, r)    r << min(d_in, d_out)
```

参数量从 `d_in × d_out` 变成 `r × (d_in + d_out)`。举原文里的例子：d = 12288、r = 64 时，一个 12288×12288 的投影矩阵有 1.5 亿参数，而它的 LoRA 补丁只有 64×12288×2 ≈ 157 万，**压缩约 96 倍**。

三个必须知道的工程细节：

**1）B 初始化为 0，A 用随机高斯。** 这样训练开始时 `B@A = 0`，模型输出与基座**逐位一致**——不会一上来就把预训练模型带偏。这是 LoRA 训练比直接微调更稳的原因之一。

**2）缩放因子 α/r 不是装饰。** 当你把 r 调大（可供使用的方向变多），每个方向的贡献需要按比例缩小，这样**换 r 时不用重新调学习率**。实践里 α 常取 r 或 2r，等价于缩放 = 1 或 2。

**3）推理时合并（merge）**：把 `B@A` 加回 `W0`，得到一个普通的权重矩阵，推理零额外延迟、零额外显存。适配器只在训练和切换时存在。

```python
def lora_forward(X, W0, b, A, B, alpha, r):
    return X @ (W0 + (alpha / r) * B @ A) + b      # 前向 = 给权重贴一块低秩补丁

# 反向：W0 不接收梯度，只有 A、B 有
# dA = B.T @ gW ,  dB = gW @ A.T
```

## 💻 实测：12% 的参数复现多少收益

把上面那套形式接到同一份数据、同一个基座上，冻结 W0，只训练 A/B（起点 acc 0.2417，全量微调 0.8717，总收益 = 0.630）：

| r | 可训练参数 | 占全量 | test loss | test acc | 收益复现 |
|---|---|---|---|---|---|
| 1 | 84 | 12.4% | 0.9717 | 0.6633 | **67%** |
| 2 | 168 | 24.9% | 0.6211 | 0.7633 | **83%** |
| 4 | 336 | 49.7% | 0.7903 | 0.7800 | 85% |
| 8 | 672 | 99.4% | 2.1998 | 0.8517 | 97% |

读这张表的正确方式是看**边际收益**：r 从 1 到 2，参数量翻倍换来 16 个百分点；从 2 到 4 又是翻倍，只换来 2 个百分点。**大头是第一批方向吃掉的**，这也正是"低秩假设"成立的实证。论文在真模型上的观察一致：把 r 从 8 加到 64，收益提升往往很小。

两个诚实的附带观察：

- **r=8 的 test loss（2.1998）比 r=2（0.6211）更差，但准确率更高。** 参数多了之后它在训练集上过拟合，在错的测试样本上更自信。训练集只有 2400 条，这个现象被放大了——玩具模型上的过拟合趋势不能外推成真模型的结论。
- **LoRA 学到的 ΔW 与全量微调 ΔW 的 Frobenius 相对误差很大**：r=2 时是 257%，而同样秩下对全量 ΔW 做**最优截断 SVD** 的相对误差只有 64.2%。可它照样复现了 83% 的准确率收益。结论很反直觉但很重要：**LoRA 找到的不是"全量微调那一步的近似"，而是另一个能完成任务的低秩解。** 参数空间里解不唯一，把它理解成"对全量微调的压缩"是错的。

最后是 merge 校验（把 `B@A` 加回 W0 之后再算一遍）：

```text
[merge 校验] 分开算 vs 合并后：loss 差 0.00e+00，acc 差 0.00e+00，权重最大元素差 0.00e+00
```

逐位一致，说明推理期合并确实是无损的。

## 🔧 工程实践：一张决策表

| 问题 | 做法 |
|---|---|
| r 怎么选 | 从 4~16 起步；任务越接近基座已有能力，r 可以越小；加秩的边际收益衰减很快 |
| α 怎么设 | 常取 α = r（缩放 1）或 α = 2r（缩放 2）；换 r 不必重调学习率 |
| 挂在哪 | 注意力层的 Wq/Wv 性价比最高；只加这两处即可拿到大部分收益，全挂 MLP 收益递减 |
| 显存还不够 | **QLoRA**：基座 4bit 量化后冻结，LoRA 用 FP16 训练，单卡就能微调 65B 级模型 |
| 多任务 | 一份基座 + 多个几百 MB 的适配器，切任务等于换文件，比存多份全量权重划算得多 |
| 什么时候不该用 | 需要注入大量新知识、换语言、继续预训练时，低秩容量不够——老老实实全量微调或提高秩 |

换算到真实规模（LoRA 论文里的 GPT-3 175B 配置：d = 12288，96 层，只在 Wq/Wv 上挂 r = 64）：

```text
适配器参数 = 96 层 × 2 个投影 × 64 × 12288 = 151.0M = 全量 175B 的 0.086%
适配器存盘 ≈ 302 MB           vs 全量权重 175B × 2B ≈ 350 GB
优化器状态 ≈ 1812 MB          vs 全量需要为 350 GB 权重配 2100 GB 的 Adam 状态
```

## 💡 小结

LoRA 把"微调"这件事从**复制一个模型**变成了**记录一次偏移**，而这次偏移的有效方向数远少于它的维度——这既是过参数化模型留给我们的一笔余量，也是这一期所有数字背后的同一个事实。
