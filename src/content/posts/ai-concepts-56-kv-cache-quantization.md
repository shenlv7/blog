# AI核心概念(56)：KV Cache 量化——K 按通道切、V 按 token 切

> 同一个 KV 缓存，同样的 4 个 bit，只换「scale 按哪个方向算」，注意力输出的相对误差可以差 **3.7 倍**。
>
> 本机纯 numpy，单 head，1024 个 token，6 个数据种子 × 3 个随机 query（n=18），零 GPU、零预训练模型：**per-tensor 0.835、per-channel 0.759、per-token 0.457、KIVI 式（K 按通道 / V 按 token）0.223**。
>
> 更值得记的是 8bit 那一行：**per-tensor 的 8bit（0.316）均值上还不如 KIVI 的 4bit（0.223）**。位宽是钱，粒度是花钱的方式；钱加倍但花错了地方，比钱少花对了还差。
>
> 先把边界钉死：这是**合成数据上的机制实验，不是真实 LLM 的精度实测**。绝对误差 0.22 不能读成「4bit KV 会让模型掉多少分」——真实模型有残差、有分组、有残差窗口，还有 32 层可以互相纠错。这篇文章能给你的是**排序和机制**，不是 loss 曲线。

## 🎯 先把三件容易混的事分开

**权重量化 vs KV 量化**：第 21 篇做的是把 **W**（权重矩阵）压成 INT4，那是一次性的、离线的，压完模型大小就定了。KV 量化压的是**推理时每一层、每个 token 现场算出来的 K 和 V**——它不进权重文件，只在显存里活着，序列越长占得越多（第 22 篇算过：7B / GQA-8 / 32 层，fp16 每 token 128 KiB，32k 上下文就是 4 GiB）。两者互不替代，可以同时开。

**为什么 KV 值得单独量化**：解码阶段每个 step 只算 1 个 token，但要把它和缓存里所有历史 token 做注意力——**瓶颈不是算力，是把整个 KV 缓存从显存搬到 SM 的带宽**。第 22 篇按公开带宽算过：70B、32k 上下文，光读一遍 cache 就要 3.21 ms/步。把 KV 从 16bit 降到 4bit，要搬的字节直接少 4 倍，这是**少花钱还更快**的少数优化之一。

**粒度（granularity）是什么**：对称量化只有一行公式——`x_q = round(x / s) * s`，其中 `s = max|x| / (2^(b-1) - 1)`。真正要选的是**这个 max 在哪个范围内取**：

| 粒度 | scale 的数量 | 一个 scale 管谁 |
|---|---|---|
| per-tensor | 1 | 整个 K 矩阵（1024×64 个元素共用一把尺） |
| per-token | N 个 | 每个 token 那一行的 64 个通道 |
| per-channel | d 个 | 每个通道那一列的 1024 个 token |
| 分组（真实系统） | N·d/G | 行内或列内每 G 个元素一把尺，KIVI 用 G=32 或 128 |

粒度越细，精度越好，但 scale 本身也要存、要读——per-token 的 scale 开销是 `d/32` 个 fp16 per token（d=128 时约 4%），可以忽略；per-element 就没有意义了，因为 scale 会和数据一样大。

**那为什么 K 和 V 要用不同的方向？** 因为两者的离群值长在不同地方。这是 KIVI（Liu 等人，ICML 2024，*A Tuning-Free Asymmetric 2bit Quantization for KV Cache*，arXiv:2402.02750）的核心观察：**K 的少数通道在两个方向上数值都很大，而且跨 token 稳定**（某个通道一旦"爆"，几乎所有 token 在这个通道上都大）；**V 的离群值则集中在少数 token 上**（某几个 token 的整行都大，其它 token 正常）。

这条观察决定了切法：K 里的离群通道如果按 token 取 max，会**把同一行 63 个正常通道一起拖进粗量化的深渊**；V 里的离群 token 如果按通道取 max，会**把同一列 1023 个正常 token 全部碾平**。反过来切，各自只牺牲自己那一小撮。

## 🔬 实验设置，以及我第一版为什么是废的

| 项 | 设置 |
|---|---|
| 规模 | N=1024 token，head_dim=64，单 head，单层 |
| K 结构 | 3 个通道（3/17/40）×6 倍幅度，跨 token 稳定 |
| V 结构 | 3 个 token（0 / 5 / 512）整行 ×60 倍 |
| 量化 | 对称、round-to-nearest、无残差、无分组（G=d） |
| 指标 | 注意力输出的相对 L2 误差 `‖o_q−o‖/‖o‖`、cos、`KL(p‖p_q)` |
| 重复 | 6 个数据种子 × 3 个随机 query = 18 次，报 mean ± std；per-tensor 有重尾，单次值会偏离均值很远 |
| 零假设 | bits=16 时量化是恒等映射，误差必须严格为 0 → 实测 **0.000e+00** |

第一版我写的是：query 也按 6 倍幅度缩放。跑出来四种方案的误差**全是 1.0 左右，cos 甚至是 nan**——看起来像"什么切法都崩"。原因很蠢：logits 被放大到几十，softmax 直接退化成 one-hot（p.max≈1）。这时量化只要让 argmax 翻一个位置，输出就整个换成另一个 token 的 V，而两个随机 V 行几乎不相关，相对误差就饱和在 `√2` 附近。**指标被 argmax 翻转支配了，什么机制都看不见。**

修法是把 query 放回标准正态、离群幅度从 40 倍降到 6 倍，让注意力变成"几百个 token 各出一点力"的形状：p.max=0.0394，**有效 token 数 exp(熵)=259.6**，top5 权重 0.039 / 0.037 / 0.028 / 0.025 / 0.021。这才是我要测的东西。这条坑写在这里，是因为它比结果更容易复现：**任何用 L2 误差评注意力的实验，先打印 p.max 和 exp(熵)，否则你测的是 argmax 稳定性，不是量化误差。**

## 📊 实验A：3.7 倍差距，以及它由两半组成

4bit、真实离群结构：

| 方案 | 相对L2误差 | cos | KL(p‖p_q) |
|---|---|---|---|
| per-tensor | 0.835 ± 0.188 | 0.436 | 3.7e-01 |
| per-channel (K&V) | 0.759 ± 0.247 | 0.556 | 2.8e-02 |
| per-token (K&V) | 0.457 ± 0.200 | 0.903 | 1.1e-01 |
| **KIVI (K通道 / V token)** | **0.223 ± 0.072** | **0.978** | **2.8e-02** |

最好比最差好 3.7 倍。但"KIVI 好"是个结论，不是解释。把 K 和 V 分开量化，才知道这 3.7 倍怎么来的：

不过在拆之前，先看一个均值藏起来的东西。我把 per-tensor 单独跑了 seed 0~11 的单次值：0.63 / 1.00 / 0.74 / 0.64 / 0.63 / 0.98 / 0.94 / **3.46** / 1.00 / 0.69 / 0.85 / 1.01。**有一个种子直接飙到 3.46**，而 18 次均值只有 0.835 ± 0.188。这说明 per-tensor 4bit 不是"稳定地差"，而是**大多数时候差、偶尔彻底改路由**：一旦离群通道把 61 个正常通道压成 0，注意力落点会跳到完全无关的 token 上，输出连方向都不对（相对误差 3.46 意味着 `o_q` 和 `o` 的差距比 `o` 自身还长 2.5 倍，即方向基本反了，不是"稍微偏了一点"）。**均值会骗人，这种重尾只有看单次数值才看得见。**

| 方案 | 只量化 K | 只量化 V |
|---|---|---|
| per-tensor | 0.666 | 0.762 |
| per-token | 0.442 | **0.109** |
| per-channel | **0.190** | 0.751 |
| KIVI | 0.190 | 0.109 |

两半各说一件事：

- **K 这一半：按通道比按 token 好 2.3 倍**（0.190 vs 0.442）。因为按 token 取 max 时，离群通道把整行的尺子撑到 6 倍，剩下 61 个正常通道只剩 1/6 的动态范围；按通道取 max，每个通道各自用满 4bit 的 15 个格子。
- **V 这一半：按 token 比按通道好 6.9 倍**（0.109 vs 0.751）。因为按通道取 max 时，60 倍的那个 token 把整列撑爆。

把 scale 分配记成一句话：**谁在"被 max 覆盖的那个方向"上稳定地大，就在哪个方向分组。**

压成 0 的比例更直观（4bit，seed=7）：

| 张量 / 粒度 | 全部元素被压成 0 | 排除离群通道后 |
|---|---|---|
| K per-token | 40.40% | **42.08%** |
| K per-channel | 19.47% | 19.51% |
| V per-token | 14.69% | - |
| V per-channel | **99.60%** | - |

V 按通道量化，**99.6% 的元素直接变成 0**——不是精度低，是这些数在反量化后被彻底抹掉，只剩那 3 个离群 token 还活着。这和 21 篇里 per-tensor INT8 把 89.74% 的权重压成 0 是同一个病：**一把尺子量所有东西，小东西就没了。**

还有一条我没预料到的：**位宽和粒度不能互相顶替**。8bit 的 per-tensor 是 0.316，4bit 的 KIVI 是 0.223——**多一位，不如切对方向**。原因很朴素：per-tensor 的误差下限由那个 6 倍离群通道决定，加一位只是把粗尺子的刻度变细一倍，而离群通道依然霸占着几乎整个量程。KIVI 从 4bit 到 8bit 是 0.223 → 0.0133（17 倍），per-tensor 从 4bit 到 8bit 只有 0.835 → 0.316（2.6 倍）。**粒度和位宽是正交的两个旋钮，只拧一个会在某个位置撞墙。**

## 🧪 三个对照组：这不是配方，是结构的推论

如果"K 按通道 / V 按 token"是普适真理，那它在任何数据上都该赢。我把结构反过来验证：

| 对照 | per-tensor | per-token | per-channel | KIVI |
|---|---|---|---|---|
| B. 反转：K 逐 token 离群、V 逐通道离群 | 0.744 | **0.212** | 0.327 | 0.296 |
| C. 纯高斯，无离群值 | 0.259 | **0.160** | 0.194 | 0.178 |
| D. 真实结构 + 0 号 token 是 sink | 0.618 | **0.303** | 0.583 | 0.465 |

**B 里排名翻转了**：KIVI 从第一掉到第三，per-token 全量化拿了第一。这说明 KIVI 不是"更好的算法"，而是"对某种数据结构的正确响应"。哪天你的模型 K 的离群变成逐 token，这套 recipe 就该换。

**C 里差距从 3.7 倍压到 1.6 倍**：没有离群值的时候，三种粒度都在同一个量级——**粒度带来的收益，本质上是"离群值税"的减免**，不是凭空涨点。

**D 是我预判错的那个**。我想的是：V 的离群 token 如果同时是 attention sink（p[0]=0.999），输出几乎等于那一个 token 的 V，per-token 的"免费午餐"——"离群 token 权重小所以量坏也不影响输出"——就该消失。结果 KIVI 只从第 1 掉到第 2（0.465 vs per-token 0.303），没崩。

原因想通了：**V[0] 的 scale 是拿 V[0] 自己的 max 算的，它永远是自己那一行里被表示得最好的元素**。按 token 量化牺牲的从来不是离群 token，而是同一行里的其它元素——当 sink 把权重全吸走，那些"其它元素"本来就不重要了。所以 per-token V 在 sink 下依然安全，甚至在 B 那种反转结构下更好。

真正被 sink 打疼的是 **per-channel (K&V)**：0.583。因为按通道分组的代价是让每个通道的尺子由该列最大值决定，而 sink 那一行的 V 是 60 倍——这把尺子对其他 1023 个 token 就是灾难，而 sink 又恰好贡献了几乎所有输出权重，误差全从这条通道进来。

顺带一提，D 的 4 个方案标准差都在 0.2~0.3，比 A 大一个量级。sink 让输出接近单行，单行的量化误差天然方差大——**这种时候看均值排序要打折扣**，我在正文里保留原始 std 就是为了让你能自己判断。

## 🏗️ 真实系统里，这套东西长什么样

KIVI 论文的做法比我这里的玩具多三件东西（我**没有**实测这三件，只按论文口径转述）：

1. **分组**：K 沿通道每 32/128 个元素一组，V 沿 token 每 32/128 个一组。纯 per-channel 在 d=128 时只有 128 个 scale，分组能在 scale 开销和精度之间取中间点。
2. **残差窗口（residual window）**：最近 128 个 token 的 KV 保留全精度。刚生成的 KV 最"热"，也被注意力最频繁地读，量化它们最亏。
3. **2bit 目标**：KIVI 报的是 2bit 下精度接近 fp16、显存和批大小有数量级收益。我这里 2bit 全线崩溃（最好的 0.906，最差的 1.53），**这是玩具和真实系统的最大差距**——真实模型有残差流兜底、有 32 层冗余、有分组和残差窗口，我的单 head 什么都没有。所以别拿我的 2bit 数字去否定 2bit KV，它只能说明：**在没有任何保护的单 head 上，2bit 的信息量不够。**

显存这本账（7B 规模，32 层 / 8 个 KV 头 / head_dim 128）：

| 上下文 | fp16 | INT8 | INT4 | INT2 |
|---|---|---|---|---|
| 8k | 1.00 GiB | 0.50 GiB | 0.25 GiB | 0.12 GiB |
| 32k | 4.00 GiB | 2.00 GiB | 1.00 GiB | 0.50 GiB |
| 128k | 16.00 GiB | 8.00 GiB | 4.00 GiB | 2.00 GiB |

注意这张表里**没有 scale 的开销**。按 4bit + 分组 G=32 算，每个 group 多一个 fp16 scale，等于每 32 个元素多 16 bit，**真实压缩比是 4bit→4.5bit 左右，不是严格的 4 倍**。写容量规划的时候，把这个零头算进去，比事后发现 OOM 便宜。

至于速度：解码是带宽瓶颈，KV 从 16bit 到 4bit，理论上是每一步少搬 3/4 的字节。但**反量化本身要花指令**，而且 KIVI 那类方案是在 kernel 里边搬边反量化，实际加速取决于你的 kernel 有没有把 dequant 藏进内存延迟里。这一层我没有 GPU，不猜数。

## 💻 可运行的最小复现

保存为 `kv_quant.py`，`python3 kv_quant.py` 直接跑（只需要 numpy，1 秒内出结果）：

```python
import numpy as np

def quant(x, bits, axis):
    """对称量化。axis=None: per-tensor; 1: per-token; 0: per-channel"""
    if bits >= 16:
        return x.copy()
    qmax = 2 ** (bits - 1) - 1
    amax = np.abs(x).max(axis=axis, keepdims=True)
    s = np.maximum(amax, 1e-12) / qmax
    return np.clip(np.round(x / s), -qmax, qmax) * s

def attn(K, V, q):
    s = K @ q / np.sqrt(K.shape[1])
    s = s - s.max()
    p = np.exp(s); p /= p.sum()
    return p, p @ V

N, d, seed = 1024, 64, 7
rng = np.random.default_rng(seed)
K, V = rng.normal(size=(N, d)), rng.normal(size=(N, d))
K[:, [3, 17, 40]] *= 6.0      # K：少数通道跨 token 稳定放大
V[[0, 5, N // 2]] *= 60.0     # V：少数 token 整行放大
q = rng.normal(size=d)

p0, o0 = attn(K, V, q)
print(f"p.max={p0.max():.4f}  有效token数={np.exp(-(p0*np.log(p0+1e-30)).sum()):.1f}")

for name, (ka, va) in {"per-tensor": (None, None),
                       "per-token": (1, 1),
                       "per-channel": (0, 0),
                       "KIVI": (0, 1)}.items():   # K按通道 / V按token
    _, o1 = attn(quant(K, 4, ka), quant(V, 4, va), q)
    print(f"{name:12s} rel_err={np.linalg.norm(o1-o0)/np.linalg.norm(o0):.4f}")
```

跑出来应当看到 `p.max=0.0394`、有效 token 数 259.6，然后是 `per-tensor 3.4554 / per-token 0.4310 / per-channel 0.5941 / KIVI 0.3145`。

注意：这段是**单次运行**（seed=7），数值和上面 n=18 的均值表不同——排序一致，绝对值会跳，**per-tensor 跳得最凶（均值 0.835，这次 3.46）**。想看稳定的均值就把 seed 循环起来，别拿单次数字下结论。

## 💡 结论：能带走的四句

1. **粒度不是超参，是数据结构的下游变量。** 先画一张「离群值在哪个方向稳定」的图（per-channel 的 max 分布 vs per-token 的 max 分布），再决定分组方向。反过来做，就是在赌。
2. **位宽和粒度正交，别只用加位宽解决问题。** 8bit per-tensor 输给 4bit KIVI，这是最便宜的一个反例。
3. **评估任何 KV 相关的近似，先看注意力的形状。** p.max 接近 1 的时候，L2 误差测的是 argmax 稳不稳，不是精度。这一条能救掉一整个下午。
4. **真实系统的收益里，有一半不在算法里**，在残差窗口、分组、kernel 融合这些工程细节上。KIVI 的 2bit 能跑，靠的不是 2bit 本身，是那 128 个全精度 token 的缓冲。

下一篇大概率是 **MoE 的路由坍塌（routing collapse）** 或者 **推测解码的接受率上界**——两个都能在本机用纯 numpy 做出可复现的数字。
