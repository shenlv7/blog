> 双塔检索训练里，batch 大小被当成"负样本数量"的同义词：B=512 就是 512 个负样本，免费、不用挖、不用标。这个等价关系有个漏口——**批内和自己同主题、却不是自己正样本的文档**。
> 在 240 个主题的合成语料上，B=512 的一批里每个查询平均带进 **1.86 个**这样的文档。它们只占一批条目的 **0.36%**，却吃掉 **19.7%** 的 softmax 分母权重。
> 把采样改成"20 个热门主题占七成"（同主题条目每步从 954 条涨到 **6966** 条），留出集 R@1 从 **0.258** 掉到 **0.204**——比 B=32 的 **0.223** 还低。
> 而把这些假负样本从分母里摘掉（oracle 上界，生产中拿不到这份标签）只补回 **0.7** 个点。伤害几乎全部来自**采样分布**本身：批内同主题近邻把更新预算吸走，摘掉几条错样本救不回来。

读这篇要会：softmax 交叉熵 / 双塔（bi-encoder）如何用向量内积打分 / 矩阵乘法里 batch 维度是怎么来的。

## 🎯 负样本要的是"不同"，不是"多"

检索模型的标准训练配方是一句话：查询和文档各过一个编码器，正样本对的内积要高，和一批里其他文档的内积要低。那些"其他文档"就是负样本，因为同在一批里，不用额外采样、不用额外前向，白送。

于是 B 越大越好的论断流行起来：B=512 白得 511 个负样本，B=8192 白得 8191 个。SimCLR 把 batch 开到 4096、CLIP 开到 32768，确实是靠这条路把对比学习拉起来的。

但免费的东西有前提：**同一批里的其他样本，在语义上必须真的不相关**。自然图片构成的 batch 里这个前提基本成立——两张随机抽取的照片，主题撞车的概率很低。检索语料不成立：查询流量本来就集中，一批 512 条里可能有一大簇在问同一类事。这时候批内负样本里混进的不是"不相关的文档"，而是"其实该被召回的文档"，只是它的搭档不是当前这条查询。

数量上它们微不足道（0.36%），权重上它们是主角（19.7%）。这就是下面所有数字的来源。

## 🔬 分母里混进了正样本

InfoNCE 对一批 $B$ 个正样本对的标准写法：

```
L = −(1/B) · Σ_i log [ exp(s(q_i, d_i)/τ) / Σ_{j=1..B} exp(s(q_i, d_j)/τ) ]
s(q, d) = cos(f(q), g(d))          τ = 0.07
```

第 $i$ 条查询的分母把整批文档都加了一遍，只有 $j=i$ 那项是正样本。若 $j \ne i$ 但 $d_j$ 和 $q_i$ 讲的是同一件事，它就被当成负样本推远——业内叫**假负样本**（false negative）。

批内同主题条目的期望数量可以直接算出来。语料有 $K$ 个主题、每个主题 $m$ 条查询、总查询数 $N = Km$，则每条查询在随机抽取的 $B-1$ 个同伴里撞到同主题的期望是

```
E[同主题条目] = (B−1) · (m−1)/(N−1)
B=512, m=8, N=1920:  511 × 7/1919 = 1.864
```

实测每步 954.59 条除以 512 条查询 = **1.865**，和公式一致。B=128 时这个量是 0.463（实测 59.44/128 = 0.464），B=32 时是 0.112（实测 3.57/32 = 0.112）。**批扩大 16 倍，撞车条数扩大 16 倍**——它跟负样本数量同速增长。

真正值得看的是权重。同一批 512 条里，假负样本占条目 1.865/511 = **0.36%**，实测吃掉 softmax 分母的 **19.7%**，密度是随机样本的 **54 倍**。原因很直接：同主题文档的相似度天然高于异主题文档，而 $\tau = 0.07$ 把 $\exp(\Delta s / \tau)$ 的差距放大了一个数量级——温度越低，这些"长得像负样本的正样本"越霸占分母。

所以"511 个负样本"这个说法要打折：其中 20% 的梯度预算花在了把相关文档推开上。

## 🏗️ 六组对照：批大了涨 3.5 个点，主题集中跌 5.4 个点

合成语料 240 个主题 × 6 篇文档 = 1440 篇；训练查询 1920 条，留出查询 960 条。编码器是 64→64→24 的两层 MLP（ReLU + L2 归一化），Adam 2000 步，全批同时当查询侧和文档侧用。下表是 6 个 arm，全部单种子 seed=1；"同主题/步"是批内与查询同主题、却不是它正样本的条目总数（每步平均）：

| arm | 负样本/步 | 同主题/步 | loss | R@1 | R@10 |
|---|---|---|---|---|---|
| B=32 | 31 | 3.57 | 1.201 | 0.223 | 0.644 |
| B=128 | 127 | 59.44 | 1.898 | 0.248 | 0.635 |
| B=512 | 511 | 954.59 | 2.805 | 0.258 | 0.627 |
| B=512，屏蔽假负样本（oracle） | 511 | 954.59 | 2.469 | 0.259 | 0.626 |
| B=512，热点主题占七成 | 511 | 6966.08 | 2.998 | 0.204 | 0.580 |
| B=512，热点占七成 + 屏蔽 | 511 | 6966.08 | 0.941 | 0.211 | 0.589 |

先看前两行：负样本从 31 条涨到 511 条（16 倍），R@1 只从 **0.223 涨到 0.258**（+3.5 个点）。这个方向是对的，幅度比"负样本越多越好"的直觉小得多——128 到 512 这四倍，只值 1 个点。

第四行是全篇最关键的对照：**同一个 batch 配置，把假负样本从分母里摘掉，R@1 只从 0.258 到 0.259**（+0.1 点，在噪声里）。也就是说"把相关文档当负样本推远"这件事，在这个规模的均匀采样下几乎不构成伤害。开头那个 19.7% 的分母权重没有转化成 19.7% 的准确率损失——梯度被稀释在一整批里，方向错了但幅度小。

第五行才是真问题。同样的 B=512、同样的步数，只把采样分布改成"20 个热门主题承接七成查询"（偏斜采样允许同一查询重复出现），同主题条目每步从 954 涨到 6966 条（7.3 倍），R@1 掉到 **0.204**，比 B=32 的 0.223 还低 **1.9** 个点。R@10 从 0.627 掉到 0.580。

换种子复跑，方向稳定：B=512 均匀采样 seed=2 / seed=3 分别是 **0.231 / 0.233**，偏斜采样是 **0.203 / 0.190**，每次掉 2.8~4.3 个点。

第六行是诊断的关键：同样偏斜的批里再摘掉假负样本，R@1 只回来 **0.7** 个点（0.204→0.211）。如果伤害来自"把这 13.6 条相关文档推错了方向"，摘掉它们应该大幅回血——但没有。所以掉分的主因不是那几条错样本，而是**采样分布本身**：偏斜采样下每一条查询的负样本都由同主题近邻主导，7.3 倍的假负样本意味着热门主题的查询贡献了七成的更新量，模型在 20 多个热门主题的内部区分上被反复打磨，剩下 220 个主题的相对位置只被顺带推到。留出集是均匀采样的，于是掉分。

这一点和均匀采样下的表现对得上：均匀批里屏蔽假负样本只值 0.1 个点。也就是说，假负样本的**数量**不是主变量，批的**主题构成**才是——19.7% 的分母权重听起来吓人，真正致命的是"这一批教模型区分的那 500 对，有多少来自同一类事"。

还有一处必须点出来：**loss 这一列不能横着比**。屏蔽假负样本把最难的负样本拿走了，loss 从 2.805 降到 2.469，召回没变；偏斜+屏蔽那行 loss 只有 **0.941**，是全场最低，召回却是倒数第二（0.211，低于均匀采样的 0.258）。InfoNCE 的 loss 是"批内相对排序"的度量，分母一改就没有可比性——调 batch 大小时盯 loss 会得到完全相反的结论。

## 💻 五十行把两个诊断量算出来

真正需要的只有两块：批内同主题条目的计数，和这批的分母权重占比。前者在训练循环里顺手累加，后者训完拿模型跑一批就够。

```python
def fn_mass(P, B=512, seed=99):
    """同一批 B 条里，与查询同主题（本该是正样本）的文档吃掉了多少分母权重"""
    r = np.random.default_rng(seed)
    idx = r.choice(len(Q), B, replace=False)
    didx = Qy[idx] * PER_DOC + r.integers(0, PER_DOC, size=B)
    S = enc(P, Q[idx]) @ enc(P, D[didx]).T / TAU
    Pm = np.exp(S - S.max(1, keepdims=True)); Pm /= Pm.sum(1, keepdims=True)
    bad = (Qy[idx][:, None] == Dy[didx][None, :]) & ~np.eye(B, dtype=bool)
    return float(Pm[bad].sum() / len(idx))

# 训练循环里，算完 S 之后加一行
fn_pairs += ((Qy[idx][:, None] == Dy[didx][None, :]) & ~np.eye(B, dtype=bool)).sum()

if mask_same:      # oracle 上界：把假负样本从分母里摘掉，保留对角线上的正样本
    bad = (Qy[idx][:, None] == Dy[didx][None, :]) & ~np.eye(B, dtype=bool)
    S = np.where(bad, -1e4, S)
```

那个 `-1e4` 不是随便取的：它把被屏蔽项在 softmax 里的权重压到 $e^{-1e4 \cdot 0.07} \approx 0$。屏蔽表要把对角线排除在外——如果连正样本一起屏蔽，分子恒为 0，`-log(1e-12 + ε)` 会给出 27.6 这个"最大可能"的 loss，同时梯度信号一起消失（正样本和负样本的分数差恒为 0）。

```
B=32                              31      3.57  1.201  0.223  0.644
B=128                            127     59.44  1.898  0.248  0.635
B=512                            511    954.59  2.805  0.258  0.627
B=512 屏蔽假负样本                     511    954.59  2.469  0.259  0.626
B=512 热点集中                       511   6966.08  2.998  0.204  0.580
B=512 热点集中+屏蔽                    511   6966.08  0.941  0.211  0.589

```

## 💡 三条判据

**一、量负样本的有效性，量"每批有多少条同主题近邻"，不是 batch size。** 上面的表里，偏斜批每查询 13.6 条同主题条目、均匀批 1.86 条，而 recall 差 5.4 个点；这个比值可以直接在训练日志里逐批统计（有主题标签或聚类 id 就能算），比盯着 batch size 有用。工程上可落地的做法是**分层采样**：把批切块，每块从一个主题簇里取，块与块之间换主题。批内靠底层矩阵乘法拿负样本，主题多样性靠采样器保证，两者不冲突。

**二、显存不够时，缩小 batch 和缩小 micro-batch 是两件事。** GradCache（Gao 等，2021）的做法是把一个大 batch 拆成若干 micro-batch 分别算特征并缓存，再在特征层面做全 batch 的对比损失——负样本数量按大 batch 算，显存按 micro-batch 算。而梯度累积（accumulate steps）只是把小 batch 的梯度加了几次，**负样本数一点没变**，这两者在检索训练里的效果完全不同，别混着调。

**三、难负样本要先过一道同主题过滤，否则等于手工制造假负样本。** DPR（Karpukhin 等，EMNLP 2020）用 BM25 挖难负样本、同时用批内负样本，两者相加才有稳定收益——BM25 挖出来的高频词重合文档里，很有一部分是真正相关但没被标进训练集的。工业上的折中是拿一个 cross-encoder 给候选对打相关性分，高分的不进负样本集合。同理，"去噪对比学习"（Chuang 等，NeurIPS 2020）给的就是一套在**没有干净标签**时估计假负样本比例、并在损失里扣掉它的方法。

**这些数字的边界**：240 个主题、主题内线性可分、每个主题 6 篇文档、单一种子跑 2000 步、六个 arm 只改采样和屏蔽两件事。真实语料是长尾的，热门主题的集中度可能远高于我这里的"七成占 20 主题"，也可能因为主题粒度更细而好得多；真实模型的编码器是非线性的，同主题文档的相似度分布比合成数据更宽。可迁移的是三条定性结论：批内负样本数量与假负样本数量同速增长、假负样本占条目比例极小但占分母权重极大、以及批的**主题构成**比假负样本条数更决定召回。本段为合成数据上的离线复现，不是真实模型的训练实测。
