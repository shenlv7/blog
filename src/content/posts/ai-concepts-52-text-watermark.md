# AI核心概念(52)：生成式文本水印——把词表随机涂绿一半，z 分数就自己长出来了

> 这一篇只回答一个很窄的问题：**不改一个权重、不重训一次模型，只在采样那一步动一次手脚，能不能让一段文本自己带上可检验的统计标记？**
>
> 能。做法朴素得有点过分：把词表随机切成绿、红两份，采样时给绿词的概率加一个偏置 δ。检测方拿到文本后重放一遍哈希，数绿词比例，算 z 分数。我的玩具生成器上，δ=2.0 时绿词占比 0.6837、z 均值 5.197、40 篇里 34 篇被判出；δ=4.0 时 z=8.333、**40/40 全中**，代价是 PPL 从 3.138 涨到 3.748。
>
> 第二个数字我必须写在最前面，因为它比成绩重要：**我最初版本的 z 分数是错的。** 无水印文本（δ=0）的 z 均值不是 0，而是 −1.195；400 篇实测均值 −1.1395、标准差 0.9838。这不是水印在起作用，是我的绿名单播种方式有系统偏差。把种子上下文从 1 个 token 加到 2–4 个，偏置收敛到 −0.08 ∼ +0.29，同时检出率从 0.85 升到 1.00。**根因是我的词表只有 357 个字符**——这条如果不查出来，后面所有「z>4 即判定」的结论都是空中楼阁。
>
> 边界先钉死：本文全部是**本机 CPU 上的模拟生成器实测**——生成器是字符级 3-gram（语料 963 字，词表 V=357，加 0.35 退避平滑），**不是任何真实 LLM**，没有 GPU、没有真实权重、没有人类文本样本。凡涉及真实系统（Gemini 的 SynthID-Text、Kirchenbauer 等人的方案）的结论，我只标明公开出处，不冒充我测过。

## 🎯 术语与出处对齐

四件事先对齐，后面所有数字都按这个读。

**生成式水印（generative watermarking）**：在模型采样的那一刻改变下一个 token 的概率分布，使输出带上统计信号。与「编辑式水印」（生成后再同义替换、插入不可见字符）和「数据驱动水印」（训练时植入触发短语）并列——后两类要么会留下可见痕迹，要么只对特定触发提示有效，这是公开文献里的分类。

**绿名单（green list）**：每个生成位置，用此前若干 token 的哈希做种子，伪随机地从词表里选出比例为 γ 的一个子集。哈希是确定性的，所以检测方能复现同一套绿名单。

**偏置 δ**：采样时给绿名单内 token 的 logit 加上 δ。δ 越大绿词越多、信号越强，文本偏离模型本意也越多。

**z 分数**：统计一篇文章里绿词数 |s|_G，与零假设（绿词比例恰为 γ）下的期望 γT 比较：

z = (|s|_G − γT) / √(T·γ·(1−γ))

零假设下近似服从标准正态，阈值取 4，单侧理论误报率 0.5·erfc(4/√2) = **3.167×10⁻⁵**。

**公开出处**（我没复现，只引文献）：Kirchenbauer 等人的绿名单方案在 ICML 2023 提出；Google DeepMind 的 SynthID-Text 发表于 *Nature* 634, 818–823 (2024)，DOI 10.1038/s41586-024-08025-4，论文自述其「只改变采样流程、不碰训练、检测不需要底层模型」，并已用于 Gemini 的输出标注，还用近 2000 万条真实回复的人类反馈评估了文本质量。**这两条是我读论文得到的，不是我测出来的。**

## 🔬 实验设置（以及它为什么不算 LLM 实测）

- **生成器**：在 963 字自写中文语料上训练字符级 3-gram，退避平滑 α=0.35，温度 1.0，按完整分布采样。它给出的 PPL 约 3.14——意思是「下一步平均有 3 个合理字符」，比真实 LLM 尖峰得多。
- **绿名单**：`blake2b(上下文)` 播种 → `shuffle(词表)` → 取前 γV 个。默认 γ=0.5。
- **检测**：按同一规则重放全文，逐位判绿红，按上式算 z。
- **质量代价**：把生成文本丢回**未加偏置**的模型，算每 token 平均对数似然。这是「文本有多不像模型自己想说的话」的直接度量。

一句话说清边界：**水印机制只依赖采样接口，跟生成器是什么无关**，所以机制层面的结论（偏置→信号、长度→检出、改写→衰减）可以迁移；但**绝对数值完全不能迁移**——357 个字符的词表和 10 万 token 的词表不是一回事，这一点下面实验 F 会直接给出证据。

## 📊 实验A：偏置 δ 的收益曲线（每档 40 篇 × 200 token，γ=0.5）

| δ | z 均值 | z 标准差 | 检出率(z>4) | 绿词占比 | 未偏置模型均 logp | PPL |
|---|---|---|---|---|---|---|
| 0.0 | −1.195 | 1.148 | 0.00 | 0.4577 | −1.1437 | 3.138 |
| 0.5 | 0.739 | 0.903 | 0.00 | 0.5261 | −1.1347 | 3.110 |
| 1.0 | 2.323 | 1.097 | 0.05 | 0.5821 | −1.1789 | 3.251 |
| 2.0 | 5.197 | 1.033 | 0.85 | 0.6837 | −1.2229 | 3.397 |
| 4.0 | 8.333 | 0.959 | 1.00 | 0.7946 | −1.3212 | 3.748 |

把质量代价单独拉出来看（相对 δ=0 基准，基准均 logp = −1.143738）：

- δ=0.5：**−0.79%**（logp 反而变好）
- δ=1.0：+3.08%
- δ=2.0：+6.92%
- δ=4.0：+15.51%

三条件读数：

1. **δ=0.5 几乎没有水印能力。** z 均值 0.739，40 篇一篇都判不出来，绿词占比从 0.4577 只爬到 0.5261。偏置太小，被采样的随机性直接吞掉。
2. **δ=2.0 是第一个可用档。** z=5.197、检出率 0.85、绿词 0.6837、质量代价 6.92%。
3. **δ=4.0 用 19.4% 的 PPL 换 100% 检出率。** 这笔账划不划算，取决于场景——平台批量标注能接受，要求文本自然度的场景不能。

**关于那个 −0.79%：它是噪声，不是「加水印让文本更好」。** δ=0.5 的真实效应应该是一个很小的正损失，我这里录到负值，说明 40 篇 × 200 token 的分辨力不足以分辨小于 1% 的质量差异。把它当成「δ≤0.5 的质量代价在测量误差以内」来读才是对的——**我宁可报这个噪声，也不愿意在表格里悄悄抹掉它。**

## 📊 实验B：假阳性（400 篇无水印文本 × 200 token）

- z 均值 = **−1.1395**，标准差 = **0.9838**
- z > 4 的篇数：**0 / 400**（比例 0.00000）
- z < −4 的篇数：**1 / 400**（比例 0.00250）
- 标准正态理论值：z>4 单侧 = 3.167×10⁻⁵，400 篇的期望命中数 = **0.0127 篇**

两条读数，一条让人安心，一条不让人安心。

安心的：z>4 一次都没出现。但经不起推敲——期望值只有 0.0127，测不出来是**应该的**，400 篇根本没有资格验证 3×10⁻⁵ 这个量级。**说「假阳性为零」是话说过头了，正确说法是「在这个样本量下无法测出」。**

不安心的：标准差 0.9838 看着正常，可 z<−4 出现了 1 次（0.25%），而正态理论只给 0.0032%。**负方向的尾巴比正态厚得多**，加上均值 −1.14 的偏移，说明这个 z 的分布根本不是标准正态。这不是水印的锅，是实验F要解剖的那个播种偏差。

## ⚠️ 实验F：为什么无水印文本的 z 不是 0（本篇最重要的一段）

上表 δ=0 的绿词占比是 0.4577，理论值 0.5；z 均值是 −1.195，理论值 0。**两个 −1 级别的系统性偏移同时出现**，说明不是随机波动。

我的第一反应是「采样方差大」，但 400 篇的 z 标准差是 0.9838，均值偏了 −1.14——**偏了整整一个标准差**，这不是样本量问题。于是做了一组对照：把绿名单的哈希种子从「前 1 个 token」改成「前 h 个 token」，h = 1,2,3,4，各测 100 篇 δ=0 与 40 篇 δ=2.0。

| 种子上下文 h | δ=0 z 均值 | z 标准差 | δ=2 z 均值 | 检出率 | 绿词占比 | 每篇唯一上下文数 |
|---|---|---|---|---|---|---|
| 1 | −1.0946 | 0.9386 | 5.2008 | 0.85 | 0.6839 | 121.4 |
| 2 | −0.0806 | 0.9277 | 5.7099 | **1.00** | 0.7019 | 171.2 |
| 3 | +0.2927 | 1.1950 | **6.3640** | **1.00** | 0.7250 | 187.2 |
| 4 | −0.1527 | 1.0645 | 5.5154 | 0.97 | 0.6950 | 194.0 |

**结论很干净**：h=1 时偏置 −1.09，h≥2 时收进 ±0.3 之内；同时 δ=2 的检出率从 0.85 升到 1.00，z 均值从 5.20 升到最高 6.36。**也就是说，我原本的「水印没被检出」有相当一部分不是因为偏置不够，而是因为 z 的基准线本身是歪的。**

根因（我的解释，对照数据支持）：

- 绿名单掩码是 `blake2b(前一个 token)` 的**确定性**函数。词表只有 357 个字符，能作为「前一个 token」的值最多 357 种；而字符级 3-gram 模型总是围着少数高频字对打转，200 个 token 里只访问到 **121 个不同上下文**（表格最后一列）。
- 于是「这个上下文里，模型最想生成的那个字，落在绿名单里吗」本质上是一枚**只在上下文首次出现时抛一次的硬币**。同一枚硬币被反复累加，偏差不会随 token 数被平均掉。
- 有效样本量是**不同上下文的个数（121），不是 token 数（200）**。z 的公式假设每个 token 独立，这个假设在小词表下被违反。
- 同一个机制也解释了实验B的负尾：偏置是系统性的，不只是方差大。
- 附加证据：文章末尾那段最小可跑代码把语料砍到 233 字、词表只剩 **V=133** 时，即使 h=2，δ=0 的 z 均值又回到 **−1.142**。**词表越小，这个偏差越重。**（对照：主实验 V=357、h=2 时是 −0.081。）

真实系统里这一条几乎自动消失：LLM 词表是 10⁵ 量级，且掩码通常由前 1–4 个 token 的哈希决定、上下文几乎不重复，每个 token 拿到的是一次独立抛币。但这也给出一条**给复现者的警告**：在小词表上跑水印实验，先测 δ=0 的 z 均值，它必须是 0；否则你测到的每一个「检出率」都掺着基准线偏移。**这一步我一开始没做，是这次实验里最值钱的教训。**

## 📊 实验C：长度决定一切（δ=2.0）

| 文本长度 T | z 均值 | 检出率 |
|---|---|---|
| 25 | 1.520 | 0.00 |
| 50 | 2.333 | 0.00 |
| 100 | 3.525 | 0.30 |
| 200 | 5.194 | 0.95 |
| 400 | 7.380 | 1.00 |

z 大致按 √T 增长（T 从 25 到 400 涨 16 倍，√16=4，z 从 1.52 涨到 7.38 是 4.86 倍，比 4 略高，因为基准线的 −1.14 偏移在短文本上占比更大——T=25 时那条公式预测 (5.19+1.14)/√200·√25−1.14 = 1.10，实测 1.52）。

工程含义很直接：**水印天生不适合短文本。** 一条 30 字的回复，z 期望只有 1.5 左右，阈值 4 根本够不着。想要判出一条短消息，只能加大 δ（更伤质量）或换更强的方案——这也是 SynthID-Text 那篇论文要引入 Tournament sampling 之类新采样算法的原因之一（这是文献结论，我没复现）。

## 📊 实验D：改写攻击——水印最脆弱的地方（δ=2.0，T=200，各 60 篇）

| 操作 | 比例 | z 均值 | 检出率 |
|---|---|---|---|
| 未改写 | — | 5.190 | 1.00 |
| 随机替换 | 5% | 4.596 | 0.70 |
| 随机替换 | 10% | 4.254 | 0.60 |
| 随机替换 | 30% | 2.381 | 0.05 |
| 随机删除 | 5% | 4.687 | 0.72 |
| 随机删除 | 10% | 4.275 | 0.63 |
| 随机删除 | 30% | 2.810 | 0.13 |
| 相邻对调 | 5% | 4.304 | 0.65 |
| 相邻对调 | 10% | 3.585 | 0.37 |
| 相邻对调 | 30% | 2.161 | 0.05 |

需要说明的是，这里的攻击是**最弱的一种**：随机替换、随机删除、相邻对调，都是我随手写的无脑操作，没有做任何针对性推断。即便如此：

- **5% 的相邻对调就把检出率从 1.00 打到 0.65。** 注意 z 只从 5.190 掉到 4.304，看着还在阈值上，但分布一摊开就有三成样本掉到 4 以下——**均值过线不等于篇篇过线**。
- **30% 的任意操作都能把 z 压到 2.2–2.8**，检出率 ≤0.13。有意思的是删除 30% 反而比替换 30% 更抗打（2.810 vs 2.381），因为删除只减少 token 数、不引入新词，而替换会往绿名单外面塞字符，同时还要按残留上下文重判。
- 我的对调操作会**破坏哈希上下文**（对调后每个位置的前文都变了，检测方重放的绿名单跟着变），所以信息损失比同样比例的替换更大。

正确结论不是我「水印很脆」，而是：**水印的定位不是防篡改，是给无对抗场景提供统计线索**（平台标注、来源审计、批量筛查）。真实对抗下它的价值主要来自攻击成本——想洗掉 z，攻击方必须真的改写一遍，而改写本身会改变文本的其他统计特征。这也和 SynthID-Text 论文把「非失真/失真」做成可配置档位的思路一致。

## 📊 实验E：绿名单比例 γ 的选择（δ=2.0，T=200）

| γ | z 均值 | 实测绿词占比 | 未偏置模型均 logp |
|---|---|---|---|
| 0.10 | 4.402 | 0.1934 | −1.1961 |
| 0.25 | **5.373** | 0.4145 | −1.2268 |
| 0.50 | 5.317 | 0.6880 | −1.2184 |
| 0.75 | 3.682 | 0.8628 | −1.1535 |
| 0.90 | 2.504 | 0.9531 | −1.1357 |

- **γ=0.25 最优（z=5.373）**，和公开文献里常被引用的 γ=1/4 一致；但我是从自己的玩具生成器上扫出来的，**不构成对真实系统的验证**，只能说「在这个设置里也落在 0.25 附近」。
- **γ=0.9 最差（z=2.504）。** 机理清楚：绿名单已经覆盖 90% 的词表，偏置几乎没有「可抬升空间」，实测绿词占比 0.9531 直接饱和。
- **γ=0.1 的 z（4.402）看着不差，但那是绿词占比 0.1934 撑起来的**——零假设只期望 0.1，多出的 0.093 就是全部信号。代价是每次「抛币」的有效信息更少，且在高频字符主导的分布下更容易被单一上下文绑架。
- 还有一条横向读法：γ 从 0.1 到 0.9，未偏置模型的 logp 只从 −1.1961 变到 −1.1357（约 5%）。**γ 对文本质量的影响远小于 δ**（δ 从 0 到 4 让 logp 掉了 15.5%）。这段话可以翻成一句实用的调参建议：**先固定 γ≈0.25，用 δ 去调检出率与质量的天平。**

## 🧭 边界与盲区（必须说清的六条）

1. **生成器不是 LLM。** 字符级 3-gram、963 字语料、V=357。机制结论可迁移，绝对数值不可迁移。
2. **没有真实人类文本。** 我的「假阳性」用的是无水印模型文本，人类文本的字符分布与之不同，假阳性率要重新测。
3. **没有测强对抗。** 只做了随机替换/删除/对调。用另一个 LLM 改写、反向推断绿名单（拿到检测器就能搜种子）、故意在红名单里采样再人工润色，这些都没测，而且很可能有效得多。
4. **没有测采样参数。** 温度扫描、top-k / top-p 截断、以及「绿名单被截断掉」的情况全部略过——而真实系统默认就是带截断的。
5. **没有测多语言、代码、公式、数字串**。这些位置的 token 分布性质完全不同，绿词占比会明显偏离 γ。
6. **质量度量单一。** 我只用了未偏置模型的平均对数似然，没有人类评价、没有下游任务指标。

## 🧩 最小可跑代码（自包含，直接 `python3` 跑）

下面 40 行就是全流程：训 3-gram、按哈希涂绿名单、带偏置采样、重放检测。跑出来的四行是本机真实输出（语料 233 字，V=133）：

```python
import hashlib, math, random
from collections import Counter, defaultdict

corpus = (
    "大模型的输出正在变成一种基础设施谁写的谁改的越来越难分清水印要解决的问题很窄"
    "在一段由模型自己采样的文本里埋进一个统计上可检验的信号使得检测方在没有原始"
    "模型权重没有生成记录的情况下仍然能判断这段文本更可能来自某个特定模型注意是"
    "更可能不是确定水印给出的是统计证据不是指纹这一点决定了它的全部设计做法是在"
    "采样阶段动手脚把词表随机切成绿色和红色两份绿色那一份的概率往上抬一点点抬的"
    "幅度记作偏置切分不是固定的而是由前一个词经过哈希函数生成伪随机数种子来决定"
)
vocab = sorted(set(corpus)); V = len(vocab)
bi, tri = defaultdict(Counter), defaultdict(Counter)
for i in range(1, len(corpus)):
    bi[corpus[i - 1]][corpus[i]] += 1
    if i >= 2:
        tri[corpus[i - 2:i]][corpus[i]] += 1

def dist(ctx):
    d = Counter(tri.get(ctx, Counter()))
    for ch, c in bi.get(ctx[-1], Counter()).items():
        d[ch] += 0.35 * c
    tot = sum(d.values())
    return {ch: c / tot for ch, c in d.items()}

def green(ctx, h=2, gamma=0.5):
    seed = int.from_bytes(hashlib.blake2b(ctx[-h:].encode(), digest_size=8).digest(), "big")
    rng = random.Random(seed); idx = list(range(V)); rng.shuffle(idx)
    return set(vocab[i] for i in idx[:int(gamma * V)])

def generate(T, delta, seed, h=2, gamma=0.5):
    rng = random.Random(seed); out = "模型"
    for _ in range(T):
        p = dist(out[-2:]); g = green(out, h, gamma)
        raw = [(ch, math.log(pr) + (delta if ch in g else 0.0)) for ch, pr in p.items()]
        m = max(v for _, v in raw)
        out += rng.choices([c for c, _ in raw], weights=[math.exp(v - m) for _, v in raw])[0]
    return out

def zscore(txt, h=2, gamma=0.5):
    f = [txt[i] in green(txt[:i], h, gamma) for i in range(2, len(txt))]
    T = len(f); ng = sum(f)
    return (ng - gamma * T) / math.sqrt(T * gamma * (1 - gamma))

for delta in (0.0, 1.0, 2.0, 4.0):
    zs = [zscore(generate(200, delta, seed=1000 + k)) for k in range(40)]
    det = sum(1 for z in zs if z > 4) / len(zs)
    print(f"delta={delta:<4} z均值={sum(zs)/len(zs):6.3f}  检出率={det:.2f}")
```

```
delta=0.0  z均值=-1.142  检出率=0.00
delta=1.0  z均值= 0.746  检出率=0.00
delta=2.0  z均值= 2.623  检出率=0.05
delta=4.0  z均值= 4.356  检出率=0.70
```

注意这段代码里 **δ=0 的 z 均值是 −1.142，不是 0**——因为这 233 字的语料只给出 V=133 个字符的词表，前面实验F描述的「同一枚硬币反复抛」的偏差被放得更大了。把它当反面教材读，比把它当 demo 读更有价值：**先验证零假设，再谈检出率。**

## 一句话收尾

水印不是一个「加密码」的问题，是一个**统计工程**问题：一组互相拉扯的参数（δ、γ、长度、哈希上下文长度）、一条必须自己先证伪的基准线、以及一个关于「它能防谁」的诚实答案——**它防不了想改的人，但能让不改的人被认出来。**
