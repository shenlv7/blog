# AI核心概念(43)：Attention Sink —— 那 4 个没人读的 token，凭什么拿走一半的注意力

> 如果你拆开一个 LLM 的注意力矩阵，会看到一件很反直觉的事：**大量注意力权重压在第一个 token 上，即使那个 token 只是一句无意义的开场白。** 直觉会告诉你去问「第一个 token 携带了什么信息」——但答案恰恰相反：它什么信息都不携带，这正是它被选中的原因。Softmax 是一个必须把 1.0 花光的函数。当一个 head 在某一步「没什么想看的」时，它也得把概率质量倒进某个槽里；它的解决方式是训练出一个语义上空的槽位，在需要放空时把质量全倒进去。
>
> 这不是一个有趣的怪癖，它是三个工程领域的共同地基：流式推理（StreamingLLM 靠保留 4 个初始 token 把窗口外推）、KV cache 淘汰策略（谁不能被逐出）、以及量化（为什么激活里会冒出比中位数大四个数量级的 outlier）。
>
> 下面三段全部是**本机离散模拟**（**不是 GPU 实测、不是真模型推理**，边界后面单独写清）：扫 sink 偏置、滑动窗口的逐出对照、把 sink 推到极端看 head 怎么变成常数。数字都来自脚本 `43-attention-sink.py` 的真实运行。

## 🎯 先把术语和出处对齐

- **attention sink（注意力汇）**：自回归 LM 会把显著注意力分给**第一个 token**，哪怕它语义上不重要。这个现象由 Xiao、Tian、Chen、Han、Lewis 在 *Efficient Streaming Language Models with Attention Sinks*（arXiv:2309.17453，v1 2023-09-29，v4 2024-04-07，ICLR 2024）里命名并系统化。摘要里的原话：窗口注意力「在文本长度超过 cache 大小时会失败」，而**保留初始 token 的 KV 就能大幅恢复窗口注意力的性能**——由此得到 StreamingLLM，让用有限长度窗口训练的模型无微调外推到 400 万 token 以上。
- **它为什么存在**：同一篇摘要给了机制线索——sink 来自「**即使初始 token 语义上不重要，也会收到很强的注意力分数**」。而 Gu、Pang 等 *When Attention Sink Emerges in Language Models: An Empirical View*（arXiv:2410.10781，2024-10-14）把这个机制说得更明确：sink 在预训练中**涌现**（需要充分的数据与有效优化），位置与损失函数、数据分布高度相关；它「更像 key 上的偏置，用来存多余的注意力分数，可以是无信息的、**不贡献 value 计算**」。而且他们把 softmax 换成**不带归一化的 sigmoid attention** 之后，直到 1B 参数都没有出现 sink——也就是说，「必须归一化」这件事本身就是成因。
- **sink = 什么都不做的槽位**：Bondarenko、Nagel、Blankevoort 在 *Quantizable Transformers: Removing Outliers by Helping Attention Heads Do Nothing*（arXiv:2306.12929，Qualcomm AI Research，2023-06-22）里从量化角度独立走到了同一个结论——激活里的强 outlier 与某些 head 想学的「**no-op / 部分更新残差**」行为直接相关；为了在注意力矩阵里拿到**精确的 0**（即完全不更新），softmax 的输入会在训练中被越推越大，于是别处就长出 outlier。他们给的解法是 clipped softmax 与 gated attention。
- **同一个现象在视觉里叫 register**：Darcet 等（FAIR）*Vision Transformers Need Registers*（arXiv:2309.16588，2023-09-26）发现 ViT 特征图里有高范数 token 出现在低信息背景区，被「挪作内部计算用」；他们直接**加一批 register token 给这个用途**，attention map 立刻变干净。
- **sink 与 massive activation 是同一件事的两面**：Sun、Chen、Kolter、Liu *Massive Activations in Large Language Models*（arXiv:2402.17762，COLM 2024）观察到极少数激活比中位数大 4 个数量级以上（LLaMA2-70B 里绝对值可超 15000），**取值几乎与输入无关，充当不可或缺的偏置项**，并且导致注意力概率向对应 token 集中。他们给的例子是：LLaMA2-7B 里这些激活出现在两个固定特征维度（1415、2533）、以及两类 token——起始 token 和第一个句号/换行。

一句话总结这五篇：**sink 不是一个 bug，是 softmax 归一化 + 训练压力共同长出来的一个「放空阀」；它用「无语义」换来了「可预测」。**

## 🔬 实验 1：只加一个偏置，分布就从「检索」变成「偏置」

设置：N=512 个位置、d=16 维 value 向量、400 条随机查询。语义 logits 是 `3·N(0,1)`，第 0 号位置额外加一个偏置 `b`（这就是 sink 的全部。它和查询内容无关）。表格里「sink 质量」是 400 条查询的平均值，「中位」是 sink 质量的中位数：

| b | sink 质量（均值） | sink 质量（中位） | 熵 (bit) | cos(输出, v_sink) | 跨查询输出方差 |
|---|---|---|---|---|---|
| 0 | 0.2% | 0.000 | 4.39 | −0.031 | 0.156 |
| 2 | 0.9% | 0.000 | 4.39 | −0.011 | 0.157 |
| 4 | 3.8% | 0.002 | 4.34 | 0.063 | 0.161 |
| 6 | 12.2% | 0.011 | 4.10 | 0.214 | 0.185 |
| 8 | 27.0% | 0.077 | 3.55 | 0.408 | 0.227 |
| 10 | 46.0% | 0.382 | 2.76 | 0.620 | 0.236 |
| 12 | 66.3% | 0.821 | 1.85 | 0.808 | 0.185 |
| 14 | 83.3% | 0.971 | 1.00 | 0.929 | 0.096 |

三件事：

1. **均值和中位数的分裂本身就是信息。** b=10 时均值 46.0% 而中位数只有 38.2%——说明查询之间差异极大：一部分查询里 sink 吃掉一半以上，另一部分里它几乎没份。到 b=14，中位 0.971 追上并超过均值（0.833），分布**反过来**变成「绝大多数查询都被 sink 吃掉、少数查询还能分出注意力」。sink 不是均匀削弱检索，而是**逐查询地切换工作模式**。
2. **熵塌得比质量涨得快。** 从 b=6 到 b=14，sink 质量从 12.2% 到 83.3%（×6.8），熵从 4.10 bit 到 1.00 bit（÷4.1）。当 entropy 掉到 1 bit，这个 head 在 512 个位置上的有效选择只剩 2 个位置——它的表达能力基本被一个常数槽位接管了。
3. **输出方差不是单调的**：0.156 → 0.236（b=10）→ 0.096（b=14）。先升后崩。解释很朴素：b≈10 时 sink 在一部分查询里主导、另一部分里不主导，两种模式混在一起，跨查询差异反而被放大；b=14 之后所有查询都进入「sink 主导」这一种模式，输出就变成了几乎同一个向量——方差崩溃。**多样性消失的时间点，和 head 放弃工作的时点是同一个。**

## 🏗️ 机制：为什么「放空」必须占用一个真实的槽位

把 softmax 写出来就明白了：`p_i = exp(z_i) / Σ_j exp(z_j)`。分子想表达「谁相关」，但**分母是强制归一化的**：所有 `p_i` 必须加起来等于 1。于是当一个 head 在某个位置**没有任何想看的输入**时，它有两个选择：(a) 把质量摊给一堆不相关的 token，等于往残差流里注入噪声；(b) 训练出一个 logit 极大、但 value 投影近似常数的槽位，把质量倒进去——因为它 value 的贡献是一个**与输入无关的常数**，等于给下游加了个 bias，而不是噪声。

Gu 等（arXiv:2410.10781）的结论正是 (b)：sink「更像 key 上的偏置，存储多余注意力分数，可以是无信息的、不贡献 value 计算」。Bondarenko 等（arXiv:2306.12929）补上了训练动力学：为了把残差更新压到**精确的 0**，softmax 输入被越推越大，于是网络别处的激活就长出 outlier——这也解释了为什么 sink 和量化难度是同一枚硬币的两面。Sun 等（arXiv:2402.17762）则从激活端看到同一件事：那些巨大激活「取值与输入基本无关，充当偏置项」。

流式推理的实践结论（Xiao 等）：既然 sink 的语义无关紧要、位置固定、又拿走大块质量，那**滑动窗口的 KV cache 只要额外保留 4 个初始 token 的 KV**，就能让有限窗口训练的模型稳定地服务无限长序列；摘要里还提到，预训练时**显式加一个占位 token 当专用 sink** 能进一步改善。他们报告的相对基线是滑动窗口重算，最高 22.2× 加速。

## 🔬 实验 2：滑动窗口逐出 sink，代价到底有多大

这是全文最有用的一段。设置：流长 N=4096、d=16、窗口 W=64、sink = **前 4 个位置**（占全部位置的 0.1%），语义分数 `N(0,1.6) − 0.5`（多数位置与查询无关），最近 8 个位置有 +3 局部加成（让窗口本身是有意义的）。参考 = 全历史 attention。两个变体：**只留窗口**（W 个最近位置）与**窗口 + 4 个 sink**。24 个查询位置（t=1024…3968）。

「捕获」= 参考分布的质量有多少落在变体看得见的集合里；KL = `KL(p_变体 ‖ p_参考)`（nats）；「top1 符」= 变体注意力最大的位置是否等于参考最大的位置。

| b | 参考里 sink 质量 | 参考 top1=sink | 只留窗口 捕获 | KL | 相对 L2 误差 | top1 符 | 窗口+sink 捕获 | KL | 相对 L2 误差 | top1 符 |
|---|---|---|---|---|---|---|---|---|---|---|
| 0.0 | 0.0% | 0.0% | 13.0% | 3.06 | 3.59 | 25.0% | 13.0% | 3.05 | 3.54 | 25.0% |
| 4.0 | 2.2% | 0.0% | 12.7% | 3.08 | 3.51 | 25.0% | 14.9% | 2.69 | 3.08 | 20.8% |
| **8.0** | **53.2%** | **95.8%** | **6.1%** | **3.84** | **1.50** | **4.2%** | **59.3%** | **0.60** | **0.79** | **95.8%** |
| **12.0** | **98.3%** | **100%** | **0.2%** | **7.21** | **1.23** | **0%** | **98.5%** | **0.02** | **0.02** | **100%** |

关键读数：

- **第一行是必须放在这里的对照组。** b=0（根本没有 sink）时，保留初始 token 与不保留**完全一样**（捕获 13.0% / 13.0%，KL 3.06 / 3.05）。所以下面那几行的收益**不是**来自「多留了几个历史 token」，而是来自那 4 个位置**性质特殊**。任何把「保留初始 token 有效」当成「旧 token 有用」的论证，在这一行就断了。
- **b=8：4/4096 个位置拿走 53.2% 的质量。** 纯窗口能看见的参考质量只剩 6.1%，KL 3.84 nats，注意力最大的位置与参考一致的比例只有 4.2%。补回这 4 个 sink 后：捕获 59.3%、KL 0.60 nats（**低 6.4 倍**）、L2 误差从 1.50 降到 0.79（**降 47%**）、top-1 一致率 4.2% → 95.8%。也就是说，**窗口版的注意力和参考注意力几乎是两个不同的 head。**
- **b=12 是极端对照：KL 7.21 vs 0.02 nats（差约 360 倍），捕获 0.2% vs 98.5%，L2 误差 1.23 vs 0.02。** 注意这里有个反直觉的地方：只留窗口的 **L2 误差反而下降**了（1.50 → 1.23）。原因是当 sink 足够强时，参考输出本身就退化成常数向量（见实验 3），而窗口版输出的模长也在变小——L2 误差是个**尺度敏感**的指标，会在这里骗人。**分布层面的 KL 和 top-1 一致率才是可靠的读数**（7.21 vs 0.02、0% vs 100%）；这也是我把它一起列出来的原因：单一指标会在机制切换处给出错误的方向感。
- **诚实交代盲区**：b=0 那一行告诉我们，本模拟里窗口本来就丢掉了大量弥散的质量（只捕获 13%），这不是 sink 造成的，是「窗口 vs 全历史」的固有代价。所以本实验能支持的结论是**「逐出 sink 会让注意力分布和输出发生量级跃变，而保留它能把差异压回 1~2 个数量级以内」**，而不是「StreamingLLM 让困惑度从 X 降到 Y」——后者需要在真模型上算困惑度，那是另一篇论文的规模。

## 🧪 实验 3：sink 越大，head 越像一个常向量（outlier 从哪来）

这一节把 b 推到极端，量两件事：输出与 sink value 的余弦、以及输出的模长（N=256、d=16、400 条查询）：

| b | cos(输出, v_sink) | ‖输出‖ |
|---|---|---|
| 0 | 0.012 | 1.708 |
| 4 | 0.136 | 1.761 |
| 8 | 0.507 | 2.233 |
| 12 | 0.904 | 3.266 |
| 16 | **0.995** | **3.930** |

b=16 时，无论查询内容是什么，这个 head 的输出有 **99.5%** 落在 sink 向量那个方向上——**它已经与输入无关了**，就是一个模长被放大 **2.30 倍**（3.930 / 1.708）的常数向量。这两件事正好对上前面两篇论文：Bondarenko 说的「no-op head 为了拿精确 0 把 softmax 输入越推越大、于是别处长出 outlier」，Sun 说的「巨大激活取值与输入基本无关、充当偏置项」。**你不需要相信任何机制解释，就能看清量化的麻烦：一个 head 的输出里有 2.3 倍的常数成分，INT8 的 scale 就得为它让路，代价是其余部分的精度。**

顺带一个可以带走的设计模式：与其和 sink 对抗，不如**给它一个专门的座位**——ViT 的 register token（arXiv:2309.16588，加一层可学习 token 专供内部计算）、Xiao 等建议的 pre-training 期占位 sink token，都是同一个思路：**既然模型需要放空阀，就明着给它一个，别让它去污染有语义的 token。**

## 💻 可运行代码

完整脚本 `~/scripts/blog_daily/43-attention-sink.py`（纯标准库，本机 13.8 秒跑完，**0 次 GPU、0 次 API 调用**）。核心就三段：

```python
def softmax(xs):
    m = max(xs)                      # 数值稳定：先减最大值
    es = [math.exp(x - m) for x in xs]
    s = sum(es)
    return [e / s for e in es]       # ← 必须归一化到 1：这就是 sink 的成因

def build_logits(t, content, b, SINK=4, recency=8):
    lg = [content[i] for i in range(t + 1)]
    for i in range(min(SINK, t + 1)):          # sink 只是一个与查询无关的偏置
        lg[i] += b
    for i in range(max(0, t - recency + 1), t + 1):
        lg[i] += 3.0                            # 局部性：最近 8 个位置有加成
    return lg

def kl(p_var, idxs, p_ref):                     # 变体分布 → 参考分布，nats
    return sum(p_var[k] * math.log(p_var[k] / p_ref[i])
               for k, i in enumerate(idxs) if p_var[k] > 0)

# exp2 主循环骨架：
#   p_all = softmax(build_logits(t, content, b))          ← 参考（看得见全部历史）
#   for idxs in (list(range(t-W+1, t+1)),                 ← 变体 a：只留窗口
#                list(range(SINK)) + list(range(t-W+1, t+1))):  ← 变体 b：窗口 + sink
#       p = softmax([lg_all[i] for i in idxs])            ← 重新归一化：这一步就是失真来源
#       record(kl(p, idxs, p_all), 捕获率=sum(p_all[i] for i in idxs),
#              一致性 = argmax == argmax(p_all))
```

## 💡 落地清单

- **别再把「第一个 token 重要」当成 prompt 技巧。** 它重要是因为它无语义。要利用这个现象就去调**位置和数量**（保留 4 个初始 KV），而不是往里塞一句精心写的「系统提示」——语义对它没有加成。
- **KV cache 淘汰：前几个位置默认是禁区。** 实验 2 的 b=8 行：逐出 0.1% 的位置，注意力分布的 KL 从 0.60 涨到 3.84 nats，top-1 一致率从 95.8% 掉到 4.2%。任何按「重要性」打分淘汰 KV 的策略，都必须给初始 token 一个不可淘汰的豁免位（这类策略的设计目标是「保住质量」而不是「保住内容」）。
- **量化：#1 要盯的不是权重，是那几个固定维度的激活。** 实验 3 里 head 输出模长涨 2.30 倍、且 99.5% 与输入无关——这正是 per-tensor INT8 的 scale 灾难。要么像 Bondarenko 那样从结构上消灭它（clipped softmax / gated attention），要么把 outlier 通道单独用高精度保留。
- **做长上下文/流式推理的评测时，别只测困惑度。** 加两个便宜且灵敏的诊断：**（a）参考分布落在你可见集合上的质量比例；（b）top-1 位置与全历史注意力的一致率。** 本实验里前者从 59.3% 掉到 6.1%、后者从 95.8% 掉到 4.2%，都比「输出向量差多少」更早、更明确地报警（L2 甚至会在机制切换处反向）。
- **架构上可以明着给放空阀。** ViT register token 与 pre-training 占位 sink token 已被证明有效；这是「顺从模型的归纳偏置」而不是「纠正它」。
- **本文的边界必须说清**：三段全部是**离散模拟**，注意力分数是手工构造的分布，不是从任何真实 LLM 里读出来的。我没有复现真实模型里的多头交互、位置编码、归一化层，也没有测困惑度——所以本文的能量在**机制的量级与方向**（保留 4 个位置能把分布差异压回 1~2 个数量级、sink 会让 head 退化成常数偏置），不在**任何一个具体模型的性能数字**。真实模型里 sink 的强度逐层不同、位置也不止第 0 个（Sun 等观察到还有第一个句号/换行 token），这些细节要靠真机实验，而本机没有 GPU。
