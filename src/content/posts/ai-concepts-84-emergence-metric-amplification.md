> 同一条每 token 正确率曲线——`p(x) = sigmoid(1.2 * (x - 9.6))`，`x = log10 N`：
> 换成 token 级准确率，它是从 **12.6%** 平滑爬到 **84.2%** 的斜坡；
> 换成 4 token 的精确匹配，它在 `x = 8.0` 到 `9.0` 这两个十进位里只从 **0.00%** 挪到 **1.14%**，然后在 `9.6` 到 `11.0` 之间从 **6.54%** 爬到 **50.4%**——中间那一段看着像被什么东西点着了。
> 模型没有变，权重曲线没有变，输出也没有变——**变的只是「全对才算对」这个除法**。
> 把答案拉到 8 个 token：每 token 正确率 56% 的模型，表面得分是 **0.97%**；16 个 token，**0.01%**。
> 再配上 100 条测试样本：真实 EM 已经 0.81% 时，**44.7%** 的评测会报出「0 分」。

读这篇要会：`p^L` 与 logit 变换的代数关系 / 二项分布的 log-odds 斜率 / 交叉熵与每 token 正确率的换算（`p = exp(-L_ce)`）。

## 🎯 一个幂运算就能把斜坡折成台阶

先把「精确匹配」（exact match，EM）写清楚：一条样本的答案有 L 个 token，**每个 token 都对**才记 1 分，否则 0 分。若每个 token 独立的正确率是 p，那这条样本得 1 分的概率就是 `p^L`。整篇要用的四条关系放在一起：

```
p_token(x) = sigmoid(k * (x - x0))        # 每 token 正确率，x = log10 N
p_EM       = p_token ** L                 # 一条 L-token 样本全对的概率
放大倍数   = d logit(p_EM)/dx / (d logit(p_token)/dx) = L * (1-p) / (1-p^L)
P(观测到 0) = (1 - p_EM) ** n             # n 条测试样本全没命中的概率
```

而评测里另一类指标——token 级准确率、编辑距离、Brier 分数——都是 p 的**线性**函数，等于直接量 p。所以同一个模型、同一批输出，两个指标之间隔着一个 L 次幂。

预训练模型的 per-token 交叉熵随规模按幂律下降，`p = exp(-L_ce)` 随之单调上升，**在 log N 上近似一条 logistic 曲线**——这就是开头那个 `sigmoid(1.2 * (x - 9.6))` 的来历。它平滑、单调、可外推。问题出在下一步：把这条光滑的 p 代进 `p^L` 之后，斜率变成多少？

第三行那个比值从 p→0 时的 L，单调衰减到 p→1 时的 1。**放大只发生在低端**——恰好就是曲线从零起跳的那一段。一张按线性纵轴画的图，低端被压到看不见（p=0.4、L=8 时 EM 只有 0.07%），上端被抬成明显的跳变，于是「一直不会」和「突然会了」被同一个除法伪造出来。

## 🔬 同一份权重曲线，四个任务长度

模拟的方式是不假设模型内部发生任何相变：固定 k=1.2、x0=9.6，x 从 6.0 扫到 14.0（步长 0.1），每个尺度采样 5000 条样本、每条 L 个 token 独立采对错，同时算 token 级准确率和精确匹配，再在两者都落在 5%–95% 的区间里拟合 logit 斜率：

| L | token 斜率 | EM 斜率 | 斜率比 | token 过渡宽度 | EM 过渡宽度 | 宽度比 |
|---|---|---|---|---|---|---|
| 1 | 1.206 | 1.206 | 1.00 | 4.919 | 4.919 | 1.00 |
| 2 | 1.202 | 1.404 | 1.17 | 4.826 | 4.170 | 1.16 |
| 4 | 1.195 | 1.510 | 1.26 | 4.988 | 3.643 | 1.37 |
| 8 | 1.201 | 1.554 | 1.29 | 4.934 | 3.575 | 1.38 |

底层曲线一模一样（L=1 时两个指标就是同一条线，斜率都是 1.206），但 L 一加长，EM 的 logit 斜率涨到 1.29 倍、过渡宽度压掉 27%。**注意这不是「L 倍」**——上面那个公式说得很清楚，放大倍数在 p→1 处衰减到 1，而 5%–95% 这个窗口大量落在高 p 区，所以测出来只有 1.2–1.3 倍。

真正被 L 改变的不是斜率，而是**动态范围**。取 L=4、把扫描结果铺开：

| log10N | p_token | token_acc | exact_match |
|---|---|---|---|
| 8.0 | 0.1279 | 0.1259 | 0.0000 |
| 9.0 | 0.3274 | 0.3297 | 0.0114 |
| 9.4 | 0.4403 | 0.4430 | 0.0386 |
| 9.6 | 0.5000 | 0.5032 | 0.0654 |
| 9.8 | 0.5597 | 0.5622 | 0.1018 |
| 10.0 | 0.6177 | 0.6179 | 0.1436 |
| 10.5 | 0.7465 | 0.7450 | 0.3070 |
| 11.0 | 0.8429 | 0.8421 | 0.5040 |

同一行里对齐看：x=9.8 那行，**模型已经把 56% 的 token 答对，EM 只有 10.18%**；再往左，x=9.0 时每 token 有 33% 正确、EM 是 1.14%。如果这张图的纵轴取 EM、横轴取模型规模，左半边就是一条贴着零的直线，右半边一路上扬——教科书上的「涌现曲线」形状，**而整个模拟里没有任何一步是非线性的**。

把任务长度当成自由参数，这个压制的规模就露出来了：

| L | EM 到 1% 需要 p | EM 到 50% 需要 p | p=0.56 时 EM | p=0.70 时 EM |
|---|---|---|---|---|
| 1 | 1.0% | 50.0% | 56.00% | 70.00% |
| 2 | 10.0% | 70.7% | 31.36% | 49.00% |
| 4 | 31.6% | 84.1% | 9.83% | 24.01% |
| 8 | 56.2% | 91.7% | 0.97% | 5.76% |
| 16 | 75.0% | 95.8% | 0.01% | 0.33% |

L=8 要求每 token 正确率 **56.2%** 才能把 EM 顶到 1%；L=16 要求 75%。**任务长度是一个和模型规模完全无关的旋钮，谁定它，谁就定了这条曲线陡不陡。** 这就是为什么「算术题」「波斯语转写」这类多 token 输出的任务在文献里最容易出涌现，而单选题（L 实际等于 1，只看正确选项的概率质量是否最大）几乎从不出——同一批模型、同一种能力，被任务格式分成了两类。

## 🏗️ 45% 的评测会报 0 分

第二层伪造来自样本量。「小模型完全不会」这个结论，往往是从「我测了 100 条，一条都没对」读出来的。

若真实 EM 为 q，n 条独立样本全都答错的概率是 `(1 - q)^n`。

取 L=4：每 token 正确率 0.30 时真实 EM = `0.30^4 = 0.81%`，但 100 条样本下 `0.9919^100 = 44.3%` —— **接近一半的评测会给出 0 分**。模拟 4000 次评测，实测 44.7%，和解析式一致。换成 p=0.40（真实 EM 2.56%）是 7.5%，p=0.50（真实 EM 6.25%）是 0.2%。

反过来算置信区间：100 条样本、0 次命中，95% 置信上界是 `3/100 = 3.0%`（rule of three）。**「0 分」在统计上只能支撑「EM 低于 3%」，支撑不了「没有这个能力」。** 而左端那几个 0 一旦落到对数纵轴上就是负无穷，画出来必然是垂直起跳。文献里那张最有名的涌现图上，左侧若干点就是「0 命中 / 一定样本量」——它们不是「零能力」，是「零分辨率」。

## 💻 三十行量完

核心只有三行：从幂律曲线取 p，二项采样出「这条样本答对几个 token」，再分别按 token 和按样本聚合。

```python
import math
import numpy as np

rng = np.random.default_rng(20261116)
K, X0 = 1.2, 9.6                    # 模型族：logit(p_token) = K*(log10N - X0)
XS = np.round(np.arange(6.0, 14.01, 0.1), 1)


def p_token(x):
    return 1.0 / (1.0 + math.exp(-K * (x - X0)))


def measure(x, L, n=5000):
    hits = rng.binomial(L, p_token(x), size=n)      # 每条样本答对几个 token
    return hits.mean() / L, (hits == L).mean()      # token_acc, exact_match


def logit(v):
    v = np.clip(v, 1e-6, 1 - 1e-6)
    return np.log(v / (1 - v))


def slope(xs, ys):
    xs, vs = np.array(xs), np.array(ys)
    m = (vs > 0.05) & (vs < 0.95)                   # 只取过渡段
    return float(np.polyfit(xs[m], logit(vs)[m], 1)[0])


for L in (1, 2, 4, 8):
    ts, es = [], []
    for x in XS:
        t, e = measure(x, L)
        ts.append(t)
        es.append(e)
    print(f"L={L}  tok={slope(XS, ts):.3f}  EM={slope(XS, es):.3f}")

for p in (0.30, 0.40, 0.50):                        # 100 条样本的「0 分」概率
    zero = np.mean([(rng.binomial(4, p, size=100) == 4).mean() == 0 for _ in range(4000)])
    print(f"p={p}  true_EM={p**4:.4f}  P(zero)={zero:.3f}")
```

真实输出（本机跑，1.05 秒）：

```
L=1  tok=1.206  EM=1.206
L=2  tok=1.202  EM=1.404
L=4  tok=1.195  EM=1.510
L=8  tok=1.201  EM=1.554
p=0.3  true_EM=0.0081  P(zero)=0.447
p=0.4  true_EM=0.0256  P(zero)=0.076
p=0.5  true_EM=0.0625  P(zero)=0.001
```

## 💡 判据：怎么分开「指标造的台阶」和真台阶

这条讨论在 2022–2023 年被推到了台面上：Wei 等人 2022 年的《Emergent Abilities of Large Language Models》（TMLR，arXiv:2206.07682）把这个现象命名并系统化；一年后 Schaeffer、Miranda、Koyejo 在 NeurIPS 2023（arXiv:2304.15004）给出上面的替代解释，并且指出 BIG-Bench 上被标注为「涌现」的任务里 **超过 92%** 只在「多选正确项取最大」或「精确字符串匹配」这两类非连续指标下出现。两条结论并不互斥，边界在下面四条上：

**一、换线性指标，看台阶还在不在。** token 级准确率、token 编辑距离、Brier 分数都是 p 的线性函数；精确匹配是 `p^L`，多选正确项是「最大概率落在正确项上」（阶跃函数）。同一批输出换成前者仍陡，才算模型的；换成前者变平，就是除法的。

**二、看连续指标上有没有真的拐点。** 有真台阶的例子是存在的：grokking 里测试准确率在训练步上长时间贴零、然后突然抬升（Power 等，arXiv:2201.02177），而同一时刻的**训练 loss 与测试 loss 都是平滑的**——那是优化动力学的事，不是评测的事。induction head 在小型 transformer 训练中形成时，per-token loss 上会留下可定位的落差。判据统一：**拐点必须在连续指标上也出现，而且能定位到一个机制**。

**三、任务长度必须写进图注。** 上面第三张表就是理由：同一个 p，L 从 4 换到 8，表面得分从 9.83% 掉到 0.97%。跨论文比较 EM 而不对齐 L 和答案格式（有没有「所以答案是」这种模板、要不要带单位），比的是格式不是模型。

**四、样本量要够到「零分辨率」之外。** 想让「0 分」有意义，n 至少要让 `3/n` 远小于你要分辨的最小 EM。想分辨 1% 的差异，100 条不够，至少要几百到上千条；文献里左侧那些点常常只有几十到一百条样本，这正是「小模型看起来完全不会」的主要来源之一。

**这几个数字的边界**：以上是独立 token 的二项模拟，真实模型的 token 错误高度相关（前一位错、后面全崩），正相关会让「全对」的概率高于 `p^L`，所以前面那些 0.97%、0.01% 属于压制更狠的一端，真实模型会略高。`p = exp(-L_ce)` 的换算与斜率放大公式是代数结果，与模型规模无关；而「log N 上恰好是斜率为 1.2 的 logistic」是我为了能扫参数取的形式——真实 p(x) 未必是 logistic，但**任何单调的 p(x) 代进 p^L 之后，低端的斜率都会被放大，且放大倍数不超过 L**，这一条不需要 logistic 假设。
