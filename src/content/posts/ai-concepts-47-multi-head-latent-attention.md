# AI核心概念(47)：Multi-head Latent Attention（MLA）——把 KV 压成一个潜向量，代价是你得先学会那个子空间

> 「MLA 把 KV cache 压掉 93.3%，还不掉点」——这句话里最容易被漏掉的主语是**训练**。缓存里那 512 维的潜向量不是白来的：它是模型把整个 KV 状态推到一个低维子空间之后的结果。**压缩率不是压缩算法给的，是模型给的。**
>
> 这篇不重复结论，只量账。四段实验全部本机纯 CPU numpy 跑出，不调 API、不用 GPU：第一段用一个共享低维子空间采样 KV，在**训练序列上拟合**低秩投影、在**留出序列上评估**——内在维 64 的模型，`r=32` 时注意力出相对误差 `7.26e-01`，`r=64` 就落到噪声地板 `7.74e-03`；内在维 256 的模型，同样的 `r=64` 还有 `8.89e-01`，要到 `r=256` 才掉到 `1.25e-02`。对照组的未训练随机投影，`r=128` 是 `9.83e-01`——等于把状态扔了。
>
> 第二段是这篇最扎心的一个数字：**同样 128 元素/token 的预算**，「低秩潜码 + 逐头上投影」出误差 `3.226e-03`，而「8 个头共用一份 K/V」是 `9.765e-01`，差 302.7 倍。第三段解释为什么位置信息必须拆出去单独存（旋转不可交换，Procrustes 最优残差 `0.2636`）。第四段按公开 config 逐 token 记账，并说明**论文摘要那个 93.3% 我没能独立复现出来**。

## 🎯 术语与出处对齐

- **MHA / MQA / GQA**。MHA 每头一套 K、V。MQA（Shazeer，*Fast Transformer Decoding: One Write-Head is All You Need*，arXiv:1911.02150，2019）让所有头共用一套，缓存降到 `1/n_h`，代价是表达力。GQA（Ainslie 等，*GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints*，arXiv:2305.13245，EMNLP 2023）折中：把头分组，组内共用一套。**这三种都是「结构上砍头」，MLA 走的是另一条路——不动头的结构，改缓存的内容。**
- **MLA（multi-head latent attention，多头潜在注意力）**：DeepSeek-V2 提出的注意力。核心是把 hidden state `h` 通过一个下投影压成一个**共享的潜向量** `c_kv = W_DKV h`，缓存里只存它；每个头在算注意力时再各自上投影出 K、V。论文：DeepSeek-AI，*DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model*，arXiv:2405.04434（2024-05-07 提交，v5 2024-06-19）。
- **论文报告的三个数**（摘要原文口径）：总参 236B / 激活 21B、支持 128K 上下文；相对 DeepSeek 67B，**训练成本省 42.5%、KV cache 降 93.3%、最大生成吞吐提升 5.76 倍**；预训练语料 8.1T token。
- **超参从哪来**：本文记账用的是 HuggingFace 上 `deepseek-ai/DeepSeek-V2-Chat` 的公开 `config.json`：`kv_lora_rank=512`、`qk_rope_head_dim=64`、`qk_nope_head_dim=128`、`v_head_dim=128`、`num_attention_heads=128`、`num_hidden_layers=60`、`hidden_size=5120`、`q_lora_rank=1536`、`max_position_embeddings=163840`、`rope_scaling` 为 yarn、`factor=40`（`4096 × 40 = 163840`，对得上）。
- **解耦 RoPE（decoupled RoPE）**：因为位置旋转没法作用在共享的潜向量上（否则上投影就吸收不进 query 侧，见实验 3），DeepSeek 额外留了 64 维专门给位置通道，单独算、单独存。
- **权重吸收（weight absorption）**：`q·K = q·(W_UK c_kv) = (W_UKᵀ q)·c_kv`——把上投影矩阵乘进 query，就不必先把 K、V 还原出来再算注意力。这一手是 MLA 推理效率的关键。
- **后续沿用**：DeepSeek-V3（arXiv:2412.19437）明确写它沿用 MLA 与 DeepSeekMoE——所以在 2026 年看，这不是一篇论文的孤例，是一条产品线的主干。

## 🔬 实验 1：压到 r 维，误差在哪里掉下来

要压 KV，先得有个前提：**KV 状态本身活在一个低维子空间里**。真实模型里这个子空间是训练出来的；我用一个共享矩阵 `W`（形状 `R0 × 1024`）来模拟它——序列 `X @ W` 就是落在这个 `R0` 维子空间里的 KV 状态（再接一点点采样噪声 0.01）。

关键在于**别作弊**：低秩投影 `P`（`r × 1024`）只在**训练序列**上拟合（对 `[K|V]` 做 SVD 取前 `r` 个右奇异向量），然后在**另一段留出序列**上评估。这才对得上真实 MLA——投影矩阵是训练时冻结的，推理时对没见过的输入用。评估指标是注意力输出的相对误差（同一批 query 下，压缩后的输出与全量输出的 `L2` 距离比）。

| 模型 KV 内在维 | r=32 | r=64 | r=96 | r=128 | r=256 | r=512 |
|---|---|---|---|---|---|---|
| R0=64 | **7.26e-01** | 7.74e-03 | 7.69e-03 | 7.62e-03 | 7.02e-03 | 5.62e-03 |
| R0=256 | 9.42e-01 | 8.89e-01 | 8.18e-01 | **6.93e-01** | 1.25e-02 | 1.07e-02 |

对照：**未训练的随机投影**，`r=128`——内在维 64 的模型出误差 `9.833e-01`，内在维 256 的模型 `9.704e-01`。同一个 `r`，一个是 `1e-2`，一个是 `1e0`。

三个读法：

1. **误差的膝盖就落在内在维上。** 内在维 64 的模型，`r=32` 崩（0.73），`r=64` 一步到位（7.7e-3）；内在维 256 的模型，`r=128` 还在 0.69，`r=256` 才落地（1.25e-02）。**你能不能压，取决于 KV 状态有多低维，不取决于你用什么压缩算法。**
2. **剩下那 `1e-2` 量级不是压缩误差，是噪声地板。** 我特意加了 1% 的采样噪声，`r` 超过内在维之后误差就不再降了——它对应的是「子空间之外那一层噪声」，而这层噪声真实模型里同样存在（数值精度、dropout、分布外输入都在制造它）。
3. **不训练就没有这个子空间。** 随机投影在所有档位都是 `≈1.0`，即等于把 K 换成另一批不相关的向量。所以 MLA 的 93.3% 从来不是「压缩技术」的功劳，是**先训练出一个低维流形，再在推理时利用它**——这个顺序反过来看，就是它全部的风险：子空间一旦不成立（分布外、超长文本、多轮累积偏置），压缩误差会直接进注意力分数。

## 🧪 实验 2：同样 128 元素/token，两种因子化能装多少信息

这一段的设置是干净的对照：全量缓存 1024 元素/token，两种方案都只给 **128 元素/token**。

- **(a) 低秩潜码 + 逐头上投影**：把 `[K|V]` 压成 128 维潜码，解码器（上投影）对每个头各自出一份 K、V；
- **(b) 组共享**：8 个头砍到只剩 1 组共享 K/V，即 `n_kv=1` 的 MQA 式做法（组内取均值，L2 最优近似）。

结果：

```
(a) 低秩潜码 r=128 + 逐头上投影 :  128 元素/token -> 注意力出相对误差 3.226e-03
(b) 组共享   n_kv=1 (8 头共用一份): 128 元素/token -> 注意力出相对误差 9.765e-01
预算完全相同, 误差差 302.7 倍
```

同样的字节数，(a) 几乎无损，(b) 基本毁掉。原因不神秘：**共享是把「头之间的差异」直接删掉，潜码是把差异挪到一个更小的坐标系里放着**。前者丢的是信息量，后者丢的是表示的自由度——而在 KV 高度相关的前提下，后者便宜得多。

⚠️ 这里的盲区必须说清：真实的 GQA/MQA 共享 K/V 是**训练出来的**，query 头会学着适应那份共享表示，所以 (b) 的 `9.765e-01` 是固定 query 下的**悲观上界**，不是 GQA 的真实表现。这张表量的是「给定预算下的可编码容量」，不是「MLA 打赢 GQA」的分层对比——两者训练到位时都能用，差别在同样的缓存预算下谁的上限更高。

## 🏗️ 机制：MLA 做对了三件事，以及为什么少一件都不行

**第一件，低秩 down/up。** `c_kv = W_DKV h` 只存 `c_kv`。拿 DeepSeek-V2 的公开配置算，`c_kv` 是 512 维，再配上 64 维位置通道，**每 token 每层存 576 个元素**——而如果按 128 头 × 128 维各存一套 K、V，是 32768 个元素。这是 1.76%。

**第二件，把位置通道拆出来。** 这一件看着像细节，其实是整套设计的死结。RoPE 是作用在 K 上的旋转；如果为了省缓存，你想干脆旋转那个 512 维潜向量，那么推理时 `K = W_UK · (R c_kv)`，而你希望把 `W_UK` 吸收进 query、写成 `(W_UKᵀ q) · (R c_kv)`——这要求「先旋转再上投影」等于「先上投影再旋转」，即两个算子可交换。实测**它就是不可交换**：

```
直接换个顺序:              ||R_k W - W R_c|| / ||W R_c|| = 0.4206
允许 key 侧任意正交变换 R': 最优残差 (Procrustes 下界)     = 0.2636
```

第二行比第一行更有说服力：我甚至允许你在 key 空间里挑**任意**正交变换（用 Procrustes 求最优解），残差仍有 `0.2636`——非零，就意味着没有哪个旋转能等价地把潜码上的位置信息搬到 key 侧。所以位置通道必须**独立于潜码存在**，压不掉。代价也能量：`64 / (512 + 64) = 11.1%` 的 MLA 缓存是为位置付的。

**第三件，权重吸收。** 既然 `c_kv` 共享，推理时逐个头上投影会反复读同一份潜码、写回 32768 元素的 K、V，带宽上反而不划算。用 `q·K = (W_UKᵀ q)·c_kv` 把上投影乘进 query、`W_UV` 乘进输出投影，就变成**只读那 576 个元素**——读带宽降到 MHA 的 1.76%。**注意这里省的是带宽，不是算力**：上投影的乘加还是要在 query 侧和输出侧做掉的，只是不必物化 K、V。

顺带说那个容易被忽略的 `q_lora_rank=1536`：它是**对 query 的低秩压缩**，省的是训练/预填充阶段的激活显存，**不省 KV cache**。看到「低秩」两个字就以为都在省缓存，是常见的误读。

## 💻 可运行代码（本机跑通版，纯 numpy）

从实验脚本里摘三段核心。第一段是「训练拟合、留出评估」的骨架（含随机投影对照）：

```python
import numpy as np
rng = np.random.default_rng(47)
L, H, Dh, WID, R0, NOISE = 512, 8, 64, 512, 64, 0.01   # 联合 KV 宽度 1024

W = rng.normal(size=(R0, 2 * WID)) / np.sqrt(R0)        # 模拟"训练学出来的低维子空间"
def sample(n, seed):
    g = np.random.default_rng(seed)
    X = g.normal(size=(n, R0)) @ W + g.normal(size=(n, 2 * WID)) * NOISE
    return X[:, :WID].reshape(n, H, Dh), X[:, WID:].reshape(n, H, Dh)

Ktr, Vtr = sample(512, 1000)                            # 训练序列
Kte, Vte = sample(512, 2000)                            # 留出序列
def flat(K, V, n): return np.concatenate([K.reshape(n, -1), V.reshape(n, -1)], axis=1)
_, _, Vt = np.linalg.svd(flat(Ktr, Vtr, 512), full_matrices=False)   # 只在训练序列上拟合

r = 128
P = Vt[:r]                                              # (r, 1024) 冻结的 down/up 复合投影
KV = flat(Kte, Vte, 512)
KV_hat = (KV @ P.T) @ P                                 # 留出序列只过 down/up
Wr = rng.normal(size=(2 * WID, 128)) / np.sqrt(2 * WID)
KV_rand = (KV @ Wr) @ np.linalg.pinv(Wr)                # 未训练随机投影(对照)
print(KV_hat.shape, KV_rand.shape)                      # (512, 1024) (512, 1024)
```

注意力出误差只取决于 `K̂, V̂`（例：`q = Kte[::5].mean(axis=0) * np.sqrt(Dh)`，出误差 `||attn(q,K̂,V̂) - attn(q,K,V)|| / ||attn(q,K,V)||`）。第二段是「不可交换」的两行：

```python
import numpy as np
def rot_pair(dim, th):                                  # block-diagonal RoPE 旋转
    R = np.eye(dim)
    for i in range(0, dim, 2):
        c, s = np.cos(th), np.sin(th)
        R[i, i], R[i, i+1], R[i+1, i], R[i+1, i+1] = c, s, -s, c
    return R
W_UK = rng.normal(size=(128, 512)) / np.sqrt(512)
R_c, R_k = rot_pair(512, 0.3), rot_pair(128, 0.3)
A = W_UK @ R_c        # 先转潜码再上投影
B = R_k @ W_UK        # 先上投影再转 key
U, S, Vt = np.linalg.svd(B @ A.T)                       # Procrustes: 最优正交 Q
best = np.sqrt(max(np.linalg.norm(A)**2 + np.linalg.norm(B)**2 - 2*S.sum(), 0)) / np.linalg.norm(A)
print(round(best, 4))                                   # -> 0.2639, 非零（数值随 rng 状态微变）
```

第三段是记账（三个方案都是乘法，谁都能验算）：

```python
mla  = (512 + 64) * 60                # 34560  元素/token
gqa  = 2 * 8 * 128 * 95               # 194560 DeepSeek 67B 量级(8 组, 95 层)
mha  = 2 * 128 * 128 * 60             # 1966080 假设 V2 用 MHA
print(mla/gqa, mla/mha)               # 0.1776 / 0.0176
```

## 💡 小结与三条陷阱

- **陷阱一：把「压掉 93%」当成纯工程技巧。** 实验 1 说得很直白：同样的压缩率，内在维 64 的模型误差 `7.7e-03`，内在维 256 的模型误差 `6.9e-01`。**MLA 的收益是训练先付了成本换来的**——模型得先把 KV 逼到低维子空间里，还得让 query 适应这个空间（否则就是随机投影那个 `9.8e-01`）。这也是它最该被盯的地方：一个靠子空间成立的压缩，在分布外输入上会怎么退化，是一个需要单独监控的问题，而不是一句「不掉点」能盖住的。
- **陷阱二：直接引用 93.3%。** 论文摘要写的是「相对 DeepSeek 67B，KV cache 降 93.3%」，但按公开 config 独立算，我得到的是两个不同的数：以 DeepSeek 67B 量级（GQA 8 组、95 层）为基线是 **降 82.2%**，以同层数 MHA 为基线是 **降 98.2%**。**我用公开配置复现不出 93.3%**，差异应该来自口径（层数怎么对齐、位置通道算不算进去、bf16 还是 fp16）。方向和量级都对，但**引用一个数之前，先确认它的分母是什么**——这是这一整篇最实用的一句话。
- **陷阱三：以为 MLA 只省显存。** 它同时改变了两件事：其一，`c_kv` 是「每层每 token 一份」，所以它**同样受益于 prefix caching**（缓存命中时连下投影都省了）；其二，吸收之后省的是**读带宽**（1.76%），不是算力——这一点在 decode 阶段（受带宽限制）收益最大，在 prefill 阶段（受算力限制）就小得多。把 MLA 当万能加速器，会在错误的阶段期待错误的收益。

最后声明本次实验的边界：全部跑在本机 CPU 的 numpy 上，**不是 GPU 实测、不是 MLA 权重实测，也没有训练任何模型**。实验 1、2 里的「训练出来的压缩器」我用 SVD 在训练序列上拟合来代替——那是线性压缩的**容量上界**（最优情形），真实 MLA 的 `W_DKV/W_UK/W_UV` 是训出来的、并要跟 query 联合适应，误差会和我的数字不同；我给出的内在维是**人为设定**的，用来展示趋势，不是任何真实模型的实测值。实验 3 的不可交换性是纯代数事实（可信）；实验 4 的记账是纯算术（可信，配置换了数字就换）。**模型给你子空间，你才能压；子空间之外，一切照旧。**
