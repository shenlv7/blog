# AI核心概念(42)：解码策略——同一批 logits，五种花法

> 「解码策略」听起来像一堆可以互相替换的开关：greedy、beam、top-k、top-p、temperature。但它们其实只做两件事：**在每一步，决定从哪一截分布里抽签，以及抽签的坡度有多陡。** 一个模型、一批完全相同的 logits，换一种花法就能从「bland 且重复」变成「像人话」——这件事 2019 年就被 Holtzman 那篇标题就叫 *The Curious Case of Neural Text Degeneration* 的论文写清楚了，问题是五年多过去，很多人的默认参数还是随手抄来的。
>
> 这篇不开空头支票：前两部分是**本机真跑 deepseek-chat 的 logprobs**（20 个位置 + 9 次定温调用），第三部分是**玩具 bigram + 穷举核对**（正文会明确标出哪些是模拟）。一句话结论：在 T=1.0 的真实分布上，固定的 top-k=10 保留了 **99.8%** 的质量——几乎没有剪掉任何东西；真正在变的是 top-p 的核，同一批位置上它从 **1 个 token 摆到 8 个**。

## 🎯 先把五种花法对齐到原文

术语当场解释，引用全部核过 arXiv 页面：

- **greedy（贪心）**：每步取概率最大的 token。局部最优，非全局最优。
- **beam search（束搜索）**：同时保留 `width` 条候选前缀，按累计 logprob 排序、逐步扩展。目标是**总 logprob 最大的那条序列**——注意这是最大似然搜索，不是「最像人话」的搜索。Holtzman 等（*The Curious Case of Neural Text Degeneration*，arXiv:1904.09751，2019-04-22）摘要里的原话就是：似然作为训练目标是好事，**作为解码目标却产生 bland 且奇怪重复的文本**。Stahlberg & Byrne（*On NMT Search Errors and Model Errors: Cat Got Your Tongue?*，arXiv:1908.10090，2019-08-27）用精确搜索实测了这一点：整个 WMT15 英德测试集上，**beam=100 都找不到全局最优**，而更刺眼的是超过 50% 的句子里，模型给**空翻译**打了全局最高分。
- **top-k**：每步只在概率最高的 k 个 token 里抽。出处在 Fan 等（*Hierarchical Neural Story Generation*，arXiv:1805.04833，2018-05-13）。
- **top-p / nucleus sampling**：每步取累计概率刚好到 p 的最小集合，核的大小**逐 token 变**。Holtzman 那篇同一篇论文提出。
- **temperature**：只给 logit 除以 T 再 softmax，不改候选集合，只改坡度。
- 后面的模块：**typical sampling**（Meister 等，*Locally Typical Sampling*，arXiv:2202.00666，2022-02-01，按「信息量接近条件熵」筛词，摘要里明确说它比 nucleus/top-k 更少退化重复）、**η-sampling**（Hewitt 等，*Truncation Sampling as Language Model Desmoothing*，arXiv:2210.15191，2022-10-27，把截断理解为「去平滑」）、**Mirostat**（Basu 等，arXiv:2007.14966，2020-07-29，直接控制困惑度）、**min-p**（Nguyen 等，arXiv:2407.01082，2024-07-01，阈值随 p_max 缩放）、以及所有 API 里那个 **repetition penalty**（常被追到 CTRL，Keskar 等，arXiv:1909.05858，2019-09-11）。

## 🔬 实测 1：真模型每一步的分布到底有多宽

四段前缀（故事续写 / 代码续写 / 常识问答 / 开放议论），每段取前 5 步，`deepseek-chat`、`temperature=1.0`、`top_p=1.0`、`top_logprobs=20`，报的 logprob 都是 API 原值。节选（**含 API 实际返回的 token，包括那些"标点"和 EOS**）：

| 前缀 | 步 | 熵(bit) | 等效候选 exp(H) | greedy 选 | top20 外尾部质量 | top-k=10 质量 | top-p=0.95 核 |
|---|---|---|---|---|---|---|---|
| 故事开头 | 0 | 0.12 | 1.1 | `a` | 0.0% | 100.0% | 1 个 / 98.6% |
| 故事开头 | 1 | 2.39 | 5.3 | `tall` | 1.4% | 97.2% | **8 个** / 95.4% |
| 故事开头 | 2 | 1.92 | 3.8 | `figure` | 0.0% | 100.0% | 4 个 / 96.7% |
| 代码续写 | 0 | 0.01 | 1.0 | `arr` | 0.0% | 100.0% | 1 个 / 99.9% |
| 常识问答 | 1 | 1.01 | 2.0 | `.` | 0.0% | 100.0% | 2 个 / 99.9% |
| 常识问答 | 2 | 0.95 | 1.9 | `<｜end▁of▁sentence｜>` | 0.0% | 100.0% | 2 个 / 98.9% |
| 开放议论 | 0 | 1.58 | 3.0 | `the` | 0.0% | 100.0% | 3 个 / 96.9% |
| 开放议论 | 1 | 1.20 | 2.3 | `data` | 0.0% | 100.0% | 3 个 / 99.8% |

20 个位置的汇总（**都是本机真实读数**）：

```
平均熵（T=1.0）        0.453 nats = 0.65 bit   → 等效候选只有 1.57 个
同一批 logprob 按 1/T 软化后的平均熵：
  T=0.7  0.349 nats（1.42 个）  T=1.0  0.453（1.57 个）
  T=1.3  0.564 nats（1.76 个）  T=1.5  0.646（1.91 个）
top-k=10 保留的真实质量  均值 99.8%
top-p=0.95 核大小        最小 1 个、最大 8 个、均值 2.1 个 token
top-20 之外的真实尾部质量 均值 0.08%、最大 1.44%
```

三个能直接拿走的东西：

1. **这个模型在 T=1.0 下本来就很尖。** 平均等效候选 1.57 个——也就是说绝大多数位置，greedy / top-k=10 / top-p=0.95 抽出来的是**同一个 token**，参数之争在这些位置上根本不存在。真正分出胜负的只有开放位置：故事开头第 1 步的核是 **8 个** token，代码续写第 0 步是 **1 个**。
2. **top-k 的毛病是「一刀切反了方向」。** 固定 k=10 在尖分布上等于不剪（99.8% 的质量本来就在前 10 个里），在开放位置上又可能剪掉本来该留的东西；而 top-p 的核是逐 token 重算的，同一批位置里从 1 摆到 8——**核这个说法本身就是「自适应」的意思**。Hewitt 等那篇摘要给了个极端例子：文档以 `Donald` 开头时，top-p 会把除 `Trump` 之外**所有**词都截掉，而 η-sampling 不会。所以「top-p 一定比 top-k 好」也是错的——它们是两种不同的误伤方式。
3. **别把 top-20 当成完整分布。** 我测到的尾部质量均值只有 0.08%，但最大到 **1.44%**，而且这些质量落在 20 名之后、API 根本不返回。任何「用 logprobs 复现采样分布」的分析都会系统性低估核的大小——差距不大，但方向固定。

## 🔬 实测 2：API 报的 logprob 是采样前的还是采样后的？

这是这篇里我自己最想验的一件事，因为它决定了后面所有数值实验能不能做。问题：`temperature` 只该影响采样，那它会不会改**报告的 logprob**？如果会，报的就是「缩放后的分布」；如果不会，报的是原始 logit。

做法：同一个 prompt、同一个首 token 位置，`max_tokens=1`，温度取 0.3 / 1.0 / 2.0，**每个温度重复 3 次**，看 `gap = logprob(top1) − logprob(top2) = log(p₁/p₂)`：

| T | gap 三次（nats） | 均值 | 3 次之间最大差 |
|---|---|---|---|
| 0.3 | 17.5033 / 16.0154 / 17.3377 | 16.95 | 1.49 |
| 1.0 | 4.8046 / 5.2013 / 4.2320 | 4.75 | 0.97 |
| 2.0 | 2.6715 / 2.6007 / 2.6007 | 2.62 | 0.07 |

**尺度核对**：`gap(0.3)/gap(1.0) = 3.57`，`1/T` 预测 `3.33`；`gap(1.0)/gap(2.0) = 1.81`，预测 `2.00`。gap 是 logit 差，除以 T 之后就该按 1/T 缩放——**实测就是按这个规律走的，所以这份 API 报的是「除以 T 之后」的分布**。两个直接后果：

- 你手上虽然只有 API 给的 logprob，但**它等价于原始 logit 除以 T**，所以按 `T′=1` 换算回去反推未缩放的 logit 是合法的——本文实测 1 里那几行 `T=0.7/1.3/1.5` 的熵就是这么算的（不是实时调 API，是拿 T=1.0 的真实 logprob 做精确算术）。
- **这些读数不是逐位可复现的。** 同一个请求重复三次，T=0.3 那组差了 1.49 nats；把抖动乘回 T 换算成「原始 logit 抖动」，三个温度分别是 0.446 / 0.969 / 0.142——**并不成比例**，说明抖动不是稳定的常数。唯一能下的结论很朴素：**做 logprob 数值实验要重复取均值、要报告温度，别拿单次读数当事实。**（顺带说，我另一轮跑同一段代码时 T=1.0 的三次完全相同、抖动 0.0000——所以这事连"抖多少"都不稳定。）

## 🏗️ 机制：截断在一张什么样的图上动刀

Hewitt 等（arXiv:2210.15191）给了一个我很喜欢的视角：把一个神经语言模型看成「**真分布 ⊗ 平滑分布**」的混合——平滑那项是为了不让困惑度变成无穷，但它同时把质量摊到了那些本不该有机会的 token 上。**截断就是在做去平滑（desmoothing）：估计真分布的支撑集。** 这个视角一下子解释了三种剪子的差别：

| 方法 | 剪什么 | 失效方式 |
|---|---|---|
| top-k | 固定剪到第 k 名 | 分布尖时白剪（本文实测：保留 99.8% 质量）；分布平时留下没意义的尾巴 |
| top-p | 剪到累计质量 p | 高置信场景下会把高质量候选一起剪掉（`Donald` → 只剩 `Trump`）；核大小逐 token 变（实测 1~8 个） |
| min-p | 相对阈值 `α·p_max` | 阈值随最可信 token 缩放，置信高时自动收紧、置信低时自动放开 |
| typical / η / Mirostat | 按信息量、熵、困惑度 | 多一个需要理解的目标量，调参不直观 |

顺带说一句 repetition penalty：CTRL（arXiv:1909.05858）那条规则是「**正 logit 除以 k、负 logit 乘以 k**」，方向很重要——搞反了会变成鼓励重复。而且它的作用机理值得记住：**它不是理解，是挤压。**

## 💻 可运行代码

完整脚本 `42-decoding-strategies.py` 在 `~/scripts/blog_daily/`，上面所有数字都能一键复现。核心就这几段：

```python
def call(messages, temperature=1.0, top_logprobs=20, max_tokens=16):
    body = {"model": "deepseek-chat", "messages": messages, "max_tokens": max_tokens,
            "temperature": temperature, "top_p": 1.0, "logprobs": True,
            "top_logprobs": top_logprobs}          # 这两个参数见 DeepSeek API 文档
    ...  # 短超时 + 重试，token 从 ~/.hermes/.env 读

def entropy(ps): return -sum(p * math.log(p) for p in ps if p > 0)

def softmax_to(logps, T):                          # 实测 2 证明：API 的 logprob 已含 1/T
    m = max(lp / T for lp in logps)
    ws = [math.exp(lp / T - m) for lp in logps]
    return [w / sum(ws) for w in ws]

def topp_size(ps, p=0.95):                         # 核是逐 token 重算的
    acc, n = 0.0, 0
    for w in sorted(ps, reverse=True):
        acc += w; n += 1
        if acc >= p: break
    return n, acc
```

## 🧪 实测 3：玩具 bigram 上，beam 精确地走向最「安全」的那条路

这一节**不是真实模型**：转移概率表写在脚本里（9 个状态的 bigram），目的是让「beam = 最大化总 logprob」这个机制能**被穷举核对**。长度 6，穷举全部 705 条可达序列：

| beam 宽度 | 选出的序列 | 总 logprob | distinct-2 |
|---|---|---|---|
| w=1（=greedy） | 数据 很 快 很 快 很 | −3.595 | 0.60 |
| w=2 | 数据 很 快 很 快 很 | −3.595 | 0.60 |
| w=4 | 数据 很 快 很 快 很 | −3.595 | 0.60 |
| **w=8** | **数据 . . . . .** | **−2.813** | **0.40** |
| w=16 | 数据 . . . . . | −2.813 | 0.40 |
| *穷举 705 条的真实最优* | 数据 . . . . . | −2.813 | 0.40 |

```
核对 beam(16) 是否等于穷举最优：True
这条全局最优自己占「全部长度 6 的序列」的概率质量：6.00%
4000 条随机采样：平均总 logprob −5.628（比最优低 2.815 nats，平均概率只有最优那条的 6.0%）
                  平均 distinct-2 0.80；distinct-2 ≤ 0.4（基本是重复串）的比例 11.6%
```

读出来的结论比数字更重要：

- **greedy 和窄 beam 是局部最优，宽 beam 是真正的全局最优——而全局最优就是最重复的那条。** distinct-2 从采样的 0.80 掉到 0.40。这不是「beam 有 bug」，是**似然最大化这个目标本身**在开放生成上的偏好：短、重复、可预测的文本累计 logprob 更高。Stahlberg 那篇里「超过一半句子的全局最优是空翻译」是同一个现象的极端形态。
- **这条最优序列只占整片分布的 6.00%。** 也就是说，beam 给你的是分布里一个 6% 的点，而不是「模型想说的话」。想清楚这一点，就知道为什么翻译/结构化抽取适合 beam，开放写作不适合。
- **重复惩罚要多大才断环？** 在这个玩具里，CTRL 式 k 从 1.0 一路加到 2.0，环都不断（因为环上每一步的胜出幅度太大，0.55 对 0.15）；**k=3.0 才断**，而且断完落到另一条同样平庸的路（`数据 很 快 很 慢 很`）。频率惩罚 fp 同理：0.5 无效，1.0 起断。**惩罚压制的是症状，代价是把内容一起压平**——这也是为什么前面那些论文要另开 tool（typical / min-p / η）而不是继续加惩罚。

## 💡 落地清单

- **确定性任务用 greedy，开放生成别用 beam。** 代码、抽取、结构化输出要的是「最可能的那一个」；写作要的是「分布里那一片」，beam 只会给你 6% 的那个点。
- **先量再调。** 本文实测：T=1.0 下这个模型的平均等效候选只有 1.57 个，top-k=10 保留 99.8% 质量——**在这种分布上纠结 top-k 完全是在调一个不生效的旋钮**。要动就动温度（实测 T=0.7→1.5 把等效候选从 1.42 抬到 1.91）和 top-p 的核。
- **top-p 和 top-k 是两种误伤方式，不是好坏关系。** 你要「自适应截断」，top-p/min-p/typical 这类才是同一条线上的；固定 k 只适合你能确认所有位置都同样平/同样尖的场景。
- **长文重复：先降一点温度 + top-p 0.9，再考虑轻惩罚。** 惩罚从 1.05~1.2 起试，k 上到 3 那种量级内容会被压平（本文玩具里 k=3 之后的输出已经不是原来的内容了）。
- **logprob 数值实验的两条纪律**：重复 ≥3 次取均值；报告温度，并记住 API 报的是**除以 T 之后**的值。别拿 top-20 当完整分布——实测尾部最大 1.44%。
- **知识缺口写在明处**：本文实测 3 用的是玩具 bigram，量的是**机制**（beam 会精确找到总 logprob 最大、也最重复的那条），不是真实模型的退化率；真实退化率要真模型 + 大规模生成 + 人工评分，那是另一篇论文的规模。
