> 「参数比样本多就会过拟合」这句话，在我这张表上只在 k<100 的那一半成立。
> 真正把误差顶到 332.88 的，是 k 恰好等于 100 的那一格：模型不多不少，正好能把训练集完全插值。
> 再往后加六倍参数，误差掉到 3.11 —— 比「最优」的 20 个特征还低。

**读这篇要会**：最小二乘解与伪逆（`pinv`）/ 矩阵的秩、奇异值、条件数 / 偏差–方差分解在说什么。不需要 GPU，不需要训练神经网络，numpy 单机 9 秒跑完。

## 🎯 一条被画过很多遍、但我想要确切坐标的曲线

双下降不是新话题：Belkin 等 2019 年在 PNAS 上指出「模型容量超过插值门槛后测试误差会再降一次」，Mei 与 Montanari 同年把随机特征回归的双下降曲线算到了渐近精确，Nakkiran 等 2020 年在 ICLR 用 ResNet 把它做成了 model-wise 与 epoch-wise 两个版本。结论早就写在那里了。

缺的是坐标。论文画的是随 n/k 比连续变化的渐近曲线，落到工程里我要回答的是：**我这次把模型从 20 个特征加到 600 个，误差会怎么走？在哪个具体数字上会炸？** 于是搭了下面这个最小装置，全部在本机 CPU 上真跑。

- 输入 $x\in\mathbb{R}^{20}$，高斯。
- 真实函数 $f(x) = 0.8x_0 - 0.6x_1 + 0.9x_2x_3 + 0.5x_4^2 + 0.7x_0x_5^2$，有二次与交互项，不是你随便一个线性模型就能拟合的。
- 训练集 100 条，标签加 $\sigma=0.5$ 的高斯噪声；测试集 5000 条，**不加噪声**，测的是对 $f$ 的期望平方误差。
- 模型：$k$ 个冻结的随机 ReLU 特征 $\phi_j(x)=\mathrm{relu}(w_j^\top x + b_j)$，只训练最后一层线性读出。容量旋钮就是 $k$。

选这个装置的理由很实际：它有闭式解，不需要优化器，9 秒能把整条曲线扫完；而它的失效模式（插值门槛上的方差爆炸）和神经网络里看到的是同一个数学现象。

## 📐 峰为什么长在 $k=n$ 上

线性读出的解是

$$\hat w=\Phi^{+}y=\begin{cases}(\Phi^\top\Phi)^{-1}\Phi^\top y, & k<n\\[2pt] \Phi^\top(\Phi\Phi^\top)^{-1}y, & k\ge n\end{cases}$$

$k\ge n$ 那一支就是「最小范数插值解」：只要 $k$ 够多，训练误差必然是 0，多出来的自由度由**范数最小**这个附加条件消耗掉。噪声怎么传进参数：

$$\|\delta \hat w\|\le \|\Phi^{+}\|\,\|\delta y\|=\frac{\|\delta y\|}{\sigma_{\min}(\Phi)}$$

$\sigma_{\min}$ 是 $\Phi$ 的最小奇异值。$k=n$ 时 $\Phi$ 是方阵，随机方阵的最小奇异值本来就小（量级 $n^{-1/2}$）；而这里的特征是 20 维输入生成的 100 个 ReLU，彼此高度共线，**有效秩远低于 100**，$\sigma_{\min}$ 比 $n^{-1/2}$ 还小得多。于是噪声被放大到 $1/\sigma_{\min}^2$ 的量级 —— 这就是那根针的来源。

$k$ 继续增大后，$\Phi$ 变成扁矩阵，行空间之外多出大量自由度，最小范数解在大空间里挑一个范数很小的解，$\|\hat w\|$ 反而下降，噪声放大随之收缩。这一支是隐式的 L2 正则，你什么都没调。

想要显式压住峰，就加 ridge：

$$\hat w(\lambda)=(\Phi^\top\Phi+\lambda I)^{-1}\Phi^\top y$$

## 🔬 主表：同一个装置，只改 k

5 个种子取均值，$n_{\text{train}}=100$，测试集 5000 条：

| 特征数 k | train MSE | test MSE | 解范数 ‖ŵ‖ |
|---|---|---|---|
| 2 | 4.8463 | 5.0162 | 0.52 |
| 20 | 2.5359 | **3.9147** | 2.60 |
| 60 | 0.8730 | 6.2892 | 7.55 |
| 80 | 0.3859 | 9.9038 | 12.47 |
| 90 | 0.2277 | 19.3780 | 17.36 |
| **100** | **0.0000** | **332.8756** | **70.54** |
| 110 | 0.0000 | 27.4810 | 20.81 |
| 150 | 0.0000 | 7.1489 | 8.01 |
| 300 | 0.0000 | 3.8018 | 3.86 |
| 600 | 0.0000 | **3.1071** | 2.48 |

三件事同时发生：训练误差在 $k=100$ 归零并保持到 600；测试误差先降到 3.91（$k=20$）再涨到 332.88，然后一路回落到 3.11；解范数在门槛附近冲到 70.54 再掉到 2.48。**范数的走势和测试误差的走势是同一条曲线**——这不是巧合，上面那行 $\|\delta\hat w\|\le\|\delta y\|/\sigma_{\min}$ 就是在说这件事。

峰值对种子极其敏感。换 10 个种子在门槛附近加密扫：$k=98$ 是 81.64、$k=99$ 是 127.50、$k=100$ 是 2992.73、$k=101$ 是 311.21。峰窄到一格，高度由一个随机矩阵的最小奇异值决定 —— 这是方差尖峰，不是稳定的偏差。

## 🏗️ 把样本量换成 40 / 80 / 160，峰跟着搬家

如果峰代表「模型太大」，它应该随 $k$ 的绝对值移动；如果代表「刚好插值」，它应该随 $n$ 移动。这是可判伪的：

| $n_{\text{train}}$ | 峰值位置 | 峰值 test（中位，8 seeds） | $k=3n$ 处 test（中位） |
|---|---|---|---|
| 40 | $k=40$ | 910.01 | 6.20 |
| 80 | $k=80$ | 555.44 | 4.56 |
| 160 | $k=160$ | 777.01 | 3.80 |

三档全部精确落在 $k=n$，一次都没偏。误差高度随 $n$ 变化不大，位置跟着样本量一比一走。**这就是为什么用「模型参数量除以训练样本数」当容量指标是合理的，而用绝对参数量不是。**

## 🧪 门槛上的尖峰有多脆

固定 $k=n=100$，只改 ridge 系数（10 seeds）：

| λ | train MSE | test MSE |
|---|---|---|
| 0 | 0.0000 | 3478.53 |
| 1e-8 | 0.0000 | 3466.20 |
| 1e-6 | 0.0001 | 2540.25 |
| 1e-4 | 0.0042 | 148.73 |
| 1e-2 | 0.0316 | 27.17 |

$\lambda$ 从 0 抬到 $10^{-2}$，峰从 3478 掉到 27.17，两个数量级。只付出 0.0316 的训练误差。峰确实是病态求逆造成的，一点正则就能收。

但注意这两个数字的对比：**在门槛上把 ridge 调到 $10^{-2}$，得到 27.17；干脆把 $k$ 从 100 加到 600、不加任何正则，得到 3.11。差 8.7 倍。** 在这个装置里，「多给参数、让最小范数自己去挑」比「卡在门槛上死磕正则化」便宜得多——因为前者的参数空间太大，噪声方向上的解其实被压得很小；后者始终站在 $\sigma_{\min}$ 最小的那个点上跟它对赌。

## 💻 核心代码

完整脚本（含三个实验、种子与加密扫描）在仓库 `demos/64-double-descent.py`，核心就这些：

```python
import numpy as np

D_IN, N_TRAIN, N_TEST, NOISE = 20, 100, 5000, 0.5

def true_f(x):
    return (0.8*x[:,0] - 0.6*x[:,1] + 0.9*x[:,2]*x[:,3]
            + 0.5*x[:,4]**2 + 0.7*x[:,0]*x[:,5]**2)

def feats(X, W, b):
    return np.maximum(X @ W.T + b, 1e-3)   # 冻结的随机 ReLU 特征

rng = np.random.default_rng(1000)
Xtr = rng.normal(size=(N_TRAIN, D_IN))
Xte = rng.normal(size=(N_TEST, D_IN))
ytr = true_f(Xtr) + NOISE * rng.normal(size=N_TRAIN)
yte = true_f(Xte)                          # 测试集无噪声

for k in [2, 20, 60, 80, 90, 100, 110, 150, 300, 600]:
    W = rng.normal(scale=1/np.sqrt(D_IN), size=(k, D_IN))
    b = rng.uniform(0, 1, size=k)
    A, At = feats(Xtr, W, b), feats(Xte, W, b)
    w = np.linalg.pinv(A) @ ytr            # k<=n 普通最小二乘；k>n 最小范数插值
    print(k, np.mean((A @ w - ytr)**2), np.mean((At @ w - yte)**2),
          np.linalg.norm(w))
```

`pinv` 默认 `rcond=1e-15`，所以在门槛上它会老老实实把病态方向也求出来——这正是我要观察的现象。生产代码里应该用 `rcond` 或 ridge 把它裁掉，否则你会得到一个数值上巨大、泛化上灾难的解。上面这段是单种子，门槛处跑出来的数字（99.46）和主表的 5 种子均值（332.88）不同，方差尖峰对种子就是这么敏感。

## 💡 三条能直接用的判断

**一、别停在第一个谷。** k=20 的 3.91 是「小模型区」的局部最优，看起来像最优容量，实际上再往上走过一段灾难区之后是 3.11。调规模时如果只在谷底附近做早停，你永远看不到后半段。

**二、容量指标要用比值，且数据量一变就得重扫。** 峰在 $k=n$，不在 $k=某个固定值$。样本从 100 加到 160，峰从 100 搬到 160：昨天验证好的模型规模，今天补了数据就可能落回雷区。

**三、判断「是不是站在门槛上」看范数，不看训练损失。** 训练误差归零有很多种归零法；解范数在门槛附近冲到最大值这件事，才是方差要爆的前兆。训练时监控最后一层（或整体）权重范数的走势，比盯着 train loss 有用。

需要写清楚适用范围：这里是**冻结随机特征 + 线性读出**，没有优化动力学，参数是「特征的个数」。深度网络里的 model-wise 双下降还叠着训练轨迹这个维度（同样的模型，训练到某个 epoch 测试误差会再起一次，Nakkiran 等把它叫 epoch-wise double descent），所以这里的 $k$ 不能直接替换成层数或宽度，这里测到的峰高也不能当作 CNN 上的预期值——那些网络的特征是学出来的，有效秩随训练变化，峰通常平缓得多。能迁移的是结构：**峰的位置由「参数量 ≈ 有效样本量」这个比值决定，峰的高度由那一刻的病态程度决定，峰之后的下降来自隐式最小范数正则。**

一句话收尾：把「过拟合」当成容量的单调函数，只在小模型那一半是对的。真正决定误差的是你离插值门槛有多近 —— 而那个门槛，是数据量画的，不是模型画的。
